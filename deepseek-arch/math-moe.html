MoE 与负载均衡的数学

这一页算清楚两件事：MoE 是怎么把"容量"和"计算量"解耦的，以及 V3 的 aux-loss-free 负载均衡为什么比传统 aux loss 高明——关键在于"选谁"和"怎么加权"被干净地分开了。

记号：\(E\) 个专家 \(\{F_1,\dots,F_E\}\)，每 token 选 Top-\(K\) 个；\(s_i\) 为 token 对专家 \(i\) 的原始亲和度。

一、MoE 的基本形式

Router 先给每个专家打分，取 Top-\(K\)，输出是选中专家的加权和：

\[ s = xW_g \in \mathbb{R}^{E}, \qquad \mathcal{T} = \mathrm{TopK}(s), \qquad y = \sum_{i\in\mathcal{T}} \underbrace{\frac{e^{s_i}}{\sum_{j\in\mathcal{T}}e^{s_j}}}_{g_i}\, F_i(x) \]

\(g_i\) 是归一化后的门控权重。V2：\(E\) 很大、总参数 236B，但 \(|\mathcal{T}|\) 很小，每 token 只算 21B——容量（所有专家的参数）与计算量（实际激活的参数）解耦。

二、负载不均与 aux loss 的两难

Router 自由发挥时，token 会涌向少数热门专家：某块 GPU 累死，其他 GPU 围观。传统解法是给 loss 加一项均衡惩罚：

\[ \mathcal{L}_{\text{total}} = \mathcal{L}_{\text{LLM}} + \lambda\,\mathcal{L}_{\text{aux}} \]

推导：aux loss 为什么是"污染"

对 router 参数 \(\theta_g\) 求梯度：

\[ \nabla_{\theta_g}\mathcal{L}_{\text{total}} = \underbrace{\nabla_{\theta_g}\mathcal{L}_{\text{LLM}}}_{\text{想答对题}} \;+\; \lambda\underbrace{\nabla_{\theta_g}\mathcal{L}_{\text{aux}}}_{\text{想分均匀}} \]

第二项的方向与"把语言建模做好"毫无关系，是纯粹的基础设施约束硬塞进来的梯度。\(\lambda\) 大了，语言建模性能肉眼可见地掉；\(\lambda\) 小了，热点照旧。这是一个调参两难，不是工程细节。

三、Aux-loss-free：拥堵收费制

V3 把均衡做成一个不进 loss 的反馈控制环。每个专家维护一个动态偏置 \(b_i\)（初值 0）：

\[ \text{选择分}_i = s_i + b_i \quad\text{（取 Top-}K\text{）}, \qquad b_i \leftarrow b_i + \gamma\,\big(\overline{\text{load}} - \text{load}_i\big) \]

每 batch 统计各专家分到的 token 数 \(\text{load}_i\)：超载的专家 \(b_i\) 被下调（收"拥堵费"），空闲的被上调（发补贴）。\(\gamma\) 是很小的步长。

推导：为什么偏置不污染梯度——关键的那一行

Top-\(K\) 选出来之后，输出加权用的门控权重只看原始亲和度 \(s_i\)，偏置 \(b_i\) 被直接扔掉：

\[ y = \sum_{i\in\mathcal{T}(s+b)} \mathrm{softmax}(s_i)\, F_i(x) \quad\text{—— 注意 softmax 里没有 } b \]

\(b_i\) 只参与离散的"选谁"这一步（Top-K 是不可微的，本来就不走梯度），而所有可微的加权系数里都没有 \(b\) 的影子。于是反向传播时：

\[ \nabla_{\theta_g}\mathcal{L}_{\text{total}} = \nabla_{\theta_g}\mathcal{L}_{\text{LLM}} + 0 \]

aux 梯度项恒为零——不是调小了，是结构上不存在。router 的每一分梯度都花在"答对题"上，而负载均衡由 \(b_i\) 这个"价格信号"在训练循环外默默完成。这就是"选谁"和"怎么加权"解耦的全部含义。

算例：偏置的一次更新

4 个专家，某 batch 负载 \(\text{load} = [70, 10, 10, 10]\)，均值 \(\overline{\text{load}} = 25\)，取 \(\gamma = 0.05\)：

\[ \begin{aligned} b_1 &\leftarrow b_1 + 0.05\times(25-70) = b_1 - 2.25 \quad\text{（热门专家被收费）}\\ b_{2,3,4} &\leftarrow b_{2,3,4} + 0.05\times(25-10) = b_{2,3,4} + 0.75 \quad\text{（冷门专家被补贴）} \end{aligned} \]

下一 batch，处在边界上的 token（\(s_1\) 只比 \(s_2\) 高一点点的）就会被 \(-2.25/+0.75\) 的价差推向空闲专家；而 \(s_1\) 遥遥领先的 token 不受影响——只搬运"边际"流量，不碰"铁粉"流量，这正是收费制比配额制聪明的地方。

直觉

把专家想成高速公路的车道：aux loss 是在交规里写"每条车道必须走够多少车"（还得交警拿着 loss 的鞭子抽）；aux-loss-free 是装 ETC 龙门架——堵的车道涨价、空的车道降价，司机（token）自己用脚投票。路还是那些路，规则不进刑法（loss）。
