5. 交叉熵、困惑度与采样策略：完整数学推导

这是全书数学最密集的一章。原书把交叉熵拆成 figure 5.7 的六个步骤，每步只给一个数字，读者要自己拼出整体。这一页把六步还原成一个公式，并补上三个原书没细说的地方：为什么困惑度可以解释成「有效词表大小」、温度到底在缩放什么、1000 次采样的计数为什么和理论值对不上。

所有数字均用原书 5.1–5.3 节的 logits 手算复核，与原文逐位吻合。

一、交叉熵：把六步还原成一个公式

1.1 从最小二乘到交叉熵

预训练的目标是「预测下一个 token」。设真实 token 为 \(y\)，模型给出的分布为 \(p=(p_1,\dots,p_V)\)。我们希望最大化 \(p_y\)，等价于最小化：

\[ \mathcal{L} = -\frac{1}{N}\sum_{n=1}^{N} \log p_{y_n} \]
预备知识：对数的三条运算法则

① 乘法变加法：\(\log(ab)=\log a+\log b\)（\(a,b>0\)）；② 除法变减法：\(\log(a/b)=\log a-\log b\)，特别地 \(\log(1/x)=-\log x\)；③ 幂变乘法：\(\log(a^k)=k\log a\)。另有一条单调性：\(\log x\) 严格递增，即 \(0

推导：为什么「最大化概率」等价于「最小化负对数」

训练目标是让正确 token 的概率 \(p_y\) 尽量大，即求 \(\arg\max p_y\)。由对数的单调性，\(p\) 越大 \(\log p\) 越大，所以

\[ \arg\max_y p_y = \arg\max_y \log p_y = \arg\min_y (-\log p_y) \]

取负号只是把「求最大」翻成「求最小」，不改变最优解的位置。对 \(N\) 个 token 取平均，就得到 \(\mathcal{L}=-\frac1N\sum_n\log p_{y_n}\)。取对数的真正好处是数值：概率连乘几十次会下溢到 0，而对数把连乘变成求和（见正文 1.1 的 key 框）。

这叫负对数似然（negative log-likelihood, NLL）。它就是交叉熵在「真实分布是 one-hot」这个特例下的形式：

\[ H(p,q) = -\sum_{v=1}^{V} p_v \log q_v \]
推导：交叉熵 = 熵 + KL 散度

在 \(-\sum_v p_v\log q_v\) 里加一项再减一项（\(\sum_v p_v\log p_v\)），用除法法则合并：

\[ \begin{aligned} H(p,q) &= -\sum_{v=1}^{V} p_v\log q_v \\ &= -\sum_{v=1}^{V} p_v\log p_v + \sum_{v=1}^{V} p_v\log p_v - \sum_{v=1}^{V} p_v\log q_v \\ &= \underbrace{-\sum_{v=1}^{V} p_v\log p_v}_{H(p)\ \text{信息熵}} + \underbrace{\sum_{v=1}^{V} p_v\log\frac{p_v}{q_v}}_{D_{\mathrm{KL}}(p\|q)\ \text{KL 散度}} \end{aligned} \]

第一项 \(H(p)\) 只与真实分布有关，训练时是常数；第二项 \(D_{\mathrm{KL}}(p\|q)\ge 0\)（Gibbs 不等式），当且仅当 \(q=p\) 时为 0。所以最小化交叉熵等价于最小化 KL 散度——也就是让模型分布 \(q\) 去逼近真实分布 \(p\)。one-hot 时 \(H(p)=0\)，交叉熵退化为纯粹的 \(-\log q_y\)。

其中 \(p\) 是真实分布（本例中 \(p_{y}=1\)，其余为 0），\(q\) 是模型分布。one-hot 代入后，\(-\sum_v p_v\log q_v = -1\cdot\log q_y\)，只剩一项。

为什么用对数

概率是乘性的，而概率连乘几十次会瞬间下溢到 0（fp32 最小正规数约 1e-38，30 项就可能溢出）。取对数把乘法变加法：\(\log\prod = \sum\log\)。

用原书 5.1.2 节的例子实测：六个 token 的概率是 [7.4541e-05, 3.1061e-05, 1.1563e-05, ...]，总和只有 0.000189。直接连乘会得到 \(0.000189^{6} \approx 4.5\times10^{-23}\)，虽然还没溢出，但精度已经损失殆尽。取对数后是 [-9.5042, -10.3796, -11.3677, -11.4798, -9.7764, -12.2561]，全部在 −10 附近，数值健康。

1.2 PyTorch 的 cross_entropy 内部做了六件事

原书 figure 5.7 把计算拆成六步。用公式写出来（这就是 torch.nn.functional.cross_entropy 的数学定义）：

  1. logits → probabilities：\(p_i = \dfrac{e^{z_i}}{\sum_j e^{z_j}}\)（内部做，数值稳定版）
  2. 取 log：\(\log p_i\)
  3. 按 targets 索引：只取 \(\log p_{y_n}\)，其他位置丢弃
  4. 取负：\(-\log p_{y_n}\)
  5. 求平均（reduction='mean'）：\(\dfrac{1}{N}\sum_n -\log p_{y_n}\)
  6. 输出标量 loss

关键在于 第 1 步和第 2 步其实可以合并成一个恒等式：

\[ \log p_y = z_y - \log\sum_{j=1}^{V} e^{z_j} = z_y - \mathrm{logsumexp}(z) \]
推导：\(\log p_y = z_y - \mathrm{logsumexp}(z)\)

从 softmax 定义 \(p_y = e^{z_y}/\sum_j e^{z_j}\) 出发，两边取对数，用除法法则 \(\log(a/b)=\log a-\log b\)：

\[ \log p_y = \log\left(\frac{e^{z_y}}{\sum_{j=1}^{V}e^{z_j}}\right) = \log\big(e^{z_y}\big) - \log\left(\sum_{j=1}^{V}e^{z_j}\right) = z_y - \log\sum_{j=1}^{V}e^{z_j} \]

其中用到了 \(\log(e^{z_y})=z_y\)（幂法则的逆用）。记 \(\mathrm{logsumexp}(z)=\log\sum_j e^{z_j}\)，即得恒等式。实际意义：PyTorch 的 cross_entropy 内部直接算 \(z_y-\mathrm{logsumexp}(z)\)，根本不构造 50257 维的概率向量——这就是正文说的「数值效率与稳定性」。

这解释了 appendix A 的那句注释："PyTorch's commonly used loss functions combine the softmax operation with the negative log-likelihood loss in a single class. The reason for this is numerical efficiency and stability."——根本不显式构造 probas 这个 50257 维的概率向量，而是直接算 logsumexp。

这就是「不要先 softmax 再 cross_entropy」的原因

如果你写 loss = F.cross_entropy(F.softmax(logits, dim=-1), targets)，模型在 logits 上做了一次 logsumexp，又在概率上做了一次。概率值可能小到 \(10^{-40}\)，再取对数就变 −92，损失完全失真，而且梯度被截断。

正确做法：F.cross_entropy(logits, targets)，把原始 logits 传进去。附录 A 说的 "the outputs of the last layer (logits) without passing them to a nonlinear activation function" 就是这个意思。

1.3 用原书数字完整走一遍

原书给出六个 token 的 log_probas（即 \(\log p_{y_n}\)）：

tensor([ -9.5042, -10.3796, -11.3677,
         -11.4798,  -9.7764, -12.2561])

直接算：

\[ \frac{9.5042 + 10.3796 + 11.3677 + 11.4798 + 9.7764 + 12.2561}{6} = \frac{64.7638}{6} = 10.7940 \]

✓ 与原书 neg_avg_log_probas = tensor(10.7940) 和 cross_entropy 的输出完全一致。

这个 10.7940 意味着什么？每个 token 平均只分到了 \(e^{-10.7940} \approx 2.1\times10^{-5}\) 的概率。随机猜的话应该得到 \(1/50257 \approx 2.0\times10^{-5}\)。也就是说，这个刚初始化的模型和随机猜几乎一样。这正是原书说训练目标是「bring the negative average log probability down to 0」的原因——把 10.79 压到接近 0 意味着每个 token 的概率趋近 1。

1.4 为什么是 mean 而不是 sum

逐 token 的 NLL 是 9.5042, 10.3796, 11.3677, ...，用 sum 会得到 64.7638；用 mean 得到 10.7940。

选择 mean 的实际理由：让 loss 的量级和序列长度解耦。如果不除以 \(N\)，训练 1024-token 序列的 loss 就是 1024-token 序列的 1024 倍，学习率、梯度裁剪阈值都得跟着改。mean 让同一个 lr=0.0004 在任何序列长度下都可用。

这个选择在第 7 章会再次出现，而且结论相反：那里用 sum 才是对的（因为要按序列而非按 token 计权）。理解「什么时候除以 N」是跨章节的关键。

二、困惑度：把 loss 翻译成人话

2.1 定义与验算

\[ \mathrm{PPL} = \exp(\mathcal{L}) = \exp\left(-\frac{1}{N}\sum_{n=1}^{N}\log p_{y_n}\right) \]
推导：困惑度 = 逆概率的几何平均

把指数里的求和搬出来，用 \(\exp(\sum)=\prod\exp\) 和 \(\exp(k\log a)=a^k\)：

\[ \begin{aligned} \mathrm{PPL} &= \exp\left(-\frac{1}{N}\sum_{n=1}^{N}\log p_{y_n}\right) = \prod_{n=1}^{N}\exp\left(-\frac{1}{N}\log p_{y_n}\right) \\ &= \prod_{n=1}^{N}\left(p_{y_n}^{-1}\right)^{1/N} = \left(\prod_{n=1}^{N}\frac{1}{p_{y_n}}\right)^{1/N} \end{aligned} \]

最后一步正是几何平均的定义：\(N\) 个数的几何平均 = 乘积开 \(N\) 次方。所以困惑度就是「每个正确 token 的逆概率」的几何平均——模型平均每个 token 要在多少个等可能的候选里猜，这正是正文 2.2「有效词表大小」的来源。

代入原书的 10.7940：

\[ e^{10.7940} = 48{,}725.93 \]

✓ 与原书 perplexity = torch.exp(loss) 打印的 tensor(48725.8203) 一致（末位差异来自 10.7940 是四位小数，真正的 loss 有更多位）。

2.2 关键性质：PPL 就是「有效词表大小」

这是原书那句 "it signifies the effective vocabulary size about which the model is uncertain at each step" 的严格含义。

考虑一个均匀分布：\(p_i = 1/V\)，则每个 \(\log p = \log(1/V) = -\log V\)，所以

\[ \mathcal{L} = \log V \quad\Longrightarrow\quad \mathrm{PPL} = V \]

代入 \(V = 50257\)：均匀分布的困惑度正好是 50,257。所以：

困惑度的两种读法

读法一（除法视角）：困惑度 = 模型在每一步「等效于从多少个 token 里随机挑一个」。PPL=100 意味着模型的预测能力相当于在 100 个候选中盲猜。

读法二（信息论视角）：每个 token 消耗了 \(\log_2 \mathrm{PPL}\) 比特。PPL=100 时是 6.64 比特/token。

下界：真实分布的困惑度下限是它的真实熵 \(H(p)\)，不是 1。英文文本的熵大约 1.1–1.3 比特/token，对应 PPL 下界约 2.1–2.4。所以训练良好的 LLM 的 PPL 远大于 1，这是正常的。

把原书的例子放进这个框架：

模型状态LossPPL解读
随机初始化（原文）10.794048,726词表 50,257 的 97%——几乎完全随机
均匀分布（理论）10.824950,257完全无信息
训练 10 epoch 后（原文）3.1122.4等效于在 22 个候选中猜
熵下界~0.8~2.2理论极限

原文 5.2 节的训练输出里，第一个 epoch 训练损失是 9.781，10 个 epoch 后降到 3.11。对应 PPL 从 e^9.781 ≈ 17,688 降到 e^3.11 ≈ 22.4。两个数量级的改善，而且注意 PPL 只下降了约 800 倍（因为 loss 的下降是对数尺度的）。

PPL 的三个使用陷阱

① 不可跨 tokenizer 比较。PPL 依赖词表大小和切分粒度。同一段文本用 50k 词表 PPL=30、用 32k 词表可能 PPL=20，但这不代表后者更好。跨模型比较必须同一个 tokenizer。

② 不可跨长度比较。loss 是逐 token 平均，短句和长句的 PPL 天生不同。评测必须固定评测集和长度设置。

③ PPL 下降不等于模型变好。PPL 只衡量对下一个 token 的拟合，不衡量事实性、安全性、指令遵循能力。第 7 章的指令微调和第 8 章的评测说明了这一点。

三、温度缩放：改变的是 logits 之间的比值

3.1 定义

\[ p_i(T) = \frac{\exp(z_i / T)}{\sum_{j=1}^{V} \exp(z_j / T)} \]

原书的实现：

def softmax_with_temperature(logits, temperature):
    scaled_logits = logits / temperature
    return torch.softmax(scaled_logits, dim=0)

3.2 温度的真实作用：压缩比值，不是缩放概率

关键性质是 softmax 对 logits 的平移不变性：给所有 logits 加同一个常数 \(c\)，概率不变，因为分子分母同乘 \(e^{c/T}\)。所以温度只作用于 logits 之间的差。

取任意两个 token，\(T>0\) 时它们的概率比是：

\[ \frac{p_i(T)}{p_j(T)} = \exp\!\left(\frac{z_i - z_j}{T}\right) \]
推导：温度只缩放 logit 差（附平移不变性）

把 \(p_i(T)\) 与 \(p_j(T)\) 的定义相除，分母 \(\sum_k\exp(z_k/T)\) 完全相同，直接约掉：

\[ \frac{p_i(T)}{p_j(T)} = \frac{\exp(z_i/T)/\sum_k\exp(z_k/T)}{\exp(z_j/T)/\sum_k\exp(z_k/T)} = \frac{\exp(z_i/T)}{\exp(z_j/T)} = \exp\!\left(\frac{z_i-z_j}{T}\right) \]

用到了 \(\exp(a)/\exp(b)=\exp(a-b)\)。同理可证平移不变性：所有 logit 加常数 \(c\) 时，分子分母同乘 \(\exp(c/T)\)，概率不变——

\[ \frac{\exp((z_i+c)/T)}{\sum_j\exp((z_j+c)/T)} = \frac{\exp(c/T)\exp(z_i/T)}{\exp(c/T)\sum_j\exp(z_j/T)} = p_i(T) \]

所以温度 \(T\) 只改变 logit 之间差值的缩放比例，不改变它们的相对顺序。这就是为什么 \(T\to 0\) 时分布坍缩到 argmax（差值被放大到无穷），\(T\to\infty\) 时趋于均匀（差值被压缩到 0）。

这解释了温度的两种效果是同一件事的两面：

温度比值 \(\exp(\Delta/T)\)效果等效行为
\(T = 0.1\)比值放大 10 倍分布极陡，只有 argmax退化成 argmax
\(T = 1\)原始比值原始分布不缩放
\(T = 5\)比值缩小到 1/5分布平坦接近均匀分布
\(T \to \infty\)所有比值 → 1完全均匀纯随机选词
\(T\to 0\) 收敛到 argmax，不是发散

这是个反直觉但重要的性质。当 \(T\to 0\) 时最大 logit 那个的概率 \(\to 1\)，其余 \(\to 0\)，总和仍是 1。所以温度 0 不会产生 NaN，只是变成贪心解码。原书代码里 if temperature < 0.0 才报错，temperature=0 是合法的。

3.4 1000 次采样的计数为什么对不上理论值

原书用 print_sampled_tokens 采样 1000 次，得到：

73 x closer    0 x every    0 x effort
582 x forward   2 x inches   0 x moves
  0 x pizza     343 x toward

但 \(T=1\) 的理论概率是 closer 0.0609、forward 0.5721、toward 0.3576，对应期望计数应该是 61 / 572 / 358。实测是 73 / 582 / 343，对不上。

原因是抽样误差。二项分布的标准差是 \(\sigma = \sqrt{Np(1-p)}\)，代入：

词\(p\)期望计数标准差实测偏离
closer0.060960.97.673+1.6σ
forward0.5721572.115.6582+0.6σ
toward0.3576357.615.2343−1.0σ

三个偏离都在 1.6σ 以内，完全在正常波动范围内。这不是 bug。

习题 5.1 的加速思路就是利用这个。题目问「能不能想到更快更准的方法来确定 pizza 被采样的频率」——直接读 probas[6] 就行，不需要采样。\(T=1\) 时是 0.0001（1000 次期望 0.1 次，所以实测 0 次完全正确），\(T=5\) 时是 0.0430。采样是用来演示机制的，不是用来测量的。

四、top-k 采样：为什么掩码要放在 softmax 之前

4.1 机制

原书 5.3.2 节的代码用 topk 找出最大的 \(k\) 个 logit，用 min 取其中最小值作为阈值，然后 masked_fill 把所有小于阈值的填成 -inf：

top_logits, _ = torch.topk(next_token_logits, top_k)
min_val = torch.min(top_logits)
top_k_filtered_logits = torch.where(
    next_token_logits < min_val, -torch.inf, next_token_logits
)

然后照常 softmax。因为 \(e^{-\infty}=0\)，被砍掉的 token 概率自动为 0，剩下的自动重新归一化——和 3.4 节（见前一章）的因果掩码完全同一个技巧。

4.2 用原书 logits 走一遍 k=3

最大的三个 logit 是 6.75（forward）、6.28（toward）、4.51（closer），阈值 \(\min = 4.51\)。掩码后：

[4.51, -inf, -inf, 6.75, -inf, -inf, -inf, 6.28, -inf]

softmax 后（figure 5.15 的柱状图）：

[0.0615, 0, 0, 0.5775, 0, 0, 0, 0.3610, 0]

和为 1.0000。✓ 注意 forward 从 \(T=1\) 时的 0.5721 升到 0.5775——因为被砍掉的部分释放出来的概率质量按比例分给了保留的三个 token。

4.3 与 temperature 的分工

这解释了原书说的 "one downside of this approach is that it sometimes leads to grammatically incorrect or completely nonsensical outputs such as 'every effort moves you pizza'"：temperature=5 时 pizza 的概率从 0.0001 涨到 0.043，1000 次会撞上约 43 次。加了 top-k 之后，pizza 无论概率多小都会被排除。

两者顺序有讲究，但不是任意的

正确顺序是 先缩放 logits → 再 top-k 掩码 → 最后 softmax。原因：top-k 是「按排名」筛选的，而排名与温度无关（温度单调变换不改顺序），所以两种顺序选出的 k 个 token 完全相同。但掩码必须在 softmax 之前，否则要额外做一次重归一化，浪费一步。

原书 generate 函数的顺序正是如此：logits = logits / temperature → top_k 筛选 → softmax → multinomial。
