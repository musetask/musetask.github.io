7.3 -100 掩码与损失聚合：完整数学推导

这一章只有一个新概念：-100 是怎么让某些 token 从损失里消失的。原书用三个数字（1.1269、0.7936、1.1269）演示，但没有解释背后的两件事：

① ignore_index 同时改了分子和分母（不只是「跳过」，而是重新定义平均值）；② mean 在这里和第 5 章的 mean 语义已经不同了。

一、三个数字，先手算一遍

原书 7.3 节的例子：

logits_1 = torch.tensor([[-1.0, 1.0],
                         [-0.5, 1.5]])
targets_1 = torch.tensor([0, 1])
loss_1 = F.cross_entropy(logits_1, targets_1)   # tensor(1.1269)

1.1 两个 token 的贡献

对第一个 token，logits 是 [-1.0, 1.0]，真实类别是 0：

\[ -\log p_0 = -\log\frac{e^{-1}}{e^{-1}+e^{1}} = -\log\frac{1}{1+e^{2}} = \log(1+e^{2}) = 2.1269 \]
推导：二分类 softmax 化简为 sigmoid

关键技巧是分子分母同除以其中一个指数项。以第一个 token 为例，分子分母同除以 \(e^{1}\)：

\[ p_0=\frac{e^{-1}}{e^{-1}+e^{1}} =\frac{e^{-1}/e^{1}}{(e^{-1}+e^{1})/e^{1}} =\frac{e^{-2}}{e^{-2}+1} =\frac{1}{1+e^{2}} \]

一般地，记 \(\Delta=z_1-z_0\) 为两 logit 之差，分子分母同除以 \(e^{z_1}\) 得 \(p_1=\dfrac{1}{1+e^{-\Delta}}\)——这正是 sigmoid 函数 \(\sigma(\Delta)\)。同除的技巧消掉了绝对数值，只留下差值 \(\Delta\)：二分类的概率只取决于两个 logit 的差距，与它们的整体平移无关（softmax 平移不变性的特例）。

对第二个 token，logits 是 [-0.5, 1.5]，真实类别是 1：

\[ -\log p_1 = -\log\frac{e^{1.5}}{e^{-0.5}+e^{1.5}} = -\log\frac{1}{1+e^{-2}} = \log(1+e^{-2}) = 0.1269 \]
推导：二分类交叉熵 = softplus

接上一步，\(p_1=\dfrac{1}{1+e^{-\Delta}}\)（此处 \(\Delta=2\)）。取负对数，用 \(\log(1/x)=-\log x\)：

\[ -\log p_1 = -\log\!\left(\frac{1}{1+e^{-\Delta}}\right) = -\big[\log 1 - \log(1+e^{-\Delta})\big] = \log\!\big(1+e^{-\Delta}\big) \]

\(\log(1+e^{x})\) 有个专门名字叫 softplus，是 ReLU 的光滑版本。所以二分类交叉熵 = \(\mathrm{softplus}(-\Delta)\)：正确类别领先越多（\(\Delta\) 越大），损失越小；\(\Delta=2\) 时得 \(\log(1+e^{-2})=0.1269\)，\(\Delta=-2\) 时得 \(\log(1+e^{2})=2.1269\)。这也解释了正文 key 框里「两者之和」的关系：\(\log(1+e^{2})=2+\log(1+e^{-2})\)，因为 \(1+e^{2}=e^{2}(1+e^{-2})\)。

平均：

\[ \mathcal{L}_1 = \frac{2.1269 + 0.1269}{2} = \frac{2.2538}{2} = 1.1269 \]

✓ 与原书 tensor(1.1269) 完全一致。

logit 差距相同，损失差了 16.8 倍

第一个 token 的两个 logits 相差 \(1.0-(-1.0)=2.0\)，第二个也是 \(1.5-(-0.5)=2.0\)——logit 差距完全相同。但因为真实类别一个要选小的、一个要选大的，损失分别是 2.1269 和 0.1269，相差 16.8 倍。

原因是对称的：\(\log(1+e^{\Delta})\) 在 \(\Delta = 2\) 时是 2.1269，在 \(\Delta = -2\) 时是 0.1269，两者之和恒为 2.2539。即「自信地猜对」和「自信地猜错」在数值上是对偶的，但猜错的代价几乎全部集中在 2.1269 这一侧。

这正是交叉熵作为损失函数的全部意义：它只在「自信地犯错」时给出大惩罚，在「自信地正确」时几乎不消耗优化预算。

1.2 三个 token 会怎样

logits_2 = torch.tensor([[-1.0, 1.0],
                         [-0.5, 1.5],
                         [-0.5, 1.5]])
targets_2 = torch.tensor([0, 1, 1])
loss_2 = F.cross_entropy(logits_2, targets_2)   # tensor(0.7936)

新增的第三项是 0.1269（与第二项相同），所以：

\[ \mathcal{L}_2 = \frac{2.1269 + 0.1269 + 0.1269}{3} = \frac{2.3807}{3} = 0.7936 \]

✓ 与原书一致。

关键观察：损失从 1.1269 降到了 0.7936。多了一个训练信号，损失反而更小——因为新加的项损失很小（0.1269），把平均值拉低了。这说明交叉熵的绝对值和「加入多少监督信号」直接相关，跨不同 mask 方案比较 loss 是没有意义的。

二、-100 的机制：分子分母同时变

2.1 命题

targets_3 = torch.tensor([0, 1, -100])
loss_3 = F.cross_entropy(logits_2, targets_3)
print(loss_3)                            # tensor(1.1269)
print("loss_1 == loss_3:", loss_1 == loss_3)   # tensor(True)

原书打印 tensor(True)。数学上这是必然的：

\[ \mathcal{L}(\text{logits}_2,\, [0,1,-100]) = \frac{\sum_{n:\, y_n \ne -100} -\log p_{y_n}^{(n)}}{\left|\{n : y_n \ne -100\}\right|} = \frac{2.1269 + 0.1269}{2} = 1.1269 \]
预备知识：集合的基数记号 \(|A|\)

\(|\{n : y_n \ne -100\}|\) 读作「满足 \(y_n\ne-100\) 的下标 \(n\) 组成的集合的元素个数」。竖线在这里不是绝对值，而是集合的基数（cardinality）。本例中有效下标是 \(\{1,2\}\)，基数为 2——这正是分母从 3 变成 2 的数学写法。

最容易理解错的一点：分母也变了

很多人以为「忽略」就是分子加 0，分母不变。那样会得到 \((2.1269+0.1269+0)/3 = 0.7513\)，和原书的 1.1269 不符。

PyTorch 的行为是：被 ignore 的位置既不进分子，也不进分母。分母是「有效 token 数」而非「总 token 数」。这就是为什么 loss_1 == loss_3 严格等于 True——损失精确等于只用两个有效样本算出的损失，与第三个位置的存在完全无关。

这个语义很关键：padding 长度不会稀释损失。如果分母固定，一个 batch 里全是短回答的样本会被大量 padding 拉低 loss，梯度信号被无效数据稀释。

2.2 为什么是 −100 这个特定的数

三个约束共同决定了 −100：

  1. 必须小于 0。token ID 是 0 到 50256 的非负整数，必须能保证 −100 不会与任何真实 token ID 冲突。
  2. 必须足够小，使 exp(logit - logsumexp) 不会产生 NaN。但更重要的是——它不参与计算，所以数值上不需要真的能算出来。PyTorch 内部先筛掉它，再计算。
  3. 必须是约定俗成的。PyTorch 默认 ignore_index=-100，这是社区通用约定（与 HuggingFace Transformers 相同）。换成一个未被约定的值（如 −1）就不会被忽略——原书明确说 "replace the −100 value with another token ID that is not 0 or 1; it will result in an error"。
原书那句括号注释值得单独讲

"However, we want to keep one 50256 (end-of-text) token ID in the targets because it helps the LLM to learn to generate end-of-text tokens."

也就是说：序列末尾的 <|endoftext|>（50256）必须保留在 targets 里，不能掩成 −100。原因是模型在推理时需要一个停止信号——如果训练时从没学过输出 50256，生成时它就永远不会停，会一直写下去。

这是一个「训练目标必须包含推理时需要的能力」的例子：虽然 50256 本身不携带任何内容语义，但它是控制流的一部分。这和 padding token 必须掩掉是同一个原则的两面：有用的（含控制信息）留，无用的（纯填充）掩。

三、原书没细说的一点：mean 的语义变了

第 5 章的 reduction='mean'：分母是 batch 内所有 token 数。第 7 章在有 -100 的情况下：分母是 有效 token 数。

第 5 章（预训练）第 7 章（指令微调，有 mask）
分母\(B \times T\)\(B \times T - \#\{\text{掩掉的}\}\)
batch 内样本长短不一无 padding，全部有效有 padding，长样本的 token 权重更大
短样本的梯度信号—被稀释（有效 token 少）
为什么这样设计简单且正确见下文权衡

这个「按有效 token 加权平均」的语义有一个重要后果，值得单独指出：

token-level 平均 ⇒ 长回答权重更大

考虑一个 batch：样本 A 的回答是 5 个 token，样本 B 的回答是 100 个 token。两个都各贡献 1 个监督标签，但 B 贡献的梯度项数是 A 的 20 倍。

所以这个损失函数实际优化的是「每个 token 的平均预测质量」，而不是「每个回答的平均预测质量」。长回答的每个 token 会被更细致地监督，短回答的 token 相对被忽略。

这是 reduction='mean' 的固有性质（RNMT 里叫 token-level averaging），不是 bug。但如果你想做「每个样本等权」，需要 reduction='sum' 后自己除以 batch size——这在 GRPO 等算法里是常见的对照设计。

四、要不要掩掉 instruction：一个真实的争议

原书 figure 7.13 右侧画了「可以掩掉 instruction 部分」的选项，并把它留作习题 7.2。这里说明它的数学含义。

4.1 两种方案的损失

假设一个样本的 prompt 模板是：

### Instruction:
{prompt}
### Input:
{input}
### Response:
{response}

方案 A（原书采用，不掩 instruction）：整段都算损失，\(N_A\) = 全序列 token 数。

方案 B（掩掉 instruction）：只有 response 部分算损失，\(N_B \ll N_A\)。

方案 A（不掩）方案 B（掩 instruction）
监督的范围学会「给定前缀，续写下一个 token」学会「只在回答区，给定前缀续写下一个 token」
有效 token 数大小（可能只有 20–50）
梯度信号量多少
过拟合风险较高（要记住指令原文）较低
小数据集表现可能更好（信号更多）更差（信号太少）
大数据集表现可能过拟合可能更好

4.2 原书引用的结论

原书写道（引用 Shi et al. 2024, "Instruction Tuning With Loss Over Instructions"）：不掩 instruction 反而对 LLM 表现有益。所以原书采用方案 A，把掩码留作习题。

为什么「不算损失」不等于「没在学」

直觉上「模型不需要学会复述指令」，所以掩掉指令应该更干净。但实际上：损失函数同时是训练信号和正则化器。

在 instruction 上算损失，迫使模型的隐状态编码指令的语义，从而让 response 的生成有更好的条件。这是一种隐式的条件增强，而非单纯的记忆负担。

这也解释了为什么这个结论会随数据集规模翻转：数据少时信号不足是主要矛盾，数据多时过拟合才是主要矛盾。原书用 1,000 条 Alpaca 样本做微调，属于「数据少」的情况，所以不掩是对的。

五、初始损失 3.826 意味着什么

原书 7.6 节的微调起点：

Training loss:   3.825908660888672
Validation loss: 3.7619335651397705

这仍然可以按困惑度读：

\[ e^{3.8259} = 45.9, \qquad e^{3.7619} = 43.0 \]

换句话说：GPT-2 medium 在指令数据上，每 token 的等效候选数是 46 个。

为什么这个数比随机初始化时高那么多

对比第 5 章随机初始化的 48,726（PPL）。现在只有 46，降了三个数量级——因为 GPT-2 medium 是预训练过的，它对英文有极强的先验，<|endoftext|>（50256）这类 token 也很常见。

但 46 仍然说明：这个模型完全不知道指令微调的数据格式（### Instruction: 这种模板）。它只知道「这是一段文本，猜下一个 token」。

训练目标就是把 46 压到接近文本熵（约 2–3）。这也是为什么指令微调只需要几千步就能见效——起点已经很低了。

注意 validation loss (3.762) 略低于 training loss (3.826)。这在微调的第一时刻是正常的：训练集样本少、且可能已在 loss 的下降沿；验证集是独立样本。这个差距会在后续训练中扩大并最终反转为过拟合信号——如果验证 loss 开始回升，就该早停了。

全章一句话

-100 做的不是「加零」，而是「从分子和分母里同时删掉这一项」。这保证了 padding 长度不影响损失，也保证了 loss_1 == loss_3 这样的严格相等。

而 -100 的默认值来自 PyTorch 约定，不是数学必然——换成任何其他数字都不会被忽略，而是会因为越界而报错。
