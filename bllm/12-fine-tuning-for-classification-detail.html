☰ 6. 分类损失与 argmax

6.6–6.7 分类损失与 argmax：完整数学推导

这一章的数学本身很简单（就是第二章的交叉熵换个维度），但有三处概念性的坑原书只是一笔带过：

① 为什么 argmax 可以跳过 softmax（数学上严格成立）；② 为什么 2.153 的初始损失说明模型完全没在「猜」；③ 交叉熵从 0.693 起步——这个数才是分类任务的随机基线。

此外，交叉熵 7.589 这个数值得单独讲：它暴露了分类微调初期最容易犯的错误。

一、argmax 与 softmax 的等价性

1.1 命题

对任意实数向量 \(z\)，softmax 保持大小顺序：

\[ \arg\max_i \frac{e^{z_i}}{\sum_j e^{z_j}} = \arg\max_i z_i \]

证明：设 \(m = \arg\max_i z_i\)。对任意 \(i\)，\(e^x\) 是严格单调递增函数，故 \(z_i \le z_m \Rightarrow e^{z_i}\le e^{z_m}\)，等号仅当 \(i=m\)。分子逐项保序，而分母 \(\sum_j e^{z_j}\) 是对所有 i 都相同的正数，除以同一个正数不改变顺序。证毕。

所以原书这句 "Using the softmax function here is optional because the largest outputs directly correspond to the highest probability scores" 是严格正确的，可以放心省掉。

省掉 softmax 省掉的不只是算力

更重要的是数值稳定性。logits 直接 argmax 是整数索引比较，零精度损失；走 softmax 则要先算 50257 维（即使是二分类也是 2 维）的 exp，虽然这不会出错，但多了一步浮点运算和潜在的溢出风险。

反过来，算 loss 时绝不能省 softmax——cross_entropy 内部自己做，而且必须用原始 logits。这就是原书 calc_accuracy_loader 用裸 logits 算准确率、calc_loss_batch 也把 logits 直接传给 cross_entropy 的原因。

1.2 用原书数字验证

原书 6.6 节的 outputs[:, -1, :] = tensor([[-3.5983, 3.9902]])：

  • argmax：3.9902 > −3.5983，返回 1（spam）。原书打印 Class label: 1。✓
  • softmax：分母 \(e^{-3.5983}+e^{3.9902} = 0.02737 + 54.0657 = 54.0931\)，得 [0.000506, 0.999494]。

argmax 和 softmax 给出同一个答案 1。✓

这个例子揭示了微调前模型的状态

softmax 后 spam 概率是 0.9995，模型极其自信地预测错了。原书 figure 6.14 的另一行 [-3.9846, 5.2940] 同样如此。

原因是：GPT-2 的输出层是为预测 50,257 个 token 训练的，从来没见过「spam / not spam」这两个类。我们把 out_head 换成 nn.Linear(768, 2) 后，它的权重是随机初始化的，没有任何先验。

更糟的是，随机初始化的二分类头经常是「一边倒」的——softmax 强烈偏向某一类。这种「自信的错误」比「均匀的瞎猜」更难训练，因为梯度会被错误的强烈信念主导。这就是原书 6.5 节强调「用两个输出节点而不是一个」的原因之一。

二、为什么不能直接优化准确率

2.1 准确率不可微

分类准确率定义为：

\[ \mathrm{Accuracy} = \frac{1}{B}\sum_{b=1}^{B}\mathbb{1}\!\left[\arg\max_i z^{(b)}_i = y_b\right] \]

其中 \(\mathbb{1}[\cdot]\) 是指示函数（条件成立取 1，否则取 0）。它是一个阶跃函数：

\(z_0 - z_1\)Accuracy\(\dfrac{\partial \mathrm{Acc}}{\partial (z_0-z_1)}\)
0.00110
0.0001undefined（跳变点）
−0.00100

指示函数几乎处处导数为 0，在跳变点不可导。这意味着：无论怎么微调 logits，只要不跨越决策边界，梯度就是零，模型永远不会更新。「从 51% 准确率调到 49.9% 再调回来」在梯度下降里是完全不可见的。

原书原话："Because classification accuracy is not a differentiable function, we use cross-entropy loss as a proxy to maximize accuracy."

2.2 交叉熵作为代理：它与准确率同向，但处处可微

二分类的交叉熵（\(C=2\)）：

\[ \mathcal{L} = -\frac{1}{B}\sum_{b=1}^{B}\left[y_b \log p_1^{(b)} + (1-y_b)\log p_0^{(b)}\right] \]
推导：二分类交叉熵是一般交叉熵的特例

一般交叉熵（见第 5 章）是 \(\mathcal{L}=-\sum_{c}p_c\log q_c\)，真实分布 \(p\) 为 one-hot。\(C=2\) 时只有两类，记真实标签 \(y_b\in\{0,1\}\)：

\[ \begin{aligned} y_b=1\ (\text{spam})&:\quad -\sum_{c=0}^{1}p_c\log q_c = -(0\cdot\log p_0 + 1\cdot\log p_1) = -\log p_1^{(b)} \\ y_b=0\ (\text{not spam})&:\quad -(1\cdot\log p_0 + 0\cdot\log p_1) = -\log p_0^{(b)} \end{aligned} \]

把两种情况写成一个式子：\(-[y_b\log p_1^{(b)}+(1-y_b)\log p_0^{(b)}]\)——\(y_b=1\) 时第二项系数 \((1-y_b)=0\) 自动消失，\(y_b=0\) 时第一项消失。再对 \(B\) 个样本取平均，即得正文公式。本质没变：每次只惩罚真实类别的负对数概率。

关键性质：对正确类别的预测越自信，loss 越小，且下降是平滑单调的。即使 argmax 早就正确（准确率不再变化），loss 仍在下降，梯度仍在推动模型。

0.6931 是分类任务的「随机猜测」基线

随机模型给出 \(p_1=0.5\)，此时 CE = \(-\log 0.5 = 0.6931\)。这个数是所有二分类交叉熵曲线的起点。

对应地，准确率的随机基线是 50%。原书 6.6 节实测微调前的准确率是 46.25% / 45.00% / 48.75%——全部在 50% 上下随机波动，正是这个基线。原书说 "the prediction accuracies are near a random prediction, which would be 50%"，✓。

所以判断分类微调是否有效有两个独立的门槛：准确率要显著超过 50%，loss 要显著低于 0.693。二者必须同时满足。

三、一个真实的失败信号：7.589

把 1.2 节的 logits 代入交叉熵，假设真实标签是 not spam（0）：

\[ \mathcal{L} = -[\log p_0] = -\log(0.000506) = 7.588 \]

这个损失非常大——比 0.693 的随机基线高了近 11 倍。梯度会非常剧烈地推动模型翻转预测。

反过来，如果真实标签是 spam（1），损失是 \(-\log 0.999494 = 0.000506\)，几乎为 0，没有任何学习信号。

这解释了原书 6.7 节的第一个 loss 值 2.153

训练开始时 Train loss 2.153，远高于 0.693 的随机基线。这不是「已经学得很好」，而是「模型正带着强烈的错误信念，需要很大的梯度去纠正」。

如果 loss 远高于 0.693，通常意味着：① 随机初始化的分类头过于极端；② 学习率设置不当（5e-5 是正确的量级，见下）；③ 标签和预测的对应关系搞反了。

到 Ep 1 (Step 000050) 降到 0.617，已经低于 0.693 的随机基线——此时才真正开始「学习」而非「纠正」。

四、两个实现细节的原书解释

4.1 为什么只取最后一个 token

# 第 5 章（预训练）：优化所有 token 的下一个词预测
logits = model(input_batch)                     # [B, T, 50257]
loss = F.cross_entropy(logits.flatten(0,1), targets.flatten())

# 第 6 章（分类）：只优化最后一个位置的分类
logits = model(input_batch)[:, -1, :]   # [B, 2]
loss = F.cross_entropy(logits, target_batch)

形状从 \([B,T,50257]\) 变成 \([B,2]\)，平均的项数从 \(B\times T\) 降到 \(B\)。这是两个本质不同的任务：

预训练分类微调
监督信号每个位置的下一个 token整个序列的一个标签
每样本监督项数\(T\)（如 1024）1
任务性质稠密监督稀疏监督（一个标签）
学习率\(4\times10^{-4}\)\(5\times10^{-5}\)
为什么分类的学习率要小 8 倍

预训练时每个样本提供 1024 个梯度信号，可以承受大学习率。分类时每个样本只提供 1 个信号，有效梯度被平均了 1024 倍。用同样大的学习率会导致参数剧烈震荡。

更本质的原因：分类是在一个已经训练好的模型上做小幅调整，而预训练是从随机初始化开始。lr=5e-5 和 weight_decay=0.1 与第 5 章的 lr=4e-4 是同一套配置思路，区别只在幅度。

原书还提供了一个对照实验（习题 6.3）：用第一个 token 而不是最后一个 token 训练，效果明显更差——因为第一个 token 还没积累到任何上下文信息。这是 [:, -1, :] 这个切片有意义的直接证据。

4.2 为什么准确率先调成 46.25%

Training accuracy:   46.25%
Validation accuracy: 45.00%
Test accuracy:       48.75%

这些数字基于 10 个 batch（每 batch 32 个样本 = 320 个样本）。在 50% 基线上，三次测量的标准误是：

\[ \mathrm{SE} = \sqrt{\frac{0.5 \times 0.5}{320}} = 0.0280 \;\Rightarrow\; 2.80\% \]
预备知识：伯努利分布的均值与方差

一次「猜对/猜错」是伯努利试验：\(X=1\)（猜对）概率 \(p\)，\(X=0\) 概率 \(1-p\)。均值 \(\mathrm{E}[X]=1\cdot p+0\cdot(1-p)=p\)；方差 \(\mathrm{Var}(X)=\mathrm{E}[X^2]-(\mathrm{E}[X])^2=p-p^2=p(1-p)\)（因为 \(X\) 只取 0/1，所以 \(X^2=X\)）。\(p=0.5\) 时方差最大，为 0.25。

推导：比例的标准误 \(\mathrm{SE}=\sqrt{p(1-p)/n}\)

320 个样本的准确率是 320 个独立伯努利变量的平均：\(\hat p=\frac1n\sum_{i=1}^n X_i\)（此处 \(n=320\)）。方差满足 \(\mathrm{Var}(aX)=a^2\mathrm{Var}(X)\)，且独立变量和的方差可加：

\[ \mathrm{Var}(\hat p)=\mathrm{Var}\!\left(\frac1n\sum_{i=1}^n X_i\right) =\frac{1}{n^2}\sum_{i=1}^n\mathrm{Var}(X_i) =\frac{1}{n^2}\cdot n\cdot p(1-p)=\frac{p(1-p)}{n} \]

标准误就是标准差：\(\mathrm{SE}=\sqrt{p(1-p)/n}\)。代入 \(p=0.5,\ n=320\) 得 \(\sqrt{0.25/320}=0.0280\)。含义：纯随机猜测下，320 个样本的准确率天然有 ±2.8% 的抖动——所以 46.25% 与 50% 的差距（约 1.3σ）在统计上什么都说明不了。

所以 46.25%、45.00%、48.75% 全部落在 \(50\% \pm 1.8\sigma\) 内，与随机猜测无法区分。原书的结论「As we can see, the prediction accuracies are near a random prediction」✓。

微调后的对照：原书 6.7 节 5 个 epoch 后达到 Training 100.00% | Validation 97.50%。100% 的训练准确率对应训练 loss 约 0.083（第 5 个 epoch 最后一次打印）。训练集完美、验证集 97.5% 的差距说明开始过拟合了——原书建议用验证集早停。

交叉熵作为「对数刻度」的直观含义

第 4 章说过，困惑度是 CE 的指数。这里同样适用：二分类里 PPL = \(e^{\mathcal{L}}\) 就是「等效候选数」，理论上限是 2（二分类只有两类）。

所以整个训练过程的 PPL 从 8.61 降到 1.09，从「在 8.6 个东西里瞎找」变成「几乎确定」。而 97.5% 的验证准确率对应 PPL 约 1.1——这两个数字描述的是同一件事。

这也解释了为什么 CE 曲线的形状比绝对值更有意义：0.5 → 0.1 看起来只降了 80%，但对应的 PPL 从 1.65 降到 1.11，实际的信息增益要大得多。这就是为什么 loss 曲线总是「前段陡、后段平」。

本章的核心：一个可微的替代品

准确率是对的目标、错的损失：它衡量我们真正在乎的东西，但不可微、无法优化。

交叉熵是可微的损失、不错的代理：它能被梯度下降优化，且与准确率同向。实践中两者高度一致（验证准确率 97.5% 对应 loss 0.074）。

用 argmax(logits) 而不是 argmax(softmax(logits)) 算准确率，既省一步运算，又避免不必要的浮点误差——因为这两者数学上严格等价。
