LLM 推理的强化学习训练现状

原文：Sebastian Raschka《The State of Reinforcement Learning for LLM Reasoning》（2025 年 4 月）· 阅读原文。 本页为中文翻译，并为文中所有数学公式补充了「推导」与「预备知识」注解（读者假设：大学数学水平，但忘了计算细节）。

最近一个月发生了很多事，尤其是 GPT-4.5 和 Llama 4 等旗舰模型的发布。但你可能注意到了，大家对这些发布的反应相对平淡。为什么？一个原因可能是 GPT-4.5 和 Llama 4 仍然是传统模型——它们没有用显式的面向推理的强化学习来训练。

与此同时，xAI 和 Anthropic 等竞争对手给模型加了更多推理能力和功能。比如 xAI Grok 和 Anthropic Claude 的界面里，某些模型都有一个 "thinking"（或 "extended thinking"）按钮，可以显式开关推理能力。

GPT-4.5 和 Llama 4（非推理模型）反响平淡，说明单纯靠扩大模型规模和数据，可能已经接近极限。但 OpenAI 最近发布的 o3 推理模型表明，策略性地投入算力——特别是用为推理任务定制的强化学习方法——仍有可观的提升空间。（据 OpenAI 员工在直播中透露，o3 的训练算力是 o1 的 10 倍。）

推理不是银弹，但它确实能可靠地提升模型在难题上的准确率和解题能力。我预计，面向推理的后训练会成为未来 LLM 流水线的标配。

这篇文章就来聊聊用强化学习训练推理能力的最新进展。

一、理解推理模型

绕不开的第一个问题当然是：推理到底是什么。简单说，推理是让 LLM 更擅长处理复杂任务的一系列推理手段和训练技术。

定义

在 LLM 语境下，推理（reasoning）指模型在给出最终答案之前，先产出中间步骤的能力。这个过程常被称为思维链（chain-of-thought, CoT）推理：LLM 显式地生成一串结构化的陈述或计算，展示它是如何得出结论的。

LLM 的推理能力可以通过两种方式提升：增加训练算力，或增加测试时（推理时）算力。上一篇文章只讲了测试时算力的方法，本文终于要细看训练方法。

用来构建和改进推理模型的强化学习训练方法，或多或少都与 RLHF（基于人类反馈的强化学习）有关——RLHF 是用来开发和对齐传统 LLM 的方法。所以在讲面向推理的 RL 改造之前，先快速回顾一下 RLHF 是怎么工作的。

二、RLHF 基础：一切的起点

传统 LLM 通常经历三步训练：

  1. 预训练（pre-training）
  2. 有监督微调（supervised fine-tuning, SFT）
  3. 对齐（alignment，通常用 RLHF）

RLHF 是"原始"的 LLM 对齐方法，是 InstructGPT 论文里用来开发第一个 ChatGPT 的配方中的标准动作。它的最初目标是让 LLM 与人类偏好对齐：比如你让 LLM 对同一个 prompt 生成多个回答，RLHF 会引导 LLM 多生成你更喜欢的那种风格的回答。（RLHF 也常用来做安全微调：避免泄露敏感信息、说脏话等等。）

为简单起见，把 RLHF 流水线拆成三个步骤看：

  • RLHF 步骤 1（前置）：对预训练模型做有监督微调（SFT）
  • RLHF 步骤 2：训练一个奖励模型（reward model）
  • RLHF 步骤 3：用近端策略优化（PPO）微调

步骤 1：有监督微调

采样一批 prompt，请人类写出高质量回答，用这个数据集以有监督方式微调预训练基座模型。这一步技术上还不是 RL，只是前置准备。

步骤 2：训练奖励模型

对每个 prompt，用上一步的 SFT 模型生成四个回答，请人类标注员按偏好排序。排序比写回答省力，但依然耗时。拿到排序数据集后，训练一个奖励模型（RM）：它对任意回答输出一个奖励分数，用来替代人工排序，让后续大规模训练可行。

奖励模型一般就从 SFT 模型改装而来：把原来的 next-token 分类输出层换成一个只有一个输出节点的回归层。

步骤 3：用 PPO 微调

用奖励模型的分数，通过近端策略优化（proximal policy optimization, PPO）继续微调 SFT 模型。PPO 是 RLHF 最初用的 RL 算法，至今仍是最流行的。

PPO 的设计目标是让策略训练更稳定、更高效（RL 里"策略"就是我们要训练的模型，这里策略 = LLM）。它的两个关键想法：

  • 裁剪过的损失函数（clipped loss）：限制每次更新中策略允许的变化幅度，防止某一步更新过大导致训练失稳；
  • KL 散度惩罚：把当前策略和原始 SFT 模型比较，鼓励更新不要偏离太远——毕竟我们是做偏好微调，不是彻底重训。这就是 "proximal"（近端）的来历。

另外 PPO 还会加一个熵奖励（entropy bonus），鼓励训练时输出多样化，促进探索。

三、PPO 简介：RL 的主力算法

下面用伪代码展示 PPO 的关键步骤。为了直观，配一个类比：想象你是个厨师，开了一家外卖小店，不断尝试新菜谱变体来提高顾客满意度。你的总目标是根据顾客反馈（reward）调整菜谱（policy）。

第 1 步：计算新旧策略的 next-token 概率之比

ratio = new_policy_prob / old_policy_prob

这是在检查"新菜谱"和"旧菜谱"差了多少。注意：这里的 "new_policy" 按惯例指正在训练中的当前版本，不是最终更新完的版本。

第 2 步：把 ratio 乘以"这个动作有多好"（advantage）

raw_score = ratio * advantage

为简单起见，假设 advantage 直接由奖励信号算出：

advantage = actual_reward - expected_reward

类比：advantage = 顾客评分 - 预期评分。比如新菜得了 9/10，平时只有 7/10，advantage 就是 +2。

注意这是简化。实际用的是广义优势估计（GAE），这里略去不表。但有一个重要细节：预期奖励由一个叫 "critic"（或 value model，价值模型）的模型算出，实际奖励由奖励模型算出。也就是说，advantage 的计算涉及另外 2 个模型，每个都和我们要微调的模型差不多大。

类比：critic 就像你请朋友先试吃新菜，请他估计顾客会打几分（预期奖励）；奖励模型就是真正的顾客，给出实际反馈（实际奖励）。

第 3 步：算一个裁剪过的分数

如果新策略变化太大（比如 ratio > 1.2 或 < 0.8），就把 ratio 裁剪：

clipped_ratio = clamp(ratio, 0.8, 1.2)
clipped_score = clipped_ratio * advantage

类比：新菜谱得到一条特别好（或特别差）的评价，你可能想把整个菜单推倒重来——但这很冒险。所以先限制这次菜谱能改多少。（比如这次菜做得特别辣，恰好这个顾客嗜辣，不代表所有人都爱。）

第 4 步：取 raw_score 和 clipped_score 中更小的那个

final_score = min(raw_score, clipped_score)

这是一种谨慎：如果 advantage 为正（新行为更好），我们封顶奖励，不想因为一次可能是运气的好结果就过度信任；如果 advantage 为负（新行为更差），我们限制惩罚，不想因为一次坏结果就反应过度——除非它持续地差。

换句话说：advantage 为正时取两者中较小的（避免过度奖励），为负时取两者中较大的（避免过度惩罚）。（感谢 Johanna Reiml 指出了本文早期版本在 PPO 下界性质上的问题，现已修正。）

第 5 步：算损失

训练时我们要最大化这个 final_score（把符号取反后用梯度下降来最小化）。另外再加一个 KL 惩罚项，β 是惩罚强度的超参数：

loss = -final_score + β * KL(new_policy || reference_policy)

类比：加这个惩罚是为了保证新菜谱别偏离你原来的风格太远，防止你每周都"重塑厨房"——比如你不想一夜之间把意餐厅变成 BBQ 店。

本节要点 · PPO 涉及 4 个模型
  1. 策略（policy）：SFT 训练过的、我们要继续对齐的 LLM；
  2. 奖励模型（reward model）：预测奖励的模型（见 RLHF 步骤 2）；
  3. critic（价值模型）：可训练的模型，估计（部分回答的）预期奖励；
  4. 参考模型（reference model）：原始策略，用来约束策略不要偏离太远。

为什么既要奖励模型又要 critic？奖励模型在 PPO 训练之前训好，用来把人工偏好标注自动化，它给完整回答打分；critic 评判的是部分回答，它在训练中持续更新，以更好地估计奖励模型给出的奖励。奖励模型通常冻结，critic 持续训练。

👉 上面五步的每一步背后都有数学：PPO 完整数学推导（重要性采样、clip 的几何意义、KL 惩罚的无偏估计）。

更多 PPO 数学细节超出本文范围，感兴趣可以读 InstructGPT 之前的四篇论文：(1) Asynchronous Methods for Deep Reinforcement Learning (2016)——把策略梯度作为 Q-learning 的替代方案引入深度 RL；(2) Proximal Policy Optimization Algorithms (2017)——PPO 本体；(3) Fine-Tuning Language Models from Human Preferences (2020)——把 PPO + 奖励学习用于预训练语言模型，加 KL 正则防止偏离自然语言太远；(4) Learning to Summarize from Human Feedback (2022)——后来 InstructGPT 沿用的 RLHF 三步流程。

四、RL 算法：从 PPO 到 GRPO

PPO 是 RLHF 最初用的算法。从技术上讲，它在用来训练推理模型的 RL 流水线里也完全可用。但 DeepSeek-R1 的 RL 流水线用的是另一个算法：GRPO（Group Relative Policy Optimization，组相对策略优化），出自他们更早的 DeepSeekMath 论文（2024）。

GRPO 的动机

DeepSeek 团队把 GRPO 描述为"PPO 的一个变体，在提升数学推理能力的同时，优化了 PPO 的显存占用"。关键词是计算效率。

效率提升的办法是扔掉 "critic"（价值模型）——也就是那个算价值函数（预期未来奖励）的 LLM。取而代之，GRPO 从策略模型自身采样多个回答，用它们的相对好坏来算 advantage。

👉 数学上这为什么行得通：GRPO 与 Dr. GRPO 数学推导（组内归一化如何替代 critic、长度偏差从哪来）。

五、RL 奖励建模：从 RLHF 到 RLVR

前面把 RLHF 讲成了流程，也介绍了 PPO 和 GRPO 两个 RL 算法。但 RLHF 本来是 LLM 对齐工具箱里的东西，它和推理有什么关系？

联系在于：DeepSeek 团队用类似的 RL 方法（配 GRPO）训练了 R1 和 R1-Zero 的推理能力。区别在于，他们用的不是人类偏好 + 训练奖励模型，而是可验证的奖励（verifiable rewards）。这种方法叫 RLVR（reinforcement learning with verifiable rewards）。

RLVR 的核心

和标准 RLHF 相比，RLVR 绕开了奖励模型。模型不再从人类标注里学"什么是好答案"，而是从确定性工具（符号验证器、规则工具）那里拿到直接的二元反馈（对/错）：数学题用计算器，代码生成用编译器。

动机有两个：一是避开昂贵/带噪声的人类或学到的奖励，用自动化的正确性检查做监督信号；二是"便宜"的工具可以替代昂贵的奖励模型训练和奖励模型本身——奖励模型通常是整个预训练模型（加一个回归头），RLVR 高效得多。

一句话总结：DeepSeek-R1 用的是 RLVR + GRPO，训练流程里干掉了两个昂贵的模型：奖励模型和价值模型（critic）。

六、DeepSeek-R1 推理模型是怎么训练的

DeepSeek-R1 家族有三种模型：

  1. DeepSeek-R1-Zero：纯 RL 训练；
  2. DeepSeek-R1：指令微调（SFT）+ RL；
  3. DeepSeek-Distill 系列：只用指令微调（SFT）蒸馏，没有 RL。

R1-Zero 用可验证奖励（RLVR）+ GRPO 训练，结果表明这足以让模型通过生成中间步骤展现出推理能力——SFT 阶段可以跳过，模型靠探索而不是学例子来提升推理能力。

R1 是旗舰，性能最好。和 R1-Zero 的区别是交替做了指令微调、RLVR 和 RLHF。

Distill 系列是小而易部署的模型：用 R1 生成的指令数据，对 Llama 3 和 Qwen 2.5 做指令微调得到。推理部分没用 RL（但 Llama 3 / Qwen 2.5 基座本身用过 RLHF）。

关键点：DeepSeek 团队训练 R1-Zero 时没有用神经奖励模型，而是规则奖励系统，主要两类：

  • (1) 准确率奖励：回答对不对。比如确定性答案的数学题，要求模型把最终答案按指定格式给出（例如放在方框里），以便规则验证；LeetCode 题则用编译器按预设测试用例给反馈。
  • (2) 格式奖励：强制模型把思考过程放在 <think> 和 </think> 标签之间。

（他们不用 outcome/process 神经奖励模型的原因：发现神经奖励模型在大规模 RL 里容易被奖励 hack。）

七、近期 RL 论文的经验教训

上个月读了大量推理模型论文，挑最有意思的想法和洞察总结如下（"[n]" 编号对应文末论文列表）。

DeepSeek-R1 论文清楚地表明：有监督微调（SFT）+ 强化学习（RL）优于纯 RL。直觉上，给蒸馏模型（本质上就是用大模型生成的推理例子做 SFT 的模型）再加 RL，应该能进一步提升。DeepSeek 团队确实观察到了这个现象，也有几个团队独立验证：

  • [8] 用 1.5B 的 DeepSeek-R1-Distill-Qwen，只用 7000 个例子、42 美元算力做 RL 微调，就大幅提升，小模型在 AIME24 数学基准上超过了 OpenAI o1-preview；
  • [15] 但另一个团队提醒：这些提升可能不总是统计显著的——RL 确实能改进小蒸馏模型，但基准分数有时会夸大提升幅度。

前面说过 RLVR 不一定非要用 GRPO；DeepSeek 的 GRPO 只是恰好高效又好用。[12] 表明，朴素 PPO + 简单的二元正确性奖励就足以让模型的推理能力和回答长度同步扩展。

更有意思的是，PPO 和 GRPO 都有长度偏差（length bias），好几篇论文研究了怎么对付"又长又错"的回答：

  • [14] 分析了 PPO 如何因损失计算中的数学偏差无意中偏爱更长的回答；GRPO 可能有同样问题；
  • [7][10] 明确指出了 GRPO 的长度偏差和难度偏差，改进版 "Dr. GRPO" 通过去掉长度归一化和标准差归一化简化了 advantage 计算，给出更清晰的训练信号；
  • [1] 在 GRPO 里显式惩罚又长又错的回答，奖励简洁且正确的回答；
  • [3][6] 没直接控制 GRPO 的回答长度，但发现 token 级奖励有好处，让模型更聚焦关键推理步骤；
  • [5] 在 GRPO 里对超过特定长度的回答加显式惩罚，推理时可以精确控长度。
数学注解

👉 长度偏差的数学推导：为什么"按 token 平均"的损失会让长错误答案受罚更小；Dr. GRPO 去掉两项归一化后 advantage 长什么样。

除了 R1 论文里的 "AHA moment"，RL 还被证明能诱导出自我验证、反思式推理能力 [2][9]——有意思的是，和 AHA moment 一样，这些能力是训练中自然涌现的，没有显式教过。

[1] 表明把上下文拉长（到 128k tokens）能进一步提升模型的自我反思和自我纠正能力。

目前大部分工作集中在数学/代码推理，但 [4] 用逻辑谜题训练也成功了，而且在数学推理任务上泛化得很好——这是 RL 能诱导出不依赖特定领域知识的通用推理行为的证据。[11] 更进一步：推理能力能自然扩展到数学、代码、逻辑之外的结构化领域之外——医学、化学、心理学、经济学、教育，用生成式软打分处理自由作答也很有效。

推理模型值得做的下一步：

  • 把现有推理模型（o1、DeepSeek-R1）和外部工具调用、RAG 结合；刚发布的 o3 指明了方向；
  • [9] 表明给推理模型搜索能力会诱导出自我纠正等行为，在极小训练集下还能跨基准鲁棒泛化。考虑到 DeepSeek-R1 团队在"保住知识型任务性能"上花的功夫，给推理模型加搜索几乎是必然选项。

R1（和 R1-Zero）的基本主张是 RLVR 显式诱导出了推理能力。但最近的发现 [10] 表明，推理行为（包括 "Aha moment"）可能本来就在基座模型里——预训练吃过大量 CoT 数据。作者对比 DeepSeek V3 基座和 R1 也支持这个观察，[13] 更发现自反思、自纠正行为在预训练过程中随算力增长渐进涌现，横跨多个领域和模型尺寸。

也许结论是：RL 确实能把简单的基座模型变成推理模型，但它不是诱导/改进推理能力的唯一方式。蒸馏也能（本文语境下蒸馏 = 在 CoT 数据上做指令微调），而预训练和指令微调本来就是同一个 next-token 预测任务和损失函数——所以预训练数据里混入 CoT 数据，很可能同样诱导出这些能力。

arxiv.org/abs/2501.12599 —— 和 R1 同一天发布的多模态 LLM RL 训练工作。同样不用过程奖励模型（PRM，只评最终答案不评中间步骤的那种），用可验证奖励。关键想法：把上下文拉到 128k tokens 帮助模型规划、反思、自纠正；除正确性奖励外还有长度奖励——鼓励短而对的回答，长而错的回答罚得更重。还提出了 long2short，把长 CoT 能力蒸馏成高效的短 CoT 模型（模型合并、最短拒绝采样、DPO、第二轮更强长度惩罚的 RL）。

📄 2 月 3 日 · Competitive Programming with Large Reasoning Models

arxiv.org/abs/2502.06807 —— OpenAI 评估 o 系列（o1、o1-ioi、o3）在竞赛编程上的论文。技术细节不多，但有意思：模型用的是 outcome-based RL 而非 process-based 奖励模型（和 DeepSeek-R1、Kimi 同路）。o3 自己学会了测试时策略：比如先写个低效但正确的暴力版本，再用它验证优化版的输出——没人手写，全是模型自己悟的。论点是：扩展通用 RL 就能让模型自己发展出推理和验证方法，不需要人类启发式或领域特定的推理管线（早期的 o1-ioi 还靠手工设计的"采样几千个再聚类重排"等测试时策略）。

📄 2 月 10 日 · Exploring the Limit of Outcome Reward for Learning Mathematical Reasoning

arxiv.org/abs/2502.06781 —— 探索只用二元"对/错"反馈（像 R1 那样）的 RL 在数学上能走多远。先用 Best-of-N 采样收集正例做行为克隆（理论上足以优化策略）。为对付稀疏奖励（长 CoT 里部分步骤对、部分错），加了一个 token 级奖励模型，学着给推理的不同部分分配重要性权重，让模型聚焦最关键的步骤。

📄 2 月 20 日 · Logic-RL: Unleashing LLM Reasoning with Rule-Based Reinforcement Learning

arxiv.org/abs/2502.14768 —— R1 聚焦数学和代码，这篇用逻辑谜题训 7B 模型。沿用类似 R1 的规则 RL，但有几处调整：(1) 更严格的格式奖励，惩罚走捷径，强制用 <think>/<answer> 把思考和最终答案分开；(2) system prompt 显式要求先逐步思考再给答案。只用 5K 合成逻辑题，模型就发展出能泛化到 AIME、AMC 等更难数学基准的推理能力——逻辑 RL 教出的推理可以跨领域迁移。

📄 3 月 6 日 · L1: Controlling How Long A Reasoning Model Thinks With Reinforcement Learning

arxiv.org/abs/2503.04697 —— 推理模型默认越想越长，但用户没法显式控制长度。这篇提出 LCPO（Length Controlled Policy Optimization）：类似 GRPO 的 RL 方法（"GRPO + 自定义长度奖励"），让模型在保准确率的同时服从用户指定的长度约束：

reward = reward_correctness - α * |target_length - actual_length|

目标长度由用户 prompt 给出，这个公式鼓励模型精确命中目标长度。还有个 LCPO-Max 变体，不要求精确命中，只要求不超过最大 token 数：

reward = reward_correctness * clip(α * (target_length - actual_length) + δ, 0, 1)

作者用 LCPO 训了个 1.5B 的 L1 模型，能按 prompt 调整输出长度，让用户在准确率和算力之间权衡。有意思的是，这些长链模型在短推理上也出奇地好，同 token 长度下甚至超过 GPT-4o 这种大得多的模型。

数学注解

👉 LCPO 两个公式的完整推导：绝对值惩罚的最优点在哪、clip(α·Δ+δ, 0, 1) 的三段分段线性分析。

📄 3 月 10 日 · R1-Searcher: Incentivizing the Search Capability in LLMs via Reinforcement Learning

arxiv.org/abs/2503.05592 —— R1 这类 RL 训出的推理模型只靠内部知识。这篇教模型在推理过程中用外部搜索：两阶段 RL，先学搜索的格式，再学怎么用搜索结果找正确答案。

📄 3 月 18 日 · DAPO: An Open-Source LLM Reinforcement Learning System at Scale

arxiv.org/abs/2503.14476 —— 主要是开源 DeepSeek-R1 式训练管线，但也给 GRPO 提了几个有意思的改进：

  1. Clip-higher：提高 PPO 裁剪区间的上界，鼓励探索，防止训练中熵崩塌；
  2. 动态采样：过滤掉采样回答全对或全错的 prompt，提高训练效率；
  3. Token 级策略梯度损失：从样本级损失改到 token 级，让长回答对梯度更新有更大影响（标准 GRPO 先对每个样本的 token 取平均、再对样本取平均，样本权重相等，长回答里的 token 反而被稀释；而且长回答里常混在最终答案前的胡话，样本级损失罚不够）；
  4. 超长奖励塑形：对因太长被截断的回答加软惩罚，减少奖励噪声、稳定训练。
数学注解

👉 DAPO 两个改动的数学推导：token-level vs sample-level 损失的加权差异证明、clip-higher 非对称裁剪的几何意义。

📄 3 月 20 日 · Reinforcement Learning for Reasoning in Small LLMs: What Works and What Doesn't

arxiv.org/abs/2503.16219 —— R1 论文说小模型上蒸馏比纯 RL 好，这篇接着问：怎么用 RL 把小蒸馏模型再往上推。用 1.5B 的 DeepSeek-R1-Distill-Qwen，7000 个例子、42 美元算力，RL 微调带来显著提升，AIME24 上超过 o1-preview。三个有意思的发现：(1) 小 LLM 用紧凑高质量数据集，前 50–100 步推理能力提升飞快，但训太久会掉（长度限制 + 输出不稳定）；(2) 难易题混着训，早期回答更短更稳，但久了还是掉；(3) 余弦形奖励函数控长度更有效、训练更稳，但峰值性能比标准准确率奖励略低。

📄 3 月 25 日 · ReSearch: Learning to Reason with Search for LLMs via Reinforcement Learning

arxiv.org/abs/2503.19470 —— 把 R1 的 RL 方法扩展到"搜索结果作为推理过程的一部分"。模型在持续推理链上学何时、如何搜索，再用检索到的信息走下一步。全程端到端 RL，没有任何关于推理步骤的监督数据，反思错误查询、自我纠正等行为自然涌现，只用一个数据集训练就能跨多个基准泛化。

和 R1-Searcher 的区别：R1-Searcher 是两阶段、outcome-based RL（第一阶段教学会调用外部检索，第二阶段学用检索信息答题）；ReSearch 把搜索直接融进推理过程，端到端训练。

📄 3 月 26 日 · Understanding R1-Zero-Like Training: A Critical Perspective

arxiv.org/abs/2503.20783 —— 追问 R1-Zero 的纯 RL 为什么work。发现 Qwen2.5 这类基座模型不做 RL 也有很强的推理甚至 "Aha moment"——Aha 可能不是 RL 诱导的，而是预训练继承的。这篇还指出了 GRPO 的两个偏差：(1) 回答长度偏差：GRPO 用回答长度除 advantage，长错误答案受罚更小，模型于是学会生成又长又烂的答案；(2) 难度偏差：GRPO 按每道题的奖励标准差归一化，太简单/太难（奖励方差小）的题被过度加权。修复方案 Dr. GRPO：去掉 advantage 计算里的长度归一化和题目级标准差，训练更高效，错误时不再鼓励长回答。

数学注解

👉 GRPO 两个偏差的数学推导：除以长度为什么偏爱长错误答案、除以标准差为什么扭曲题目权重。

📄 3 月 31 日 · Crossing the Reward Bridge: Expanding RL with Verifiable Rewards Across Diverse Domains

arxiv.org/abs/2503.23829 —— R1 和跟随者都聚焦代码/数学这种易验证领域。这篇把方法扩展到医学、化学、心理学、经济学、教育等自由作答、难验证的领域。发现用专家写的参考答案做评估比预想中可行，引入了一种生成式软打分方法给奖励信号，不需要重度的领域标注。

📄 3 月 31 日 · Open-Reasoner-Zero: An Open Source Approach to Scaling Up Reinforcement Learning on the Base Model

arxiv.org/abs/2503.24290 —— 在基座模型上做推理 RL 的极简配置：用朴素 PPO而非 GRPO，还跳过 RLHF 管线里常用的 KL 正则。结果这个简单配置（朴素 PPO + 基于答案正确性的二元奖励）足以让模型的推理性能和回答长度同步扩展；用和 R1-Zero 同样的 Qwen-32B 基座，多项推理基准上超过 R1-Zero，只用了 1/10 的训练步数。

📄 4 月 5 日 · Rethinking Reflection in Pre-Training

arxiv.org/abs/2504.04022 —— R1 让我们觉得推理能力从 RL 里涌现，这篇来了个反转：自纠正在预训练里早就出现了。方法是在任务里故意掺入有缺陷的思维链，测模型能不能发现并纠正。发现显式和隐式的反思都随预训练稳定涌现，横跨多领域、多模型尺寸，连相对早期的 checkpoint 都有自纠正迹象，且随预训练算力增强而变强。

📄 4 月 7 日 · Concise Reasoning via Reinforcement Learning

arxiv.org/abs/2504.05185 —— 推理模型爱生成长回答，抬高推理成本。这篇证明这个行为来自 RL 训练过程本身，而非"长答案更准"的真实需求：当模型拿到负奖励时，PPO 损失的数学结构会让回答越长、平均到每个 token 的损失越小。模型于是"学会"了：答错时把回答写长一点，惩罚就被稀释了——即使多出来的 token 对解题毫无帮助。这或许解释了纯 RL 训出的 "aha moment" 和长 CoT 从哪来。（注：这个分析针对 PPO，作者声明暂不适用于 GRPO。）另外，第二轮 RL（只用少量"有时能解出来"的题）可以在保住甚至提升准确率的同时把回答缩短，对部署效率意义重大。

👉 长度偏差的严格推导：负奖励下 per-token 损失如何被长度稀释，一步步算给你看。

📄 4 月 9 日 · A Sober Look at Progress in Language Model Reasoning: Pitfalls and Paths to Reproducibility

arxiv.org/abs/2504.07086 —— 给"RL 能改进蒸馏小模型"的说法泼冷水。AIME24 这种小基准极不稳定：换个随机种子分数能差几个百分点。在更受控、标准化的评估下，RL 的提升比报道的小得多，经常不统计显著；有些 RL 模型确实有温和提升，但通常弱于有监督微调，且泛化到新基准时不太行。结论：RL 也许在某些情况下有帮助，但好处被夸大了，需要更好的评估标准才能看清什么真有用。
