6.8 序列 logprob 与 6.9 策略梯度损失：完整数学推导

这一页把原文 page-58 / page-59 的数学部分完整展开。目标是让你能自己重推出原文给出的每一个数字，而不只是看懂结论。 覆盖三块：序列 logprob 从哪来、为什么用 sum 而不是 mean、advantage 怎么把奖励变成学习信号。

原文在这一节只给了公式和代码，数学推导被压缩成了几句话。下面每一步都补上中间的推理。

符号约定

先把后文反复用到的符号一次性定好，后面不再重复解释。

符号含义
\(x\)输入 prompt 的 token 序列，长度 \(P\)（prompt length）
\(y_t\)生成回答中的第 \(t\) 个 token，\(t = 1, \dots, T_i\)
\(y_{<t}\)已生成的全部 token，即 \((y_1, \dots, y_{t-1})\)。注意不包括 prompt，但条件里始终含 \(x\)
\(T_i\)第 \(i\) 个回答的 token 数。各 rollout 长度不同，这是后面 mean / sum 之争的关键
\(W\)（或 \(\theta\)）模型参数。原文用 \(W\)，公式里我沿用 \(\theta\)，两者同一个东西
\(N\)rollout 数量，代码里的 num_rollouts
\(r_i\)第 \(i\) 个 rollout 的 reward，由第 3 章的验证器给出 0 或 1
\(A_i\)第 \(i\) 个 rollout 的 advantage，整条序列一个标量
最容易混淆的一点：\(y_{<t}\) 指的是「同一个回答内部已生成的 token」，不包含 prompt；而条件概率里 \(x\) 是始终在场的。写成 \(P(y_t \mid y_{<t}, x, \theta)\) 而不是 \(P(y_t \mid x_{<t}, y_{<t})\)，就是为了体现 prompt 是固定的上下文。

一、logprob 从哪来：链式法则

1.1 联合概率 = 条件概率连乘

给定 prompt \(x\) 和参数 \(\theta\)，模型生成 \(y_1, y_2, \dots, y_T\) 这个特定序列的概率，根据概率链式法则：

\[ \begin{aligned} P(y_1, \dots, y_T \mid x, \theta) &= \underbrace{P(y_1 \mid x, \theta)}_{t=1} \cdot \underbrace{P(y_2 \mid y_1, x, \theta)}_{t=2} \cdot \cdots \\[4pt] &\quad \cdot \underbrace{P(y_T \mid y_{<T}, x, \theta)}_{t=T} \end{aligned} \]

注意最后一项的下标是 \(y_{<T}\)，而第一项 \(y_0\) 是空集，所以 \(P(y_1 \mid x, \theta)\) 里的条件里没有 \(y\)。这个结构就是「自回归」的数学含义：第 \(t\) 个 token 的条件分布，依赖前 \(t-1\) 个已确定的 token。

1.2 为什么必须取对数

上面这个连乘在数值上是不可用的。考虑一个 265 token 的回答（后面 2.1 节我们会看到，真实例子正好是这个数）。即使每个 token 的概率都相当高，比如 0.9：

\[ 0.9^{265} \approx 10^{-12.3} \]

如果再长一点，概率就落到 float64 能表示的范围之外了（float64 最小正规数约 \(10^{-308}\)），再往后会直接下溢成 0。下溢之后你无法区分「几乎不可能」和「真的不可能」，梯度信息彻底丢失。

解法是取对数。对数有个恒等式：

\[ \log(ab) = \log a + \log b \]

于是连乘直接变成连加。两边取对数：

\[ \boxed{\; \log P(y_1, \dots, y_T \mid x, \theta) = \sum_{t=1}^{T} \log P(y_t \mid y_{<t}, x, \theta) \;} \]
关键

这是恒等式，不是近似。它同时解决两件事：数值稳定（加法不会下溢），以及可微（\(\log\) 的导数是 \(1/x\)，非常干净——这正是最大似然估计和交叉熵里必然出现 \(\log\) 的根本原因）。

右边是一个标量，不是一串数。这就是「序列 logprob」的准确含义：整个生成序列的联合概率的对数。

1.3 每一项具体怎么算

单 token 的条件概率来自你已经在 GPT-2 那本书里写过的部分，只是换了个说法。模型前向传播最后一步输出层得到一个长度等于词表大小的向量 \(\text{logits}_t \in \mathbb{R}^{|V|}\)，然后 softmax：

\[ P(y_t \mid y_{<t}, x, \theta) = \text{softmax}(\text{logits}_t)_{y_t} = \frac{\exp(\text{logits}_t[y_t])}{\sum_{v \in V} \exp(\text{logits}_t[v])} \]

其中求和遍历整个词表。本书 Qwen3 0.6B 的词表大小是 151,936。PyTorch 里对应 torch.log_softmax(logits, dim=-1)，它直接返回对数概率，内部用数值稳定技巧实现，没有真的先算 exp 再取 log。

注意

这里 \(y_t\) 是一个已经确定的实际 token，不是采样出的候选。模型已经生成完了 \(y_1 \dots y_T\)，现在回头问「当初这一步模型有多确信」。这个量衡量的就是模型对自己已经做出的选择有多意外。

推论：\(\text{logits}_t[y_t]\) 只是取一个分量，不是取最大值。所以代码里必须用 gather 按索引取值，不能用 argmax——argmax 问的是「当时最想说什么」，gather 问的是「当时实际说了什么」。

二、代码里的那个 \(-1\)

这是原文最容易卡住的地方。它来自一个结构性事实：因果掩码（causal mask）。

2.1 错位一格

自回归模型的第 \(i\) 个位置只能看到 \(0 \dots i\) 的输入（靠下三角 mask 实现）。所以输出层的第 \(i\) 行预测的是位置 \(i+1\) 的 token：

\[ \text{logits}[i] = \text{「位置 } i+1 \text{ 的 token 在位置 } 0 \dots i \text{ 条件下的分布」} \]

设 token_ids 长度为 \(L = P + T\)。那么「位置 \(i\) 的实际 logprob」这个量要从第 \(i-1\) 行取：

\[ \text{actual\_logp}[i] \;=\; \text{logprobs}\big[i-1,\; \text{token\_ids}[i]\big] \]

把索引从 0 开始数，就是：预测行 \(0 \dots L-2\) 配对实际 token 位置 \(1 \dots L-1\)。对应原文 listing 6.11 的 gather 写法：

def sequence_logprob(model, token_ids, prompt_len):
    logits = model(token_ids.unsqueeze(0)).squeeze(0).float()
    logprobs = torch.log_softmax(logits, dim=-1)   # 形状 [L, |V|]

    selected = logprobs[:-1].gather(1, token_ids[1:].unsqueeze(-1)).squeeze(-1)
    return torch.sum(selected[prompt_len -1:])
代码片段对应数学作用
logprobs[:-1]取行 \(0 \dots L-2\)最后一行没有「下一个 token」，丢弃
.gather(1, token_ids[1:])\(\text{logprobs}[i-1,\, \text{token\_ids}[i]]\)错位配对：从每行 151,936 个值里挑出实际生成的那个 token 的标量值
.squeeze(-1)—压掉 gather 产生的 singleton 维度
selected[prompt_len-1:]下标 \(P-1 \dots L-2\)只取生成部分，排除 prompt
torch.sum(...)\(\sum_{t=1}^{T} \log P(y_t \mid y_{<t}, x, \theta)\)1.2 节的求和

2.2 为什么是 prompt_len - 1 不是 prompt_len

这是最容易写错的一处。上面已经确立：selected[i] 对应位置 \(i+1\) 的 token。生成部分从位置 \(P\) 开始（token_ids[P] 是第一个生成 token），所以要的是位置 \(P, P+1, \dots, L-1\)，对应 selected 的下标：

\[ P-1,\; P,\; \dots,\; L-2 \]

也就是切片 selected[prompt_len - 1:]，长度正好 \(T\)。写成 [prompt_len:] 会把 prompt 的最后一个 token 算进生成部分，同时漏掉第一个生成 token。

原文 listing 6.9 用的是更显式的写法：

start = len(prompt_ids) -1      # = P - 1
end   = full_ids.shape[0] -1   # = L - 1
t_idx       = torch.arange(start, end)        # P-1 … L-2
next_tokens = full_ids[start+1: end+1]  # P … L-1
next_token_logps = logprobs[t_idx, next_tokens]

两者数学上完全等价，作者说 listing 6.11 是「同样结果的更紧凑、更快版本」。

2.3 验证一下数字

原文给了实测：平均 logprob = -0.061279，序列 logprob = -16.239，并说两者关系是 avg × token 数。反推：

\[ \frac{16.239}{0.061279} \approx 265 \]

所以答案有 265 个 token，对得上。

别被这个数字误导

平均每个 token 的对数概率是 \(-0.06\)，换算成实际概率是 \(\exp(-0.06) \approx 0.94\)。也就是说模型对这个回答极度确信，几乎每一步都是训练时见过的高频模式。

但这是 base 模型，输出往往是模板化重复的，所以平均 logprob 会高到离谱。高 logprob 不代表答对，只代表「像训练数据」。这正是第 5 章结尾那个反直觉结论的根源——logprob 会偏爱流畅的错误答案。Table 6.1 里 logprob 只能当辅助信号，verifier 永远是第 3 章那个数学等价判定。

三、mean 还是 sum：全章最重要的一个选择

torch.mean(next_token_logps) 和 torch.sum(next_token_logps)，一个字符的差别，但对应两个完全不同的问题。第 5 章用 mean，第 6 章 GRPO 用 sum，原因值得讲清楚。

3.1 mean 是长度归一化，为了「可比」

\[ \text{avg} = \frac{1}{T}\sum_{t=1}^{T} \log P(y_t \mid y_{<t}, x, \theta) = \frac{1}{T}\log P(y_{1:T} \mid x, \theta) \]

除以 \(T\) 得到「每 token 的平均惊讶程度」。用途是跨序列比较。看一个具体例子：

回答token 数每步平均 logprobsummean
答案 A5−0.1−0.5−0.1
答案 B500−0.1−50−0.1

用 sum 判定，答案 B 会被评为「糟糕 100 倍」。但事实上它每一步都和 A 一样好，只是写长了。mean 消除了长度影响，所以可以拿来打分、排序、选优——这正是第 5 章用它当 confidence scorer 的原因（listing 5.8 的 avg_logprob_answer）。

3.2 sum 是真实联合概率，为了「求导」

GRPO 里不用 mean，结构上的原因是：GRPO 给每个 rollout 一个 reward、一个 advantage、一个标量 logprob。三个都是标量，长度归一化在这里会破坏配对关系。

看 1.1 节的公式就清楚了。对单个回答求导：

\[ \frac{\partial}{\partial \theta} \log P(y_{1:T} \mid x, \theta) = \sum_{t=1}^{T} \frac{\partial}{\partial \theta} \log P(y_t \mid y_{<t}, x, \theta) \]

这是可加的——每个 token 各贡献一份梯度，\(T\) 越长总梯度越大。GRPO 的 loss 形式是 \(\mathcal{L} \propto A_i \cdot \log\pi_\theta(y^{(i)})\)，代入：

\[ \frac{\partial \mathcal{L}}{\partial \theta} = A_i \sum_{t=1}^{T_i} \frac{\partial}{\partial \theta}\log P(y_t \mid y_{<t}, x, \theta) \]
选择梯度量级后果
sum\(\propto T_i\)长回答对参数更新影响更大。有偏，但忠实反映「这个完整序列的联合概率有多小」
mean\(\propto T_i \cdot \frac{1}{T_i} = 1\)，每个 token 权重一样丢失了「整个序列多不可能」的信息，把长推理和短推理当等价看待

原文的解释是：用 mean 会「unintentionally rescale the learning signal in policy optimization and cause longer and shorter responses to contribute unevenly to the update」，而且「that kind of length-based rescaling is not part of the original GRPO formulation」。

一句话

mean 问的是「这条回答平均每一步像不像训练数据」，适合打分。sum 问的是「模型整体上有多可能生成这条回答」，适合求导。GRPO 需要的是后者。

3.3 推论：长度偏置，以及它如何解释 Ch7 的 reward hacking

你可能会想：既然 sum 让长答案梯度更大，模型会不会学会疯狂写长？原文给了一个很清醒的分析。

序列 logprob 随 \(T_i\) 线性缩放，所以更长的回答得到更负的 logprob。对两个同样好的答案（\(A_i > 0\) 相同），优化 \(A_i \sum_t \log \pi_t\) 时，长序列的 logprob 天生更小，需要更大的参数变动才能改善，而改善空间的绝对值也更小。原文的措辞：

For two equally good answers, the optimization implicitly favors the shorter one, since it is cheaper in terms of likelihood. Summed logprobs therefore encourage the model to stop earlier unless producing a longer response is justified by a higher reward.

也就是：等 reward 下，模型倾向更早停止。这就是为什么原文说序列 logprob「consistent with their role in GRPO when rewards and advantages are applied at the sequence level」。

这一条能解释 Ch7.6 的失败

第 7.6 节的 format reward 实验里，作者观察到 reward_avg 一直很高但 eval_acc 掉，figure 7.19 显示这和 avg_response_len 缩短相关。作者的诊断是模型「过度专注于拿格式分」。

结合本章的推导可以看到两个力量在合谋：格式奖励让模型学会「套 tag 就拿分」，而序列 logprob 的长度效应让它倾向于套完 tag 就早点收工。思考被压缩，答案质量下降——这是 reward hacking，而根因之一是序列级 logprob 的长度偏置。

3.4 四个 rollout 的实测

原文 listing 6.12 算了四个回答的序列 logprob：

回答reward序列 logprob观察
\boxed{83}1−7.92最短 → 最高（最不负）
The final answer is 830−16.61—
The correct answer is \boxed{83}1−20.15—

两个观察，作者都点出来了：

  1. 短 = 高（较不负）。\(\boxed{83}\) 只有几个 token，在 4 个回答里最「便宜」。这就是 3.3 的长度效应。
  2. 唯一答错的那个分数最低。这个 base 模型在 4 次里对 3 次，答错那次的 logprob 也最低——「意外」和「错」正相关。因为训练数据里正确的解法是被大量重复的模式，错误数字则罕见。

四、Advantage：为什么必须做组内归一化

4.1 公式与验算

\[ A_i = \frac{r_i - \mu_r}{\sigma_r + \epsilon}, \qquad \mu_r = \frac{1}{N}\sum_{j=1}^{N} r_j \] 
advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-4)

取原文的 r = [1., 1., 0., 0.] 手算：

\[ \mu_r = \frac{1+1+0+0}{4} = 0.5 \] \[ \sigma_r = \sqrt{\frac{(1-0.5)^2+(1-0.5)^2+(0-0.5)^2+(0-0.5)^2}{4-1}} = \sqrt{\frac{1.0}{3}} \approx 0.5774 \]

（分母是 \(n-1\)，因为 PyTorch 的 torch.std 默认取无偏估计）

\[ A_i = \frac{1-0.5}{0.5774} \approx 0.866, \qquad \frac{0-0.5}{0.5774} \approx -0.866 \]

对上原文输出的 [0.8659, 0.8659, -0.8659, -0.8659]。✓

4.2 为什么不是直接用 reward 当权重

这是最值得想清楚的一步。两个理由：

理由一：绝对奖励没有意义，排序才有意义

策略梯度定理的形式是：

\[ \nabla_\theta J(\theta) = \mathbb{E}_{y \sim \pi_\theta(\cdot|x)}\Big[\nabla_\theta \log \pi_\theta(y|x) \cdot A(x,y)\Big] \]

其中 advantage 其实是 \(A = Q - V\)：把「绝对好坏」减去「这个状态下平均能拿多少」。减掉 baseline \(V\) 的目的是让梯度只反映「比预期好多少」，而不是在所有状态上无差别地往好的方向推。

跨 prompt 而言 reward 的绝对值不可比：一道题 4 个 rollout 全对（\(r=[1,1,1,1]\)）和另一道题的全错，reward 都是常数 1 或 0，但难度天差地别。

GRPO 的核心简化

GRPO 把 baseline 换成「同一组 rollout 的平均 reward」。这是一个 Monte Carlo 估计的 baseline——不需要训练一个额外的 critic 网络（value network）来拟合 \(V\)，直接用同批其他样本的均值当基线。

这就是 GRPO 相对 PPO 最大的工程优势：不需要 critic，显存和训练复杂度大幅下降。原文特别加了 Note 强调：the "GR" (group relative) refers to the fact that GRPO generates multiple answers per prompt and compares them relative to each other。

理由二：不中心化会让模型整体漂移

假设 \(r = [1,1,1,1]\)，全为正。那么 \(\max \log \pi\) 等价于无条件提高这批序列的概率，不管它们到底好不好。碰上全错的组（\(r=[0,0,0,0]\)），损失又变成无条件压低。净效果是模型在两个极端之间来回震荡，学不到方向性。

减掉均值后 \(A\) 之和为 0（中心化），梯度就纯粹表达「哪边该升、哪边该降」的相对关系。原文验证了这一点（第 7.3.1 节）：adv_avg 恒为 0.0000，作者说「this metric mainly serves as a sanity check that the implementation behaves as expected」。

4.3 除以标准差再加一层

让不同难度题目的信号强度一致。看一个对比：

reward 向量难度原始 \(A_i\)（未标准化）标准化后 \(A_i\)
\([0, 0, 0, 1]\)难（只有 1 个对）\([-0.25, -0.25, -0.25, 0.75]\)\([-0.5, -0.5, -0.5, +1.5]\)
\([0, 0, 1, 1]\)较易（2 个对）\([-0.5, -0.5, 0.5, 0.5]\)\([-0.866, -0.866, +0.866, +0.866]\)

除以标准差后，两组 \(A\) 的标准差都回到约 1（这正是标准化的定义），学习信号强度与题目难度解耦。注意分量不必相同——难例里唯一答对的那个会拿到更大的正优势（\(+1.5\) vs \(+0.866\)），但整体尺度已被拉齐。这解释了为什么第 7 章要监控 adv_std：

adv_std 范围含义
接近 1信号尺度良好，通常训练稳定
非常小学习信号消失，常伴随 reward collapse（组内全对或全错）
非常大更新过于尖锐，可能破坏训练稳定性

4.4 零 advantage：全对或全错

如果 \(r = [0, 0]\)（原文 listing 6.15 的实际输出就是 'rewards': [0.0, 0.0]）：

\[ A_i = \frac{0 - 0}{0 + \epsilon} = 0 \quad\Longrightarrow\quad \mathcal{L} = 0 \quad\Longrightarrow\quad \nabla_\theta = 0 \]

原文：if we were training the model, the gradient would be zero and the model parameters would not be updated.

这是 desirable 的

这组 rollout 里没有可学的信息：4 个全对说明模型已会做这题，4 个全错说明模型完全不知道往哪走。两种情况下梯度为 0 是正确行为——不在无信息的数据上浪费算力，也不引入噪声。

但它同时是 GRPO 数据效率的主要瓶颈：真实训练中大量 prompt 会落入这个区间。这正是 DAPO 的两条改进针对的——过滤零梯度样本、active sampling（超采样那些「有对有错」的组）。

顺带一提 listing 6.15 的细节：两个 rollout 的 gen_len 分别是 4 和 256。前者 4 个 token 就吐了 <|endoftext|>，后者跑满了 256 上限。这正是 DAPO 那条「filter out 退化的 rollout」要处理的情况。

五、策略梯度损失：把信号接回参数

5.1 公式的嵌套结构

\[ \mathcal{L}_{\text{pg}} = -\frac{1}{N}\sum_{i=1}^{N} A_i \left[\sum_{t=1}^{T_i} \log \pi_\theta\big(y_t^{(i)} \mid y_{<t}^{(i)}, x^{(i)}\big)\right] \]
注意这个公式的两层结构，各司其职：
内层 \(\sum_{t=1}^{T_i}\) = 序列 logprob（6.8 节算的，对单个回答内部求和，各 \(T_i\) 不同）
外层 \(\frac{1}{N}\sum_i\) = 跨 rollout 平均（对不同的回答平均，\(N\) 相同） 
logps   = torch.stack(rollout_logps)                    # 形状 [N]
pg_loss = -(advantages.detach() * logps).mean()      # 标量

5.2 三个细节

负号：最大化转最小化

PyTorch 优化器只会最小化 loss，而 RL 想要最大化：

\[ \max_\theta \frac{1}{N}\sum_{i=1}^{N} A_i \log \pi_\theta(y^{(i)} \mid x^{(i)}) \]

而 \(\max f \iff \min(-f)\)，且是严格等价：\(\nabla(-f) = -\nabla f\)，优化器往负梯度方向走，就等价于往 \(\nabla f\) 方向走。参数更新完全相同。

.detach()：切断梯度

advantage 来自 reward，reward 是 0/1 的常数（答对就是 1，答错就是 0），数值上是常量，不该有梯度。detach() 把这个节点从计算图摘出来。

如果不 detach，反向传播会试图穿过 advantage 计算回传到 reward，而 reward 又来自生成过程——那等于在「通过修改模型参数来改变奖励」，是在优化 verifier，不是在优化策略。

原文的措辞：they are treated as fixed learning signals during the policy update. 记住这个原则：advantage 是给定的学习信号，不是需要优化的东西。

5.3 手算验证

用 3.4 节的实测数据：

\[ \begin{aligned} \text{logps} &= [-7.9243,\ -20.1546,\ -16.6130,\ -23.3677] \\ A &= [0.8659,\ 0.8659,\ -0.8659,\ -0.8659] \end{aligned} \] \[ \begin{aligned} \mathcal{L}_{\text{pg}} &= -\frac{1}{4}\Big[(-7.9243)(0.8659) + (-20.1546)(0.8659) \\ &\qquad\qquad\quad + (-16.6130)(-0.8659) + (-23.3677)(-0.8659)\Big] \\[4pt] &= -\frac{1}{4}\big[-6.862 - 17.452 + 14.386 + 20.233\big] \\[4pt] &= -\frac{10.305}{4} \approx \mathbf{-2.576} \end{aligned} \]

对上原文的 tensor(-2.5764)。✓

5.4 逐项读懂这个 \(-2.576\)

它不是 0，说明当前策略还没达到这组的最优状态。看每一项的符号：

rollout\(A_i\)\(\log \pi\)乘积梯度的作用
\boxed{83}+0.87−7.92−6.86✅ 正确 → 推高其概率
The correct answer is \boxed{83}+0.87−20.15−17.45✅ 正确 → 强烈推高
The final answer is 83−0.87−16.61+14.39❌ 错误 → 压低其概率
We get \boxed{38}−0.87−23.37+20.23❌ 错误 → 更强地压低

机制一句话：\(A > 0\) 的项在 \(\mathcal{L}\) 里是负数，最小化 \(\mathcal{L}\) 就是把它们往更负推，即最大化 \(\log\pi\)，即提高这批正确回答的概率。\(A < 0\) 的项贡献正数，最小化会压低它。

再看第二行：\(-17.45\) 的绝对值比第一行的 \(-6.86\) 大得多。一个又长又正确的回答，拿到的梯度权重远大于一个短而正确的回答。这正是 3.2 和 3.3 讨论的序列级 logprob 效应。

由此理解 DAPO 的 token-level loss：它要把外层平均里的 \(1/N\) 重新分配回每个 token，让长回答不再获得不成比例的权重。理解了这一点，你就知道它为什么要改、往哪改。

六、完整版 GRPO（Ch7 补上的两项）

上面是最简版本，pg_loss 就是总 loss。真实的 GRPO 还要加裁剪和 KL：

\[ \mathcal{L} = \underbrace{-\frac{1}{N}\sum_{i=1}^{N} \min\Big(\rho_i A_i,\; \mathrm{clip}(\rho_i,\, 1-\epsilon,\, 1+\epsilon)\, A_i\Big)}_{\text{clipped policy ratio}} + \beta \underbrace{\hat{D}_{\text{KL}}\big(\pi_\theta \,\|\, \pi_{\text{ref}}\big)}_{\text{KL 正则}} \] \[ \text{其中}\quad \rho_i = \frac{\pi_\theta(y^{(i)} \mid x^{(i)})}{\pi_{\theta_{\text{old}}}(y^{(i)} \mid x^{(i)})} = \exp\big(\log\pi_\theta - \log\pi_{\theta_\text{old}}\big) \]

这里有个本章埋下的关键点：6.9 算 logprob 时用的是 model.eval() 的同一个模型，没有第二个副本。而 \(\rho_i\) 的分母需要「采样时的策略」\(\pi_{\theta_\text{old}}\)。Ch7 用 inner_epochs 控制这件事：

为什么 Ch7.2 的 loss 恒为 0

只做 1 次内层更新（--inner_epochs 1）时，模型还没变，\(\rho_i \equiv 1\)，裁剪项恒等于 1。而因为 advantage 均值为 0、且只有一个优势项，标量 policy loss 就等于 0。

原文的解释：loss = 0 is a computational artifact caused by the default settings. It mainly reflects that the run uses a single inner epoch and no KL term, which makes the logged scalar loss uninformative. 修复命令是 --kl_coeff 0.001 --inner_epochs 2。
