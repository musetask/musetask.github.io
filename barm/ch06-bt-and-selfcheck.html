0. 预备知识（只有这一节需要先看）

0.1 「概率模型」是什么意思

一个概率模型就是一个函数，输入是「情况」，输出是「这件事发生的可能性」，取值在 0 到 1 之间。

在 RLHF 里，输入是「两个候选回答 + 谁更好」，输出是「\(y_w\) 赢的概率」。这就是一个概率模型。BT 就是把这个函数的具体形式定下来。

0.2 为什么几乎所有东西最后都要「取对数」

因为概率会连乘，而连乘会崩。两个原因：

原因说明
数值会下溢float64 能表示的最小正规数约 \(10^{-308}\)。一条 300 token的回答，即使每步概率高达 0.9，整体概率也是 \(0.9^{300} \approx 10^{-13.7}\)。再长一点就直接变成 0，之后你无法区分「几乎不可能」和「真的不可能」，梯度信息彻底丢失
连乘变连加\(\log(ab) = \log a + \log b\)。乘积的和不好算，加法的和好算

这也是第 6 章里从链式法则一路推到 \(\log\pi\) 的原因——不是为了「数学上更优雅」，是因为不取对数就算不出来。

0.3 sigmoid 和 logit

这两个函数互为反函数，你会反复见到它们成对出现：

\[p = \sigma(z) = \frac{1}{1 + e^{-z}} \qquad\Longleftrightarrow\qquad z = \operatorname{logit}(p) = \ln\frac{p}{1-p}\]

直觉理解：

  • \(\sigma\) 把任意实数压到 (0, 1)，所以它天生适合当概率。
  • \(\operatorname{logit}\) 把概率「拉回」实数轴，是逆变换。
一个高频困惑：为什么不能用 softmax 直接当概率？——因为 softmax 需要一组 logit（一个向量）才能算出归一化的分布，而 sigmoid 只吃一个标量。两者关系：把 sigmoid 写成 \(\frac{e^z}{e^z + 1} = \frac{e^z}{e^z + e^0}\)，就看出它就是只有两个 logit（\(z\) 和 0）的 softmax。这个观察在 1.4 节会用到。

0.4 「似然」和「极大似然」

这是本书里唯一一处严格意义上的统计推断，值得单独说清：

  1. 你有一批观测数据，比如 66,000 对「谁更好」的标注。
  2. 你有一个带参数的模型，参数是 \(\phi\)（奖励模型的权重）。
  3. 你问：哪个 \(\phi\) 让这批数据「最可能出现」？

「让数据最可能出现」的那个参数，就叫极大似然估计（MLE）。做法是：

  • 第一步：算整批数据的联合概率。数据之间假设独立，就等于把每条的概率连乘。
  • 第二步：取对数（把连乘变连加）。
  • 第三步：最小化这个对数（即最小化负对数似然 NLL）。

所以「损失 = 负对数似然」在 RLHF 里长这样：

\[\mathcal{L}_{\text{RM}}(\phi) = -\,\mathbb{E}_{(x,y_w,y_l)\sim D}\Big[\log \underbrace{P(y_w \succ y_l \mid x)}_{\text{这条数据出现的概率}}\Big]\]

注意期望里面只有一条数据：\(E\) 的意思是对数据集中的每一条都算一次，然后平均。

第一部分 · Bradley–Terry 公式

1.1 要解决的问题：从「排序」到「可微的数」

第一步：看清我们手上有什么

RLHF 的第一步是训一个奖励模型。但标注员手里只有排序，没有分数。

Prompt标注员的判断
“我要买一台编程和日常用的笔记本，该考虑什么？”Response B 比 Response A 好

具体一点说，标注员看到的是（排名从好到差）：

Response B  >  Response A

第二步：看清我们缺什么

而 RLHF 后面要用的，是策略梯度。它的形式是（先不管符号，第六章会讲）：

\[\nabla_\theta J(\theta) = \mathbb{E}\Big[\nabla_\theta \log \pi_\theta(y|x) \;\cdot\; \underbrace{\text{某个标量}}_{\text{reward}}\Big]\]

这个标量必须满足三个条件：

  1. 可微——不然回传不了梯度。
  2. 连续——不然梯度是 0 或者跳变，优化器走不动。
  3. 能区分好坏——至少要告诉我们 A 比 B 差，好让模型知道该往哪调。

排序不是数。所以中间缺了一次翻译：把「谁更好」变成「有多好」。

为什么不能直接拿排名当权重

一个很自然但错误的念头：「B 排第 1，A 排第 2，那就用 2 和 1 当分数？」这样做有三个致命问题：

问题说明
不同 prompt 之间不可比prompt 甲的「第 2 名」和 prompt 乙的「第 2 名」难度完全不同。标 2 和标 1 抹平了这个差异，而模型需要知道「这道题整体很难」
名次不是「好多少」「第 1 名比第 2 名好 2 倍」和「第 1 名比第 2 名只好 0.001」在名次上完全一样，但后者模型几乎不用改，前者需要大力调整
没法推广到新样本模型生成的新回答没有排名——它从来没被人排过。而训练时必须能给新样本打分

所以我们需要的是一个函数：给它任意一个回答（包括没见过的），它能吐出一个数，而且这个数在不同回答之间可比。

第三步：三条建模要求

这个函数不能随便定，否则训练不出东西。它必须满足：

  1. 单调：\(r\) 大的应该更可能赢。
  2. 无交互：\(a\) 赢 \(b\) 的概率只由 \(r_a - r_b\) 决定，与「在场还有谁」无关。否则每次比较都要重新算一个模型，谈不上复用。
  3. 跨比较一致：如果 \(a\) 稳定赢 \(b\)、\(b\) 稳定赢 \(c\)，那 \(a\) 应该稳定赢 \(c\)，而且这个关系必须由概率运算自动搭出来，不能人工规定。
一句话

BT 模型就是满足这三条要求的概率模型里唯一的一个（连续情形）。它必然长成 sigmoid 的样子——这不是「我们选了 sigmoid」，是推出来的。

1.2 两条假设

假设 1：无交互

存在一个标量 \(r_i\)（叫强度、rating、分数都行），使得

\[P(y_i \succ y_j) = F(r_i - r_j)\]

请注意这个式子的形状——只有差。\(r_i\) 本身是多少完全不重要，重要的是两个数之间的距离。

「无交互」这个名字有点误导。更准确的说法是：不存在「对手强度」这类额外的修正项。围棋里叫「段位」的东西，就是这种修正项；BT 明确假设不存在。

假设 2：乘法一致性

比较可以搭接。数学上写成：

\[P(y_a \succ y_c) \;=\; \frac{P(y_a\succ y_b)\,P(y_b\succ y_c)}{P(y_a\succ y_b)\,P(y_b\succ y_c) + P(y_b\succ y_a)\,P(y_c\succ y_b)}\]

这个式子的形状值得停一下。分子是「\(a\) 赢 \(b\)」且「\(b\) 赢 \(c\)」的联合概率；分母补上「两条都输」的情况。它等价于一句更直白的话：

假设 2 的白话版

log-odds 是相加的。「\(a\) 比 \(b\) 强多少」加上「\(b\) 比 \(c\) 强多少」，就是「\(a\) 比 \(c\) 强多少」。

为什么这个假设是 BT 的全部威力所在？因为它说的是：标注员在不同题目之间表现是一致的——他在 A/B/C 上的口味可以互相推断。如果这个假设不成立（比如有的标注员偏爱长答案、有的偏爱短答案），奖励模型就学不出东西来。

这也是下面 1.10 节那两个偏置必须显式控的根本原因：那两个偏置恰恰是假设 2 被破坏的最常见形式。

1.3 求解 F

现在开始推。目标：从假设 1 和假设 2 出发，把 \(F\) 的形状定死。

第 1 步：把 \(F\) 参数化成一个更简单的函数 \(G\)

假设 1 说 \(F\) 依赖差 \(d\)。第一步要处理一个技术问题：\(F\) 是概率，值域在 (0,1)，不好做乘法。所以先变形。

任何满足 \(F(d) + F(-d) = 1\) 的函数都能写成：

\[F(d) = \frac{G(d)}{1 + G(d)}, \qquad G(0) = 1\]

这个变形不损失一般性。想验证的话，反着解就行：令 \(G(d) = F(d)/(1 - F(d))\) 代回去，一定还原。

由 \(F\) 单调可知 \(G\) 也单调。所以 \(G\) 把实数轴单调映射到正实数轴。

这个变形的直觉：「赢的概率」除以「输的概率」，就是 \(G\)。也就是赔率（odds）。这是一个在所有对数线性模型里反复出现的标准技巧——把有界的概率搬到无界的实数轴上，才能做加法。

第 2 步：代入假设 2

把 \(F = G/(1+G)\) 塞进假设 2。四项分别是：

项代入后
\(P(y_a\succ y_b)\)\(\dfrac{G(d_1)}{1 + G(d_1)}\)
\(P(y_b\succ y_c)\)\(\dfrac{G(d_2)}{1 + G(d_2)}\)
\(P(y_b\succ y_a)\)\(\dfrac{G(-d_1)}{1 + G(-d_1)}\)
\(P(y_c\succ y_b)\)\(\dfrac{G(-d_2)}{1 + G(-d_2)}\)

其中 \(d_1 = r_a - r_b\)，\(d_2 = r_b - r_c\)，所以 \(d_1 + d_2 = r_a - r_c\)。

代入后，分子是 \(\dfrac{G(d_1)G(d_2)}{(1+G(d_1))(1+G(d_2))}\)，分母的对应项是 \(\dfrac{G(-d_1)G(-d_2)}{(1+G(d_1))(1+G(d_2))}\)。

关键一步

两边都有 \((1+G(d_1))(1+G(d_2))\) 这个因子，上下直接约掉。这是整个推导里最省事的一步，很多人卡在这里是因为没意识到分母会共享因子。

约掉之后剩下：

\[G(d_1)\,G(d_2) \;=\; G(d_1 + d_2)\]

第 3 步：这个方程的解是什么

这就是指数函数的定义方程。连续解只有一个：\(G(d) = e^{\lambda d}\)。

为什么只有指数函数？（可选阅读）

一个标准证明思路，两行：

设 \(G(d) = e^{h(d)}\)（任何正函数都能这样写，令 \(h = \ln G\)）。代入：

\[e^{h(d_1) + h(d_2)} = e^{h(d_1+d_2)} \;\Longrightarrow\; h(d_1) + h(d_2) = h(d_1 + d_2)\]

所以 \(h\) 满足柯西函数方程。而柯西方程的连续解只有线性函数——这是分析学里的经典结论。

于是 \(h(d) = \lambda d\)，代回去得 \(G(d) = e^{\lambda d}\)。

另外由 \(G(0) = 1\) 可知 \(h(0) = 0\)，所以那个「常数项」被自动定掉了，不会多出一个自由参数。

如果不要求连续，柯西方程还有病态解（依赖选择公理的加性函数），概率论里习惯默认排除——因为概率必须是可测的。

第 4 步：代回去

\[F(d) = \frac{e^{\lambda d}}{1 + e^{\lambda d}} = \frac{1}{1 + e^{-\lambda d}} = \boxed{\;\sigma(\lambda d)\;}\]

取 \(\lambda = 1\)（相当于把 \(\lambda\) 吸收进 \(r\) 的尺度）就是熟悉的 BT 形式：

\[P(y_w \succ y_l \mid x) = \frac{\exp\big(r_\phi(x, y_w)\big)}{\exp\big(r_\phi(x, y_w)\big) + \exp\big(r_\phi(x, y_l)\big)} = \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)\]

验算：假设 2 真的被满足吗

\[P(a\succ b) = \sigma(1.5) = 0.8176, \quad P(b\succ a) = 0.1824\] \[P(a\succ c) = \frac{0.8176 \times 0.8176}{0.8176\times 0.8176 + 0.1824 \times 0.1824} = \frac{0.6685}{0.6685 + 0.0333} = \frac{0.6685}{0.7018} = 0.9526\]
第三行特意用了一个负的 \(d_2\)：意味着 \(b\) 其实输给 \(c\)。搭接之后 \(a\) 仍然赢 \(c\)，而且赢的概率正好是 \(\sigma(1.5)\)。这不是巧合，是构造保证的。

1.4 σ 就是两分类的 softmax

\[\sigma(z) = \frac{e^{z}}{e^{z} + e^{0}}\]

把 \([y_w, y_l]\) 当成两个 logit 丢进 softmax，出来的就是它。

这个观察的价值

它把「奖励模型」这件听起来很玄的事，翻译成了一件朴素的事：奖励模型就是一个二分类器。输入两个候选，输出「第一个赢的概率」。第 2 名的 logit 恒为 0，相当于「不偏不倚」。

这也解释了奖励模型为什么通常和策略模型同架构——它就是策略模型换了个输出头。所以「reward model 常常和基座模型一样大」不是巧合，是架构复用的必然结果。

1.5 BT 损失

现在有了 \(P(y_w\succ y_l\mid x) = \sigma(r_w - r_l)\)，对数据集 \(D = \{(x, y_w, y_l)\}\) 做极大似然（0.4 节的三步）：

  1. 联合概率 = 每条连乘：\(\prod_{(x,y_w,y_l)\sim D} \sigma(r_w - r_l)\)
  2. 取对数：\(\sum \log \sigma(r_w - r_l)\)
  3. 最小化它的负：\(\mathcal{L}_{\text{RM}}(\phi) = -\,\mathbb{E}_{(x, y_w, y_l)\sim D}\Big[\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)\Big]\)

形式上，它和「二分类的交叉熵」完全一样——因为 1.4 节说了这就是个二分类器。

性质一：平移不变

损失里只出现 \(r_w - r_l\)。所以给所有 \(r\) 加 100，损失一个字节都不变（实测：\(-\log\sigma(5)\) 和 \(-\log\sigma(105-100)\) 完全相等）。

白话版：你没法问「这个回答值 3 分还是 −1 分」，因为分数的绝对位置是任意的。只有差距有意义。这会导致一个很麻烦的后果，见 1.7。

性质二：饱和

\(d = 5\) 时 \(\sigma = 0.9933\)，损失只剩 0.0067，梯度只剩 −0.0067——不到 \(d=1\) 时梯度的四十分之一。

梯度为什么会衰减成这样？求一下：

\[\frac{d}{dd}\Big[-\log\sigma(d)\Big] = \frac{d}{dd}\Big[\log(1 + e^{-d})\Big] = \frac{-e^{-d}}{1 + e^{-d}} = \sigma(d) - 1 = -(1 - \sigma(d))\]

当 \(d\) 越大，\(\sigma(d)\) 越接近 1，梯度就越接近 0。

白话版：奖励模型「已经分得够开了」，再继续加大差距也换不来多少分数。它会自动停手，不会无限拉大分差去刷分。这是 BT 自带的稳定机制。

性质三：无绝对刻度

训完之后 \(r_\phi\) 只能在同一个 prompt 下比较两个输出。跨 prompt 比是没有任何意义的。

原文措辞的常见误读

原书说「一个坏答案给 −2，一个好答案给 +2」。这句话常被误读成奖励模型的输出范围。

实际上：奖励模型给的是偏好概率；上面那三个性质合起来说明它根本没有绝对刻度。±2 是训练 LLM 时人为设定的目标奖励值（也就是把概率映射到一个便于设定的区间），跟奖励模型是两码事。

1.7 平移不变 → 所以必须导出 KL

这是本部分最重要的一条因果链。它不是「工程上有人加了个正则项试试看有效」，而是被数学逼出来的。

逐步推

  1. 损失只通过 \(r_w - r_l\) 出现，所以给所有奖励加 100，损失不变。
  2. 也就是说，目标函数没有定义奖励的绝对位置，沿 \(r \to r + C\) 是一个完全平坦的方向（梯度恒为零）。
  3. 而 RL 的优化是无约束的：只要奖励高，模型可以把权重推到任意远处。它不会自动停在「合理」的地方。
  4. 再叠加第 6 章的一个事实：序列 logprob 是长度敏感的——序列越长，\(\log\pi\) 越负。

第 3、4 步合起来就是一条完整的骗分路径：

步骤模型的策略结果
1把回答写得无限长\(\log\pi(y)\) 越来越负
2在 reward 里找对应的空隙因为平移不变，reward 的绝对值可以被整体抬高而不损失任何东西
3净效果模型学会了「变长」这个捷径，而不是「把题做对」

所以 InstructGPT 在 reward 里加了一项：

\[r(x, y) \;=\; r_\phi(x, y) \;-\; \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}\]

这就是 KL 散度（取对数形式）。它的作用是把参考模型锚住，禁止策略漂移。注意方向：这是减号——离参考模型越远，实际拿到的奖励越低。

结论

BT 的平移不变性不是「无害的数学便利」，它是RLHF 里 KL 项存在的根本原因。没有平移不变就没有这个无界方向；没有这个无界方向，用不用 KL 都行。

用一个一参数玩具模型把这件事看出来

构造一个极简模型：词表只有两个 token，X（正确）和 Y（错误）。唯一参数 \(\theta\) 是 X 的 logit。于是

\[P(X) = \sigma(\theta), \qquad \log\pi(X) = \log\sigma(\theta), \qquad \log\pi(Y) = \log\sigma(-\theta)\]

给两条 rollout：\(A_1 = +0.8659\)、\(A_2 = -0.8659\)（和第 6 章那组数字一致）。

推导：为什么这个玩具模型的 loss 是线性的
\[\mathcal{L} = -\frac{1}{2}\Big[A_1\log\sigma(\theta) + A_2\log\sigma(-\theta)\Big] = -\frac{A}{2}\Big[\log\sigma(\theta) - \log\sigma(-\theta)\Big]\]

而 \(\log\sigma(\theta) - \log\sigma(-\theta) = \log\dfrac{\sigma(\theta)}{1-\sigma(\theta)} = \operatorname{logit}(\theta) = \theta\)。所以：

\[\boxed{\mathcal{L} = -\frac{A}{2}\,\theta} = -0.43295\,\theta\]

实测确认：\(\theta=1\) 时 \(\mathcal{L} = -0.432950\)，\(-0.43295\times 1 = -0.432950\)；\(\theta=2\) 时两者都是 \(-0.865900\)。

梯度是常数 \(-A/2\)，与 \(\theta\) 无关。这意味着一件事：梯度下降永远往同一个方向走，永远不会停。没有任何平衡点。

KL 的恢复力是 \(\sigma(\theta)(1-\sigma(\theta))\theta\)。这个函数有上限：

这正是 reward hacking 的数学形状：不是「模型学坏了」，而是「约束的强度不够」。所以调 \(\beta\) 不是玄学，是在跟奖励强度赛跑。

1.8 和 Elo 是同一个东西

附录 F.4 讲的 Elo 排行榜和 BT 是同构的。

Bradley–Terry\(\sigma\big(\lambda (r_w - r_l)\big)\)\(e\)\(\lambda\)

为什么同构？两者都是 \(\frac{1}{1 + \text{某个底数的负幂}}\)，只是底数和尺度不同。取 \(\lambda = \ln 10/400 \approx 0.0057565\)，两者完全相同。实测 \(d = 2\) 时：

算法计算结果
Elo\(1/(1 + 10^{-2/400})\)0.502878
BT\(\sigma(0.0057565 \times 2)\)0.502878
\(\lambda\) 和 400 是什么角色

它们控制输出多样性。\(400\) 大 → 分数差异被压缩 → 老选手很难被爆冷 → 排行榜稳定但反应迟钝。\(400\) 小 → 分数差异被放大 → 爆冷频繁 → 灵敏但噪声大。

这个角色和第 4 章的 temperature 一模一样：都是「把 logits 的尺度调大调小」。

Elo 和 BT 的区别只在更新方式：Elo 是每场比赛立刻增量更新（在线），BT 是一次性拟合全部偏好数据（全批量）。数学内核完全一样。

1.9 GRPO 用的是 BT 吗？不是

这是个容易混淆的点。对照一下两条路线：

RLHF + PPORLVR + GRPO
打分从哪来训好的 \(r_\phi\)，本节这个 BT 模型第 3 章的数学验证器，给 0/1
打分形态连续标量（\(\sigma(r_w-r_l)\)，或映射到 ±2）二值
baseline 从哪来critic \(V_\psi\) 回归估计同组其他 rollout 的均值
信号\(r_\phi(x,y) - \beta\text{KL} - V_\psi\)\(\hat{A}_i = \dfrac{r_i - \text{mean}}{\text{std}}\)，组内 z-score
额外模型reference + reward + critic = 3 个0～1 个

也就是说，GRPO 把整个 BT 奖励模型和 critic baseline 都扔掉了，直接在 0/1 正确性上做组内标准化。

为什么能扔？一个类比：

类比：BT + critic 像是「请一个专业评委（奖励模型）给每份答卷打分，再请一个教务（critic）估计平均分来减掉」。GRPO 像是「同一批答卷里相互比较，只看谁比这批的平均水平好」。

后者在有标准答案的任务上完全够用，而且不可能被 hack——因为打分的是一个确定性的程序，不是一个可以被迎合的模型。DeepSeek-R1 论文的原话：神经奖励模型「susceptible to reward hacking during large-scale reinforcement learning」。

代价：只剩相对信息，且组内全对或全错时无信号。这就是第三道自查题。

常见误解

GRPO 的 advantage 不是 BT 模型输出的概率。它是对 0/1 正确性做 z-score 的结果，量纲完全不一样。把 \(\sigma(r_w-r_l)\) 和 \((r_i-\bar r)/\sigma_r\) 放一起比较是没有意义的。

1.10 实践：两个偏置必须显式控

BT 的乘法一致性假设一旦被违反，奖励模型就静默地学到别的东西——训练不会报错，只是效果变差。这是这类问题最难查的地方。

偏置一：位置偏置

表现：LLM 裁判（或者人）天然偏爱 Response A，或者偏爱 Response B，跟内容无关。很多模型有明显的「先写的更受优待」倾向。

为什么致命：如果 A 总是赢，BT 学到的就不是「A 的内容更好」，而是「A 这个位置更好」。给同一个回答换个位置标注，标签就变了。

DeepSeek-R1 的对策细节
正反各问 4 次同一对回答，4 次独立查询，每次随机把两个回答分配到 A / B 位置
取平均4 个判断求平均得到最终偏好分数
丢弃分歧大的4 个分数的极差 \(\Delta \le 1\) 的样本直接扔掉——「to ensure meaningful distinctions」

偏置二：长度偏置

表现：长回答显得更「用心」，LLM 裁判和人类都偏爱长的。

为什么致命：这会造成一种慢性的、看不出来的驱动力——模型越长奖励越高。这和你在 1.7 节看到的「序列 logprob 长度效应」是同向叠加的，两个力量合谋。

DeepSeek-R1 的对策细节
数据构造阶段配平「we ensure that the chosen and rejected responses of the whole dataset have comparable lengths」

第三条：裁判本身要够强

实测坑

R1 复现 HarmBench 时发现，用 LLaMA-2-13B 当裁判得到的结论不可靠，只好改用 GPT-4o（2024-11-20 版本）。

裁判的强度直接决定结论的可信度。这条对评测和训练同样成立——你在第 6 章用 GRPO 训出来的模型，其 reward 全是这个 0/1 验证器给的，验证器写错了，梯度就是错的。

论文的安全性评测里有一句值得警惕：

when obtaining results for different models, some queries are flagged as unsafe by the risk control system, leading to automatic refusals. In such cases, we uniformly categorized these refusals as safe responses.

1.11 BT 的验证代码

import math

sig = lambda z: 1 / (1 + math.exp(-z))

def combine(d1, d2):
    """假设 2：从两两比较搭接出 P(a>c)"""
    p1, p2 = sig(d1), sig(d2)
    num = p1 * p2
    return num / (num + (1 - p1) * (1 - p2))

# 1) 搭接一致性
for d1, d2 in [(1.5, 1.5), (0.5, 3.0), (2.0, -0.5)]:
    assert abs(combine(d1, d2) - sig(d1 + d2)) < 1e-12
print("搭接一致性 OK")

# 2) Elo 与 BT 同构
lam = math.log(10) / 400
d = 2.0
assert abs(1 / (1 + 10 ** (-d / 400)) - sig(lam * d)) < 1e-12
print("Elo == BT OK,  lambda =", lam)

# 3) 平移不变
assert abs(-math.log(sig(5)) - (-math.log(sig(105 - 100)))) < 1e-12
print("平移不变 OK")

# 4) 饱和
for d in [0, 1, 2, 3, 5, 6]:
    print(f"d={d:>4}  sigma={sig(d):.4f}  loss={-math.log(sig(d)):.4f}")

方向

\(\hat{A} > 0\) 的项在 loss 里是负数，最小化 loss 就是把它们往更负推 = 让 \(\log\pi\) 下降 = 概率上升。\(\hat{A} < 0\) 的项贡献正数，最小化会压低它 = 概率下降。

也就是说：正确且高 advantage 的回答被推高，错误且低 advantage 的回答被压低。方向完全由 \(A\) 的符号决定，大小由 \(|A|\) 决定。

为什么符号是这样？（从梯度往回推）

上面是「看结果」，我们再看一遍「为什么是这个结果」。对 loss 求参数梯度：

\[\frac{\partial \mathcal{L}_{\text{pg}}}{\partial \theta} = -\frac{1}{N}\sum_{i=1}^{N} \hat{A}_i \, \nabla_\theta \log \pi_\theta(y^{(i)}|x^{(i)})\]

梯度下降的更新规则是 \(\theta \leftarrow \theta - \eta \cdot \frac{\partial \mathcal{L}}{\partial\theta}\)。所以：

\[\Delta\theta_i \;=\; +\frac{\eta}{N}\,\hat{A}_i \, \nabla_\theta \log \pi_\theta(y^{(i)}|x^{(i)})\]

关键在 \(\nabla_\theta \log\pi_\theta\)：它的方向是「提高这条序列的概率」。梯度下降总是往负梯度走，而这里前面有个负号，所以：

  • \(\hat{A}_i > 0\) → \(\Delta\theta_i\) 沿着 \(\nabla \log\pi_i\) 的方向 → 提高概率 ✓
  • \(\hat{A}_i < 0\) → 反方向 → 压低概率 ✓
  • \(\hat{A}_i \approx 0\) → 几乎不动 → 不贡献
数值实证：用一个一参数模型跑一遍，看正确 token 真的被推高

光看公式还是有点抽象。我们造一个能跑的最小模型：词表两个 token（X 正确、Y 错误），唯一参数 \(\theta\) 是 X 的 logit。于是

\[P(X) = \sigma(\theta), \qquad \log\pi(X) = \log\sigma(\theta), \qquad \log\pi(Y) = \log\sigma(-\theta)\]

给两条 rollout：\(A_1 = +0.8659\)、\(A_2 = -0.8659\)。

\[\frac{d\log\sigma(\theta)}{d\theta} = 1-\sigma(\theta), \qquad \frac{d\log\sigma(-\theta)}{d\theta} = -\sigma(\theta)\] \[\Rightarrow\quad \frac{d\mathcal{L}}{d\theta} = -\frac{1}{2}\Big[A(1-\sigma) + (-A)(-\sigma)\Big] = -\frac{A}{2} = -0.433\]

步骤 5 · 那个负号是干什么的

RL 想要最大化：

\[\max_\theta \frac{1}{N}\sum_i \hat{A}_i \log\pi_\theta(y^{(i)}|x^{(i)})\]

而 PyTorch 优化器只会最小化。好在两者是严格等价的：

\[\max f \iff \min(-f), \qquad \nabla(-f) = -\nabla f\]

优化器往负梯度方向走，等价于往 \(\nabla f\) 方向走，参数更新完全相同。

用原文那个 f(x) = 3 的例子完整走一遍

原文用了一个很朴素的例子，我们把它做完：

  • 最大化视角：目标 \(f(x) = 3\)。3 比 2 好，所以我们想要 3。
  • 但 PyTorch 会最小化：它看到 loss = 3，会想「3 比 2 大，我把它降下来」，于是朝 2 走——正好和我们想要的相反。
  • 翻转符号：定义 \(L(x) = -f(x) = -3\)。现在最小化 \(L\) 就是把 −3 往下压，比如降到 −5；对应 \(f\) 就从 3 涨到 5。

关键：\(L\) 越小，\(f\) 越大。而优化器就是往 \(L\) 小的地方走，所以它自然把 \(f\) 往大处推。

回到本章：\(-2.5764\) 就是「越小越好」。如果它变成 \(+2.5764\)，最小化就会朝相反方向走。

反证：去掉负号会怎样

如果没有负号，损失是 \(\frac{1}{N}\sum \hat{A}_i\log\pi_i = +2.5764\)。最小化它就会：压低正确回答的概率、抬高错误回答的概率。模型会朝完全相反的方向走，MATH-500 准确率断崖式下跌。

步骤 6 · 一个容易被漏掉的观察

看第 1 行和第 2 行：\(-6.86\) 和 \(-17.45\)。

rollout长度（量级）梯度权重
\boxed{83}几个 token-6.86
The correct answer is \boxed{83}长得多-17.45（2.5 倍）

一个又长又正确的回答，拿到的梯度权重大得多。这不是 bug，是第 6 章用 \(\sum_t\) 而不是 \(\text{mean}_t\) 的直接后果——内层求和的贡献正比于序列长度。

这个观察连着两个后续：

  • 第 7 章的 DAPO / token-level loss 就是要把外层的 \(1/N\) 重新分配回每个 token，让长回答不再获得不成比例的权重。
  • 第 7.6 节的 format reward 失败：格式奖励让模型学会「套 tag 就拿分」，而序列 logprob 的长度效应让它「套完 tag 早点收工」，思考被压缩 → reward 高但 eval掉。
原文对长度的说法要留意：等 reward 下模型倾向更早停止，而不是无限变长。原因是长序列的 \(\log\pi\) 天生更负，需要更大的参数变动才能改善，而改善空间也更小。

自查题 2 · 为什么是 prompt_len - 1 而不是 prompt_len

这道题考什么

考的是因果掩码造成的「错位一格」。这类 bug 最烦的地方在于：它不报错。程序照常运行，只是算出了一个错的值。

相关代码：

def sequence_logprob(model, token_ids, prompt_len):
    logits = model(token_ids.unsqueeze(0)).squeeze(0).float()
    logprobs = torch.log_softmax(logits, dim=-1)      # [L, |V|]
    selected = logprobs[:-1].gather(
        1, token_ids[1:].unsqueeze(-1)
    ).squeeze(-1)
    return torch.sum(selected[prompt_len - 1:])

步骤 1 · 因果掩码的结构性事实

自回归模型的第 \(i\) 个位置只能看到 \(0, 1, \dots, i\) 的输入（靠下三角 mask 实现）。所以输出层的第 \(i\) 行 预测的是位置 \(i+1\) 的 token：

\[\text{logits}[i] = \text{「位置 } i+1 \text{ 的 token 在位置 } 0 \dots i \text{ 条件下的分布」}\]

再叠加 gather 的错位配对（logprobs[:-1] 配 token_ids[1:]），两边都移动了半格，合起来正好对上：

\[\text{selected}[k] \;=\; \log P\big(\text{token\_ids}[k+1] \mid \text{token\_ids}[0..k]\big)\]
记住这一句

selected[k] 对应的是位置 \(k+1\) 的 token，不是位置 \(k\)。

步骤 2 · 生成部分在哪个区间

设 prompt 长度 \(P\)，生成长度 \(T\)，总长 \(L = P + T\)。位置 \(P\) 是第一个生成 token：

我们要的token 位置对应 selected 下标切片写法
prompt 部分（不要）\(1, 2, \dots, P-1\)\(0, 1, \dots, P-2\)selected[:P-1]
生成部分（要）\(P, P+1, \dots, L-1\)\(P-1, P, \dots, L-2\)selected[P-1:]

推导的起点是那句「selected[k] 对应位置 \(k+1\)」：位置 \(P\) 对应下标 \(P-1\)，位置 \(L-1\) 对应下标 \(L-2\)。所以下标区间是闭区间 \([P-1, L-2]\)，写成 Python 切片就是 selected[P-1:]。

步骤 3 · 长度校验（这步最不容易出错）

\[\text{len}\big(\text{selected}[P-1:]\big) = (L-2) - (P-1) + 1 = L - P = T \quad✓\]

切片长度必须正好等于生成 token 数。这是最快的自查手段——如果对不上，一定错。

步骤 4 · 用一个可逐格核对的小例子走一遍

  • 多算了 prompt 的最后一个 token——位置 2 的值 −2 被算进来了

步骤 5 · 为什么这不是「差一个格」，而是语义错误

这是本题最值得想清楚的地方：为什么「多算一个 prompt token」不是无所谓的噪声？

对比两个位置回答的问题：

位置 3（第一个生成 token）位置 2（prompt 末 token）
logprob 在问什么「读完整个问题之后，模型有多确定自己该从这里开始回答」「在已有 prompt 的条件下，prompt 的下一个字应该是什么」
编码了什么对 prompt 的理解——它已经把题目读进去了只是语言模型的续写惯性：prompt 写到一半，下一个词多半是什么
典型数值可能是 −2（模型要「切换模式」进入解题）可能是 −0.1（续写一个数字或符号，模型很确定）
对 RL 训练的价值高——它标记了「从提问到解题」的转折点低——它对「答得对不对」几乎没有贡献
一句话

用 prompt 末 token 的 logprob 去顶替第一个生成 token，等于用「预测问题文本的下一个字」冒充「回答的第一个决策」。这两件事没有任何语义关系。

还有一个更技术性的理由：它会系统性地压低序列 logprob。因为 prompt 末 token 的 logprob 通常比生成部分更接近 0（更不负），把它换进来，等于往一个偏负的包里塞了一个偏正的值，让整条序列的 logprob 变得不那么负，于是 A * logπ 这一项的绝对值变小，正确的回答拿到的梯度权重被稀释了。

步骤 6 · 顺带：为什么还要 logprobs[:-1]

这是同一件事的另一半，容易被忽略。输入总长是 \(L\)，logits 有 \(L\) 行，但最后一行 logits[L-1] 预测的是位置 \(L\) 的 token，而它不存在。

所以：

  • logprobs[:-1] → 只留行 \(0 \dots L-2\)，长度 \(L-1\)
  • token_ids[1:] → 只取位置 \(1 \dots L-1\)，长度 \(L-1\)
  • 两者才能 gather 对齐

如果不写 [:-1]，两个张量长度差 1，gather 会直接报 shape 不匹配。

对比一下两种错误的「友好程度」

忘记 [:-1] → 会立刻崩，报错告诉你出问题了。

把 [P-1:] 写成 [P:] → 静默算错，程序跑得好好的，只是结果不对。

所以这一节专门讲的是后者。

步骤 7 · 顺带二：为什么用 gather 而不是 argmax

方式问的问题本例结果
argmax「模型当时最想说什么？」tok1，值 −0.5
gather「模型实际说了那个 token，事后看有多意外？」tok2，值 −9.0

用一个三 token 的小例子（logprob 行 [-2.0, -0.5, -9.0]，实际生成了 tok2）：argmax 给出 tok1 和 −0.5，gather 给出 tok2 和 −9.0，差 8.5 倍。

在 GRPO 里我们要问的是后者。因为 rollout 已经生成完了，\(y_t\) 是既成事实。我们回头问的是「当初这一步模型有多确信」——这个量衡量的正是意外程度，而意外程度恰好与「这一步是否出错」高度相关（第 6 章实测：唯一答错那条的 logprob 最低）。

用 argmax 的话，每一步都取最大值，所有 token 的 logprob 都一样接近 0，这个信号完全消失。

自查题 3 · rewards=[0,0] 时 loss 为什么是 0，为什么这是好事

步骤 0 · 原文实证

原文 listing 6.15 用 num_rollouts=2 跑 math_train[4]，输出：

{'advantages': [0.0, 0.0],
 'loss': -0.0,
 'loss_tensor': tensor(-0., grad_fn=<NegBackward0>),
 'pg_loss': -0.0,
 'rewards': [0.0, 0.0],
 'samples': [{'gen_len': 4,   'reward': 0.0, 'text': ' 14'},
            {'gen_len': 256, 'reward': 0.0, 'text': ' 4\nTo solve the problem, ...'}]}

两条 rollout 都答错（正确答案是 6，必须写成 \boxed{6}），所以 reward 全 0。

步骤 1 · 手算

先看中心化：

\[\mu_r = \frac{0 + 0}{2} = 0, \qquad \sigma_r = 0\]

再看归一化。这里分子恰好也是 0，所以 \(10^{-4}\) 加不加都一样：

\[\hat{A}_i = \frac{0 - 0}{0 + 10^{-4}} = 0 \quad\text{（两个都是）}\]

代入 loss：

\[\mathcal{L}_{\text{pg}} = -\frac{1}{2}\big[0 \times \log\pi_1 + 0 \times \log\pi_2\big] = -0.0\]

实测：adv [0.0, 0.0]、loss -0.0。

关于 -0.0：这不是 bug。Python 里 -0.0 == 0.0 为 True，打印成 -0.0 只是浮点符号位的显示差异。数学上它就是 0。

步骤 2 · 梯度为什么也是 0

\[\frac{\partial \mathcal{L}_{\text{pg}}}{\partial \theta} = -\frac{1}{N}\sum_{i=1}^{N} \hat{A}_i \, \nabla_\theta \log \pi_\theta(y^{(i)}|x^{(i)})\]

所有 \(\hat{A}_i = 0\)，所以每一项的系数都是 0。对计算图来说：没有任何一条路径能从 loss 通到模型参数上。

实测：loss.grad_fn is None（因为输入本来就没有 requires_grad）；真实训练时 loss_tensor.backward() 会把所有参数的 .grad 保持为 None 或 0，然后 optimizer.step() 什么都不做。

原文的措辞：the gradient would be zero and the model parameters would not be updated。

步骤 3 · 顺手看看另外三种 reward 组合

为了对照，我们把四种情况都算一遍（同一组 logprob）：

← 表格可左右滑动→

reward 向量情形\(\sigma_r\)\(\hat{A}\)loss
[0,0,0,0]全错0.0000[0, 0, 0, 0]-0.0000
[1,1,1,1]全对0.0000[0, 0, 0, 0]-0.0000
[1,1,0,0]一半对（本章的例子）0.5774[+.866, +.866, -.866, -.866]-2.5764

[0,1,0,1] 的 loss 是 +4.1097，正的。loss 是正的不代表「训练得好」——它只是这一组的相对量的另一种排列方式。

这也是原文说「不要过度解读 loss 绝对值」的另一个理由。真正该看的是多步平均的 reward_avg 和 MATH-500 准确率。

步骤 4 · 为什么这是好事 —— 三个层次

层次一：数学上，组内全相同 = 无信息。

GRPO 的学习信号完全来自组内对比。四条 rollout 拿一样的分，意味着这组样本没有携带任何关于「哪条更好」的信息。这种情况下梯度为零不是算法失效，而是算法正确地反映了「无事可学」。

打个比方：你让四个人描述同一道题的解法，然后问「谁解得更好」。如果四份答案的评分完全一样，你无法从中学到任何东西——不管你再怎么分析这四份数据。梯度为 0 就是这个事实的数学表达。

层次二：行为上，两种情形梯度为零都对。

组内情形含义如果继续硬更新会怎样
\(r = [1,1,1,1]\)
全对		模型已经会做这道题了过拟合到这批具体答案上；把已经学会的东西推坏（学过的东西最容易被新信号带偏）
\(r = [0,0,0,0]\)
全错		模型完全不知道往哪走既然没有一个方向能走，梯度只能是个随机方向的噪声，纯属破坏

从算力角度看：这两个 prompt 贡献不了任何信息，继续在它们上面花 rollout 的钱是浪费。

层次三：统计上，中心化保证了「净推力」恒为 0。

\[\sum_i \hat{A}_i = \frac{\sum_i (r_i - \mu_r)}{\sigma_r + \epsilon} = \frac{0}{\sigma_r + \epsilon} = 0\]

不管组内是什么样的分布，减完均值之后 advantage 之和永远是 0。所以这一组 rollout 对模型的整体推力是零，只有相对方向。

这正是第 7.3.1 节监控 adv_avg 的意义——它恒为 0.0000，作者说这只是「a sanity check that the implementation behaves as expected」。

为什么这个性质是必需的？假设不减均值会怎样：

情形不减均值时 max logπ 的实际含义后果
\(r = [1,1,1,1]\)（全对）「无条件抬高这批序列的概率」，不管好不好净效果：模型在「全抬高」和「全压低」两个极端之间来回震荡
\(r = [0,0,0,0]\)（全错）无条件压低同上

减完均值后 \(A\) 之和为 0，梯度就纯粹表达「哪边该升、哪边该降」的相对关系，学到了方向性。

步骤 5 · 但这同时是 GRPO 数据效率的主要瓶颈

零梯度是好事，但零梯度样本太多就是问题。

真实训练中，大量 prompt 会落入这个区间：

  • 简单题：模型很快就能全对 → 组内无方差 → 该 prompt 从此永久贡献 0 梯度
  • 难到没救的题：一直全错 → 同样 0 梯度

所以你会看到一个「正常但反直觉」的现象：reward_avg 在上升，而「有效样本比例」在下降。这不是 bug，是 GRPO 的固有结构。

这正是 DAPO 那两条改进针对的地方：

改进做法针对
dynamic sampling丢弃零梯度的组，继续采样直到攒够 \(G\) 个有效组算力浪费在无信息样本上
filter out 退化 rollout丢掉没头没尾直接吐答案、或撞满 token 上限的 rolloutlisting 6.15 里 gen_len=4 和 gen_len=256 那两个极端

步骤 6 · 实现上的三个坑

坑一 · num_rollouts 必须 ≥ 2

torch.std() 默认无偏，分母是 \(n-1\)。当 \(n = 1\) 时分母为 0，结果是 NaN：

torch.tensor([1.0]).std()   # nan   （警告: degrees of freedom is <= 0）
torch.tensor([0.0]).std()   # nan

NaN 会顺着 advantage 污染整个 loss，反向传播后所有权重变成 NaN，模型直接报废。这就是 compute_grpo_loss 里 assert num_rollouts >= 2 的真正原因。

而 n = 2 时恰好安全：\([0,0]\) 的分子也是 0，\(0/1 = 0\)。

坑二 · 1e-4 只是除零兜底，不影响任何实际计算

因为验证器只给 0/1，reward 全等时分子必然是 0，1e-4 加不加结果一样。

实测：遍历 \(N = 2 \dots 8\) 的全部 0/1 reward 向量，加与不加 1e-4 的 advantage 最大差异是 7×10⁻⁴。可以完全忽略。

它不是超参，不需要调。它的作用就是让全等组输出 0 而不是 NaN。

坑三 · 别把零梯度当成训练失败

原文第 6.11 节明确提醒：不要过度解读 loss 的绝对数值。reward_avg=0.000 的步 loss 接近 0 是正常的；反过来，loss 数值大只说明组内差异大，训练初期尤其如此，不代表学得好。

该看的是多步平均的 reward 趋势，以及下一节的 MATH-500 准确率。

三道题串起来看

它们不是三个孤立的知识点，正好对应一条完整链路上的三个环节：

题号在链路上的位置唯一要记住的点
1信号 → 梯度的方向由 \(\hat{A}_i\) 的符号决定；负号把最大化翻成最小化
2数据结构的索引对齐因果掩码让输出层错位一格，所以是 P-1；校验切片长度 == \(T\)
3信号什么时候该为空组内无差异 = 无信息；梯度为 0 是正确行为，但零梯度样本过多是效率瓶颈

把这三道题串起来，就是 GRPO 一轮的完整生命周期：
