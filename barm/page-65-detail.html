7.3 advantage 统计量与熵：完整数学推导

这一节推导两个诊断指标。它们本身不进入 loss，只用来回答一个问题：训练现在是在进步还是在崩？ 熵尤其重要——它是唯一能提前预警「训练崩溃」的指标，而 7.5 的 KL 失效模式正是靠它被发现的。

一、advantage 统计量

1.1 为什么均值和标准差都要看

优势函数：

\[ A_i = \frac{r_i - \mu_r}{\sigma_r + \epsilon} \] 
def compute_advantage_stats(rewards_list):
    rewards = torch.tensor(rewards_list)
    advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-4)
    adv_avg = advantages.mean().item()
    adv_std = advantages.std().item()
    return advantages, adv_avg, adv_std

1.2 均值恒为 0（设计使然）

\(r_i\)\(A_i\)
1+0.8659
1+0.8659
0−0.8659
0−0.8659

因为分子减的就是同一个均值：

\[ \begin{aligned} \frac{1}{N}\sum_{i=1}^{N} A_i &= \frac{1}{N(\sigma_r+\epsilon)}\sum_{i=1}^{N}(r_i - \mu_r) \\[4pt] &= \frac{1}{N(\sigma_r+\epsilon)}\left(\sum_i r_i - N\mu_r\right) = 0 \end{aligned} \]

对照原文输出：Advantage mean = 0.0000, std = 0.9998。

所以 adv_avg 是纯 sanity check

原文：Because of how advantages are computed in GRPO, their mean is always zero. In practice, this makes the mean mostly a sanity check that the implementation behaves as expected.

它的唯一作用是查 bug。如果 adv_avg 偏离 0，说明归一化实现有问题。

1.3 标准差才是信息量所在

由于 \(A_i\) 已经按 \(\sigma_r\) 归一化，adv_std 本质上是在度量组内 reward 的区分度。原文给了明确的解读：

adv_std含义训练影响
≈ 1.0信号尺度良好✅ 稳定，通常伴随有效更新
非常小学习信号消失⚠️ 常伴随 reward collapse（全对/全错）
非常大更新过于尖锐⚠️ 可能破坏训练稳定性

原文在 7.3.3 分析实际训练曲线时说：Early in training, we see relatively high variance... Over time, the advantage standard deviation gradually decreases and stabilizes, which means that the rollouts become more similar in quality.

训练中 adv_std 下降是好事还是坏事？原文的框架里，下降意味着模型输出质量趋于一致（好事），但降到 0 意味着完全没信号（坏事）。所以要看的不是绝对值，而是是否稳定在非零水平。

二、熵（entropy）

2.1 定义与直觉

熵衡量模型生成下一个 token 时的不确定程度：

\[ H(P) = -\sum_{v=1}^{|V|} P(v) \log P(v) \]

两个极端：

分布熵行为
全部质量集中在一个 token\(H = 0\)完全确定性，argmax 退化情形
质量均匀分布\(H = \log|V|\)完全随机

2.2 熵的最大值随词表大小变化

均匀分布时 \(H = \log |V|\)。这解释了原文的分级标准：

熵范围解释
≈ 0 – 0.5一个 token 主导，模型高度自信，近似确定性
≈ 1 – 2概率分散在合理数量的 token 上，稳定训练的典型状态
接近 \(\log|V|\)概率铺开到大量 token，高度不确定，近似随机
这个分级的适用范围

原文的例子用 词表大小 7（否则 151,000 维没法画图），此时 \(\log 7 = 1.9459\)。但表 7.3 的分级是按 真实词表 151,936 说的（\(H_{\max} \approx 11.93\)）。两个数不在同一量纲——看熵曲线时不要拿这个 demo 的 1.37 当参照。

2.3 从 logits 算熵

logits = torch.tensor([0.6667, -2.0000, 1.3333, -0.0000, -0.6667, 2.0000, -1.3333])

probs    = torch.softmax(logits, dim=-1)
logprobs = torch.log_softmax(logits, dim=-1)
entropy  = torch.sum(-(probs * logprobs))
print("Probs:", probs)
# tensor([0.1295, 0.0090, 0.2522, 0.0665, 0.0341, 0.4912, 0.0175])
print("Entropy:", entropy)  # tensor(1.3700)

2.5 熵的非负性

每一项 \(-p \log p \ge 0\)（因为 \(0 \le p \le 1\) 时 \(\log p \le 0\)），所以 \(H \ge 0\) 恒成立。这就是为什么代码写成 -(probs * logprobs) 而不是 (probs * logprobs)。

2.6 为什么能只用 logprobs 算 probs

原文指出：torch.log_softmax 内部等价于 torch.log(torch.softmax())，而 exp 是 log 的逆函数，所以：

\[ P(v) = \exp(\log P(v)) \] 
print("Probs:", torch.exp(logprobs))
# 和直接 softmax 得到完全一样的值

2.7 扩展 sequence_logprob 同时返回熵

def sequence_logprob_and_entropy(model, token_ids, prompt_len):
    logits = model(token_ids.unsqueeze(0)).squeeze(0).float()
    logprobs = torch.log_softmax(logits, dim=-1)
    targets = token_ids[1:]
    selected = logprobs[:-1].gather(1, targets.unsqueeze(-1)).squeeze(-1)
    selected_answer_logprobs = selected[prompt_len -1:]
    logp_all_steps = torch.sum(selected_answer_logprobs)
    # 熵需要在整个词表上算，不能只取选中 token
    all_probs = torch.exp(logprobs)
    entropy = torch.sum(-(all_probs * logprobs), dim=-1)

一个容易忽略的差别：序列 logprob 只关心 实际生成的那个 token（gather），而熵关心 整个词表的分布形状。所以熵必须在 logprobs 的完整 [L, |V|] 矩阵上求，不能先 gather。采样动作 vs 分布形状，两回事。

三、熵作为训练崩溃的早期信号

熵的状态诊断可能原因
极低，接近 0训练坍缩（collapse）模型停止探索，重复产出相同输出；采样多样性丧失 → self-consistency 失效
适中（稳定区间）✅ 健康—
过大，持续上升更新不稳定响应随机化；7.5 的 KL 失效模式
7.5 的 KL 失效就是靠这个指标确诊的

奖励塌到 0 之后，PG 梯度消失，KL 项成为唯一梯度来源——而它作用在固定采样 token 上，最小化它会压低已采样 token 的概率，让质量流向其他 token，熵上升，输出变随机。

所以只要你发现 entropy_avg 后期突然飙升，就该怀疑 KL 项或者步长过大。这个指标是诊断工具，不是优化目标。

四、四个指标的分工

指标衡量理想值异常意味着
adv_avg归一化 sanity check恒为 0偏离 0 → 实现 bug
adv_std学习信号强度稳定非零趋 0 → reward collapse；过大 → 尖峰更新
entropy_avg输出多样性 / 探索度适中且平稳趋 0 → 坍缩；飙升 → 随机化
avg_response_len生成长度（6.8 长度偏置）与准确率同向缩短但准确率降 → reward hacking
