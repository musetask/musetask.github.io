6.1.1 RLHF：偏好目标、奖励模型与 PPO 的数学形式

原文的 6.1 节把 RLHF 讲成「两步流水线」（训练奖励模型 → 用奖励模型更新 LLM），图 6.5 里给出了几条公式，但全部推导都跳过了；第 6 章的正式推导要从 6.7 才开始。这一页把 6.1 节欠下的数学补齐：为什么成对偏好能训出一个标量奖励模型（Bradley–Terry 似然）、PPO 的目标函数从哪来、KL 为什么必须存在，并说清它与后面 GRPO 的对应关系。

一、为什么需要 RLHF：token 级目标的局限

预训练和 SFT 的目标都是逐 token的：

\[ \mathcal{L}_{\text{SFT}} = -\sum_{t=1}^{T} \log \pi_\theta(y_t \mid y_{<t}, x) \]

也就是 5.5 节的链式法则取对数。这个目标有两个结构性缺陷：

  1. 它不知道整体好坏。序列概率高只说明「每个 token 在给定前缀下都还行」，一个流畅但答错的答案可以拿到很低的 loss。
  2. 它无法表达偏好。原文的例子里 Response A 和 Response B 都提到相关要点，但 B 更具体、更贴合用例。「更具体」不是任何一个 token 级别的属性，它只在完整输出被并排比较时才存在。
RLHF 改变的是优化的对象，不是模型的容量

模型还是那个模型，损失还是那个损失。变的是信号的定义域：从「每个 token 是不是人写的」变成「整段输出是不是人更喜欢的」。原文的原话：RLHF moves beyond this token-level optimization and instead optimizes models on whole outputs。

二、步骤一：奖励模型的 Bradley–Terry 目标

2.1 从偏好推出概率

标注员给出成对偏好 \(y_w \succ y_l\)。需要一个模型把「偏好」翻译成「可比较的数值」。Bradley–Terry 模型（也是第 F.4 节 Elo 的概率基础）假设：给定两个输出，偏好 \(y_w\) 的概率只由两者奖励之差决定：

\[ P_\phi(y_w \succ y_l \mid x) = \frac{\exp\big(r_\phi(x, y_w)\big)}{\exp\big(r_\phi(x, y_w)\big) + \exp\big(r_\phi(x, y_l)\big)} = \sigma\!\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big) \]
这里出现了一个 softmax。把第 F.4 节的 \(1/(1+10^{-\Delta R/400})\) 换成自然指数形式就得到它——两处是同一个函数，区别只在 Elo 用 10 为底、BT 用 \(e\) 为底。Elo 那边 400 的角色，在这里相当于一个温度超参。

2.2 奖励模型 = 一个只输出标量的 LLM

\(r_\phi(x, y)\) 的实现很朴素：把 prompt + response 拼起来送进 LLM，取最后一个位置的标量输出（不是词表 logits，是单独的一维 head）。所以奖励模型和策略模型常常是同一个架构、同一份预训练权重，区别只在输出头和微调数据。

2.3 损失函数：成对交叉熵

对数据集 \(D = \{(x, y_w, y_l)\}\) 做极大似然：

\[ \mathcal{L}_{\text{RM}}(\phi) = -\mathbb{E}_{(x, y_w, y_l)\sim D}\Big[\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)\Big] \]

这个损失有几个值得注意的性质：

  • 只需要差值。损失只通过 \(r_w - r_l\) 出现，所以奖励的整体平移是无害的——给所有奖励加 100，损失不变。这正是后面第七节 KL 必须存在的原因。
  • 饱和。当 \(r_w - r_l \ge 5\) 时 \(\sigma \approx 0.993\)，\(\log\sigma \approx -0.007\)，梯度几乎为 0。奖励模型会自然停止在「已经分得够开」的地方，不会无限增大差值。
  • 没有绝对分数。训练完的 \(r_\phi\) 只能在同一个 prompt 下比较两个输出。原文说「好的答案 +2、差的 -2」其实是 RL 阶段的目标信号，不是奖励模型的输出尺度。

    • 三、步骤二：PPO 的目标函数

    3.1 从策略梯度出发

    我们想最大化期望奖励：

    \[ J(\theta) = \mathbb{E}_{y \sim \pi_\theta(\cdot|x)}\big[r_\phi(x, y)\big] \]

    REINFORCE 的策略梯度定理给出：

    \[ \nabla_\theta J = \mathbb{E}\big[\nabla_\theta \log \pi_\theta(y|x) \cdot A(x, y)\big] \]

    其中 advantage \(A\) 衡量「这个动作比平均水平好多少」。问题在于方差极大——整段序列的奖励只在最后才知道，中途完全无法分解，所以每个 token 都在背一个高噪声的信号。

    3.2 PPO 的两个改进

    改进一：价值函数基线。引入 critic \(V_\psi(x, y_{\le t})\) 估计「到目前为止的平均水平」，用它做基线降方差：

    \[ A_t = r_t + \gamma V_\psi(x, y_{\le t+1}) - V_\psi(x, y_{\le t}) \]

    （\(\gamma V\) 这一项是 GAE 引入的，把多步 TD 残差组合成优势估计。）critic 自己要用回归损失训练：

    \[ \mathcal{L}_V = \mathbb{E}\big[\big(V_\psi - \text{目标}\big)^2\big] \]

    改进二：重要性采样比率 + 裁剪。采样昂贵，所以一批数据要复用多步（这使数据变成 off-policy）。用新旧策略的概率比来校正：

    \[ \rho_t(\theta) = \frac{\pi_\theta(y_t|x, y_{<t})}{\pi_{\theta_{\text{old}}}(y_t|x, y_{<t})} = \exp\!\big(\log\pi_\theta - \log\pi_{\text{old}}\big) \]

    然后把这个比值裁剪到 \([1-\epsilon, 1+\epsilon]\)，并取悲观下界：

    \[ \boxed{\;\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t\Big[\min\big(\rho_t A_t,\ \operatorname{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t\big)\Big]\;} \]

    PPO 论文里的完整目标是要最大化的三项之和（注意符号约定和「最小化 loss」相反）：

    \[ J_{\text{PPO}} = \mathcal{L}^{\text{CLIP}} - c_1 \mathcal{L}_V + c_2\,\mathbb{E}\big[\mathrm{H}(\pi_\theta(\cdot | x, y_{<t}))\big] \]

    最后一项是熵奖励：在要最大化的目标里加 \(+c_2 H\)，等价于在要最小化的 loss 里写 \(-c_2 H\)——两种写法都是在鼓励探索。推导见 7.4 推导。

    3.3 为什么必须有一个 KL

    PPO 的优化是无约束的：只要奖励高，模型可以把权重推到任意远处。而 5.6 推导已经证明 logprob 是长度敏感的量——序列越长，\(\log\pi\) 越负。如果放任策略漂移，模型会学出「靠变长骗高分」这类退化解。InstructGPT 因此在奖励里加了一项：

    \[ r(x, y) = r_\phi(x, y) - \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} \]
    这个 \(-KL\) 项和 7.5 节的 GRPO KL 项是同一个东西

    它们符号相同、作用相同、只是记法不同：这里写成 reward 的一部分（所以进的是 advantage），第 7 章写成 loss 的一部分（所以不进 advantage）。常见的实现陷阱正源于此——放错位置会让 \(\beta\) 失效，因为组内归一化会把一个全局的常数偏置减掉。详见 7.5 推导。

    四、PPO 的成本问题：四条资源账单

    1. 要训一个额外的 reward model，规模常常和基座模型相当。原文：which is often a large LLM that is also expensive to train。
    2. 要多一个 critic（value model），又是一份模型权重 + 一份显存。
    3. 每步要四个模型同时在显存里：policy、reference、reward、critic。
    4. reward hacking：一旦有可被利用的漏洞，策略会去钻。BT 奖励模型只见过训练分布，一旦偏离就会给出不可信的分数。

    这四条直接导向了 RLVR 的动机：把第 1、2 条整个消掉（用确定性验证器代替 reward model，用组内相对比较代替 critic），只剩第 3、4 条（KL 与 reward hacking），而第 3 条的 KL 后来也被证明在数学任务上弊大于利（见 7.5 推导）。

    五、RLHF → RLVR：只换了信号，结构不变

    RLHF（两步）RLVR（一步）
    打分来源训练好的 \(r_\phi\)（LLM）确定性验证器（比答案、跑代码）
    打分形态连续标量（−2 … +2）二值（0 / 1）
    信号来源人工偏好无（完全自动）
    策略更新PPO（需 critic）GRPO（不需 critic）
    流水线图 6.5 的上下两个子图只有图 6.5 的下半部分

    原文：the two-step RLHF pipeline shown in figure 6.5 collapses into a single training loop that resembles step 2 in RLHF。RLVR 消掉的是第 1 步，不是第 2 步——第 2 步那个「采样 → 打分 → 策略梯度更新」的循环，才是 DeepSeek-R1 之后所有推理模型训练的核心骨架。

    二值奖励的后果：组内全对或全错

    验证器只给 0/1，所以一个 prompt 的 \(G\) 个 rollout 很容易全部正确（\(r_i \equiv 1\)）或全部错误（\(r_i \equiv 0\)）。此时组内标准差为 0，advantage 分母除零，梯度信号为零。见 6.7 推导 · 4.4（rewards=[0,0] 时 loss 恰为 0）和 6.2 推导里 DAPO 的「filter out zero-gradient examples」。
