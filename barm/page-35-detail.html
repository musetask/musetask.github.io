4.6 多项式抽样：\(P(x_i) = p_i\) 与「0.40 是 0.10 的 4 倍」

4.4 的推导只走到了 softmax + temperature，从分布到「抽一个」这一步是空的。原文在这里直接说「0.40 的 token 是 0.10 的 4 倍」，却没给推导。这一页把这一步补上：抽样本身的定义、那句 4 倍怎么来的、torch.multinomial 的确切语义，以及 1,000 次抽样的实验数字能不能被理论值预测。

一、定义：多项式（分类）抽样

设词表 \(V\) 上有一个已归一化的概率分布 \(\mathbf{p} = (p_1, \dots, p_{|V|})\)，满足 \(p_i \ge 0\) 且 \(\sum_i p_i = 1\)。多项式抽样（分类抽样，categorical sampling）就是：随机取一个类别 \(I\)，使得

\[ \Pr(I = i) = p_i, \qquad i = 1,\dots,|V| \]

注意这里没有任何额外结构——不需要排序、不需要累积质量、不需要 top-p。这一步的数学内容极简，所有的复杂度都在前一步：p 本身是怎么算出来的（那才是 4.4 温度缩放和 4.5 top-p 过滤的内容）。

1.1 与「贪心解码」在数学上的区别

\[ I_{\text{greedy}} = \arg\max_i p_i \quad(\text{确定性，} \Pr(I) \text{ 是 } \delta\text{ 分布}), \qquad I_{\text{sample}} \sim \text{Categorical}(\mathbf{p}) \quad(\text{随机，} \Pr(I=i) = p_i) \]
温度为 0 时「温度」这个旋钮就失效了

贪心解码只看排名，完全不看分值。所以只要 temperature = 0，z / 0 无论怎么定义都不影响输出——温度缩放彻底不起作用。这正是 listing 4.8 里要写 if temperature is None or temperature == 0.0: next_token = torch.argmax(...) 走单独分支的原因。

二、「0.40 是 0.10 的 4 倍」这句话的推导

原文说：a token with probability 0.40 is four times as likely to appear as one with probability 0.10, but both remain possible outcomes。这句话有两个可检验的数学含义。

2.1 含义一：长期频率之比

做 \(n\) 次独立抽样，token \(i\) 出现次数为 \(N_i\)。由弱大数定律：

\[ \frac{N_i}{n} \xrightarrow[n \to \infty]{\text{几乎必然}} p_i \]

于是：

\[ \frac{N_{0.40}}{N_{0.10}} \xrightarrow[n \to \infty]{} \frac{0.40}{0.10} = 4 \]

这才是「4 倍」的严格含义：不是「一次抽样里更容易被选中」这种无法量化的说法，而是长期出现次数的比例。

2.2 含义二：单次抽样的比值没有意义

「4 倍容易」这个说法容易被误解成「一次抽到前者的概率是后者的 4 倍」——这当然是对的（\(0.40/0.10 = 4\)），但概率比 ≠ 可能性。用原文给的三个候选做具体演示：

token概率1,000 次抽样的期望次数标准差
"Berlin"0.7070014.5
"Munich"0.2020012.6
"Hamburg"0.101009.5

（单个 token 的出现次数服从二项分布 \(N_i \sim \text{Binomial}(1000, p_i)\)，\(\mathrm{Var} = np(1-p)\)。）

结论：三个 token 全部都会出现，只是次数不同。Hamburg 出现 0 次的概率是

\[ (1 - 0.10)^{1000} = 0.9^{1000} \approx e^{1000 \ln 0.9} = e^{-105.36} \approx 1.7\times 10^{-46} \]

——约等于不可能。「但 both remain possible outcomes」不是修辞，是字面上的意思。

三、怎么实现一次抽样

3.1 逆 CDF 法（累积分布反演）

把概率排序，令 \(F_k = \sum_{i\le k} p_i\)（\(F_{|V|} = 1\)，即 CDF）。抽一个 \(u \sim \text{Uniform}(0,1)\)，返回

\[ I = \min\{k : F_k > u\} \]

验证：对任意 \(i\)，

\[ \Pr(I = i) = \Pr(F_{i-1} \le u < F_i) = F_i - F_{i-1} = p_i \quad\blacksquare \]

干净利落。注意这个推导用到了 \(\text{Uniform}(0,1)\) 与 CDF 的关系——这正是 4.5 节里 torch.cumsum 那个技巧的理论依据，也是为什么 top-p 只需要一次 cumsum。

3.2 Gumbel-max 法（softmax 的另一种用法）

还有一个等价且优雅的实现。若 \(g_i \overset{\text{iid}}{\sim} \text{Gumbel}(0,1)\)，则

\[ I = \arg\max_i \big(\log p_i + g_i\big) \]

同样满足 \(\Pr(I = i) = p_i\)（Gumbel-max trick）。由于 \(g_i = -\log(-\log u_i)\)，这等价于把随机数 \(u_i\) 代入逆 CDF。这个式子在实践中极重要：温度缩放的 \(p_i = e^{z_i/T}/\sum_j e^{z_j/T}\) 代入后，\(\log p_i = z_i/T + \text{const}\)，于是

\[ I = \arg\max_i \left(\frac{z_i}{T} + g_i\right) \]
这才是「logits → 采样」最紧凑的写法

取对数把 softmax 消掉了，整个采样退化成「加噪声后的 argmax」。对照来看：

  • \(T \to 0\)：\(\frac{z_i}{T}\) 爆炸，噪声被淹没 → 退化为 argmax（贪心）。
  • \(T \to \infty\)：只剩噪声 → 均匀随机（\(1/|V|\)）。

这正是 4.4 推导页里那两个极限的另一个证明角度——从采样算子本身看，而不是从概率比看。

四、torch.multinomial 的确切语义

next_token = torch.multinomial(probas.cpu(), num_samples=1)
行为说明
输入要求非负、不需要归一化到 1（内部自己会归一化）
num_samples > 1有放回（with replacement）：k 个样本相互独立，都服从同一个 \(\mathbf{p}\)
replacement=False无放回抽 k 个不同类别（此时 k 不能超过非零类别的个数）
返回形状 [batch, num_samples] 的 token id，不是概率

所以「多项式抽样」这个名词要小心：它不是在描述「抽 \(k\) 个」的分布（那是多项分布 \(\text{Multinomial}(n,\mathbf{p})\)），而是在描述抽一个的机制。抽 \(n\) 次的计数向量才服从多项分布：

\[ (N_1, N_2, \dots, N_{|V|}) \sim \text{Multinomial}\!\left(n;\ p_1, \dots, p_{|V|}\right) \] 
print("Sampled token:", torch.multinomial(next_token_probas.cpu(), num_samples=1))
为什么必须 .cpu()：原文把抽样放在 CPU 上并说明原因——torch.multinomial() 在 CUDA 和 MPS 上的实现与 CPU 不一致，作者在 PyTorch 2.9 上观察到 num_samples 较大时甚至会崩溃。抽样是整个流程里唯一一个「不可复现就是 bug」的环节，放在 CPU 是为了让 torch.manual_seed(123) 真正生效。

五、原文实验的定量检验

5.1 温度 5.0：为什么「没有一个 token 出现超过 2 次」

在这个温度下 " Berlin" 的概率是 0.0003（4.4 推导页算过）。抽 1,000 次，它出现 \(N\) 次满足 \(N \sim \text{Binomial}(1000, 0.0003)\)，均值 \(\lambda = 0.3\)：

\[ \Pr(N \le 2) \approx e^{-\lambda}\left(1 + \lambda + \frac{\lambda^2}{2}\right) = e^{-0.3}(1 + 0.3 + 0.045) = 0.9964 \]
这就是原文实验结果的解释

99.6% 的概率下 " Berlin" 出现不超过 2 次——而这正是原文列出的结果：每个 token 都是 2x、2x。输出里一堆无意义的 token（' represent'、' Inf'、' beside'）也同样如此：它们的概率都很小，各自被抽中 1~2 次后，剩下的次数被其它长尾 token 分掉。

所以 count_samples 的输出不是「采样不准」，而是 T = 5.0 把分布压得太平之后的忠实结果。

5.2 温度 0.35：435 次与理论值一致吗

原文说 probas_lowT[0, 19846] 约等于 42%，而 1,000 次抽到 435 次。检验：

\[ \hat{p} = \frac{435}{1000} = 0.435, \qquad \sigma = \sqrt{\frac{p(1-p)}{n}} = \sqrt{\frac{0.42 \times 0.58}{1000}} = 0.0156 \] \[ z = \frac{0.435 - 0.42}{0.0156} = +0.96 \]

0.96 个标准差，完全在预期范围内。实验和理论对得上。

其余 token 同样符合：' ______' 209 次、' ____' 169 次、' __' 158 次、Munich 和 Hamburg 各 3 次。把 7 个主要 token 的经验频率代回熵公式（见 7.3 推导）：

\[ H = -\sum_i \hat{p}_i \log \hat{p}_i \approx 1.3884 \ \text{nats} = 2.0031 \ \text{bits} \]

也就是说 1,000 次抽样的结果里有约 2 个比特的不确定性。这个数可以直接读作「模型在这个位置有多确定」——也正是 7.3 节里用熵做训练崩溃早期信号的那个量。

T = 0.35 和 T = 5.0 的本质差别只有一个

温度缩放 把概率比变成了 \(e^{\Delta/T}\)。当 \(T\) 从 5 降到 0.35（14 倍），任何一对 token 的概率比都被指数放大 14 倍。于是原本平坦的长尾被压缩，采样结果从「一堆噪声」变成「' Berlin' 为主 + 几个合理的城市名 + 几个来自 quiz 模板的下划线」。

注意 T = 0.35 < 0.8（self-consistency 用的值），这符合预期：这一节是在演示「温度确实在起作用」，不是推荐这个值。原文在「Choosing temperature settings」里给的经验区间是 0.3–0.8。

六、这一节与 self-consistency 的因果关系

  1. 4.6 的抽样提供随机性。单次结果仍然是错的（原文跑出 \(\boxed{x = \frac{90}{7}}\)，正确答案是 83）。
  2. 4.4 的温度控制随机性的大小。T → 0 就没有随机性，self-consistency 退化为单次生成。
  3. 4.5 的 top-p清理长尾，防止随机性把输出带偏到完全无关的 token。
  4. 多数投票把「单次会错」变成「多数会对」。这是第 4 章 self-consistency 的全部机制。
为什么不是温度越大越好：投票的准确率取决于「正确答案在 \(N\) 次采样中的票数占比」。温度过低 → \(N\) 个答案完全一样，占比退化为 1/1（若答案错则必错）；温度过高 → \(N\) 个答案都是噪声，占比接近均匀，投票 ≈ 随机猜。最优温度让占比在「略高于 1/2」和「远高于 1/2」之间——这正是 0.8 这类经验值的来源。
