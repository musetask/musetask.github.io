4.5 top-p（nucleus）过滤：完整数学推导

上一页的 temperature 调节的是整个分布的陡峭程度，但它对所有 token 一视同仁。top-p 解决的是另一个问题：不管分布多陡，都要先砍掉那些「就算概率最高也荒谬」的尾部 token。 两者叠加使用，是 self-consistency 能工作的最后一块拼图。

一、定义

把概率按降序排序，取累积概率质量刚好达到或超过 \(p\) 的最小 token 集合：

\[ S = \min\Big\{ k \;:\; \sum_{i=1}^{k} p_{(i)} \ge p \Big\} \]

其中 \(p_{(i)}\) 表示排序后第 \(i\) 大的概率。保留 \(p_1, \dots, p_S\)，其余置 0，再重新归一化使其和为 1，然后从这 \(S\) 个里采样。

top-p 的设计哲学

它保留的是自适应数量的 token：分布尖锐时只留 1–2 个，分布平坦时留几十上百个。而 top-k 保留固定数量。

这正是原文的对比：top-k keeps a fixed number of the most likely tokens, whereas top-p keeps a variable number of tokens depending on their cumulative mass. 分布不确定时 top-k 会强行保留 50 个垃圾 token，top-p 则不会。

二、代码里的累积和技巧

原文用一个略有技巧的写法：

sorted_idx   = torch.argsort(toy_probas, descending=True)
sorted_probas = toy_probas[sorted_idx]
cumsum = torch.cumsum(sorted_probas, dim=0)

keep_mask = (cumsum - sorted_probas) < top_p   # 加入前还不够 p → 必须保留（含越界项）
n_kept = keep_mask.sum().item()

常见的两种写法并不等价，差别就在「刚好把累积质量推过 \(p\) 的那个 token」要不要留：

keep_mask = (cumsum - sorted_probas) < top_p   # 本书采用：包含越界项（nucleus 标准做法）
keep_mask = cumsum <= top_p                     # 另一种：不含越界项（更保守，集合可能 < p）

2.1 cumsum - sorted_probas 是什么意思

这是这一节唯一的技巧，值得单独讲。设排序后概率为 \(q_1, q_2, \dots\)，定义：

\[ c_k = \sum_{i=1}^{k} q_i \]

那么：

\[ (c_k - q_k) = \sum_{i=1}^{k-1} q_i \]

就是前 \(k-1\) 个 token 的累积质量，不含第 \(k\) 个自己。

那么 keep_mask = (cumsum - sorted_probas) < top_p 就是在问：「我加入这个 token 之前，累积质量还不到 \(p\) 吗？」如果是，说明我需要它来把质量凑到 \(p\)，必须保留。

token（降序）\(q_i\)\(c_i\)\(c_i - q_i\)\(< 0.8\) ?保留
10.45380.45380.0000✓✅
20.27520.72900.4538✓✅
30.08290.81190.7290✓✅
40.02500.83690.8119✗❌
…………✗❌

所以答案 n_kept = 3，与原文一致。截断点在第 3 和第 4 之间，因为 \(c_3 = 0.8119 \ge 0.8\)。

注意：判断的是「加入之前」

(cumsum - sorted_probas) < top_p 问的是「不含自己时累积质量是否还不够 \(p\)」。所以越界的那一项会被留下——这正是 nucleus sampling 的标准定义，保证留下的集合质量 \(\ge p\)。

若改成 cumsum <= top_p，越界项会被砍掉，集合质量可能严格小于 \(p\)。两种写法不要混着记。

三、置零与重新归一化

kept_sorted = torch.where(keep_mask, sorted_probas, torch.zeros_like(sorted_probas))
filtered = torch.zeros_like(toy_probas).scatter(0, sorted_idx, kept_sorted)
# filtered = [0, 0, 0, 0, 0.4538, 0, 0, 0, 0.0829, 0.2752]

denom = torch.sum(filtered).clamp_min(1e-12)
renormalized = filtered / denom
# [0, 0, 0, 0, 0.5589, 0, 0, 0, 0.1021, 0.3390]

3.1 为什么必须重新归一化

置零后总和是 \(0.8119\)，不是 1。torch.multinomial 要求概率分布和为 1，所以要除以实际总和：

\[ \tilde{p}_i = \begin{cases} \dfrac{p_i}{\sum_{j \in S} p_j} & i \in S \\[6pt] 0 & i \notin S \end{cases} \]

验算：\(0.4538 / 0.8119 = 0.5589\)，\(0.0829 / 0.8119 = 0.1021\)，\(0.2752 / 0.8119 = 0.3390\)。✓

.clamp_min(1e-12) 防什么？如果 keep_mask 一个都没保留（极端情况下所有概率都很小，比如 top_p 设得极小），denom 会是 0，导致 0/0 = NaN。clamp_min 给一个下界防止除零。这是工程细节，但值得知道。

3.2 scatter 为什么要还原顺序

整个流程是「排序 → 过滤 → 再排回去」。原因：词表索引顺序是有意义的，模型输出层的第 \(i\) 个分量永远对应第 \(i\) 个 token。我们只是在排序后的临时空间里做计算，最终必须映射回原始位置，否则概率会安到错误的 token 上。

filtered = torch.zeros_like(toy_probas).scatter(0, sorted_idx, kept_sorted)
#          ↑ 造一个全 0 的目标形状        ↑ 按 sorted_idx 把值放回去

四、top-p 和 temperature 怎么配合

它们控制的是分布的不同维度：

temperaturetop-p
作用位置softmax 之前，缩放 logitssoftmax 之后，截断概率
控制什么分布的整体陡峭程度候选集合的大小
效果连续调节多样性硬性砍掉长尾
失效模式T 太大 → 全是垃圾；T 太小 → 无多样性p 太大 → 退化成全词表；p 太小 → 只剩 argmax

原文的完整生成函数把它们串在一起（listing 4.16）：

if temperature is None or temperature == 0.0:
    next_token = torch.argmax(out, dim=-1, keepdim=True)   # 贪心
else:
    logits = scale_logits_by_temperature(out, temperature)   # ① 缩放
    probas = torch.softmax(logits, dim=-1)                    # ② 归一化
    probas = top_p_filter(probas, top_p)                      # ③ 截断 + 重归一
    next_token = torch.multinomial(probas.cpu(), num_samples=1)  # ④ 采样

原文的实测（temperature=0.5, top_p=0.8）：输出 \boxed{18}，仍然错误。「能采样出不同答案」和「采样出正确答案」是两件事——前者是手段，后者要看 4.6 的投票。

和 self-consistency 的关系

4.6 节要采样 N=8（或更多）个不同答案做投票。质量靠 top-p 保证下限（不采到荒谬 token），多样性靠 temperature 保证（每次不完全一样）。两个都必须有：

只调温度不打分 → 可能全是垃圾；不打分只调温度 → 高温时仍会采到长尾里的怪东西。

五、一个数值例子走完全程

用原文的 toy_probas（长度 10，top_p = 0.8）：

  1. 排序：argsort(descending=True) → 索引 [4, 9, 8, ...]，概率 [0.4538, 0.2752, 0.0829, 0.0250, ...]
  2. 累积：cumsum = [0.4538, 0.7290, 0.8119, 0.8369, ...]
  3. 判断：cumsum - sorted_probas = [0, 0.4538, 0.7290, 0.8119, ...]，前三个 < 0.8
  4. n_kept = 3，截断点在 token 3 与 4 之间（\(c_3 = 0.8119 \ge 0.8\)）
  5. 置零还原：[0,0,0,0, 0.4538, 0,0,0, 0.0829, 0.2752]
  6. 重归一：除以 0.8119 → [0,0,0,0, 0.5589, 0,0,0, 0.1021, 0.3390]
  7. 采样：只会命中索引 4、8、9
