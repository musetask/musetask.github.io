7.5 KL 正则项：完整数学推导与它的失效模式

这是全书最有价值的一节，因为它展示了一个更少见的现象：一个理论上正确、实践中却会毁掉训练的组件。作者不仅实现了 KL 项，还诚实地记录了它怎么失败、以及为什么数学任务上干脆不用它。

一、KL 散度是什么

1.1 定义

KL 散度（相对熵）衡量两个概率分布的差异：

\[ D_{\text{KL}}(P \| Q) = \sum_{v} P(v) \log \frac{P(v)}{Q(v)} \]

在 LLM 上下文里，两个分布都是每个位置的 next-token 分布，所以是词表上的求和（151,936 项）。

1.2 两个关键性质

性质数学含义
非负\(D_{\text{KL}}(P\|Q) \ge 0\)，等号当且仅当 \(P = Q\)可以用来做惩罚项
不对称\(D_{\text{KL}}(P\|Q) \neq D_{\text{KL}}(Q\|P)\)方向有讲究，见第三节
不归一化可以 \(> 1\)，无上界量级需要用 \(\beta\) 调

1.3 拆开之后是两项；代码只保留了其中一项的采样版

用恒等式 \(\log \frac{P}{Q} = \log P - \log Q\) 拆开：

\[ \begin{aligned} D_{\text{KL}}(P \| Q) &= \sum_v P(v)\, \log\frac{P(v)}{Q(v)} \\[4pt] &= \sum_v P(v)\big(\log P(v) - \log Q(v)\big) \\[4pt] &= \underbrace{\sum_v P(v)\log P(v)}_{=\,-H(P)} - \sum_v P(v)\log Q(v) \end{aligned} \]

第一项是负熵。所以精确 KL 是两项：

\[ \boxed{\; D_{\text{KL}}(P\|Q) = -H(P) - \mathbb{E}_{v \sim P}\big[\log Q(v)\big] \;} \]

也可以写成期望差：

\[ D_{\text{KL}}(P\|Q) = \mathbb{E}_{v \sim P}\big[\log P(v) - \log Q(v)\big] \]
这就是代码里 mean(new_logps - ref_logps) 的来源——以及它缺了什么

精确 KL 要对整个词表求期望。代码只在已经采样出来的那几个 token 上算 \(\log\pi_\theta - \log\pi_{\text{ref}}\)，既没有对词表求和，也没有用 \(\pi_\theta\) 自己的分布做加权——这是一个采样式代理（sampled surrogate），不是精确 KL。原文对此有明确说明，见第四节。

二、KL 项在 GRPO 里的角色

2.1 目标函数

\[ \mathcal{L} = \underbrace{-\frac{1}{N}\sum_{i=1}^{N}\min\big(\rho_i A_i,\; \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon)A_i\big)}_{\text{7.4 裁剪}} + \underbrace{\beta\, \hat{D}_{\text{KL}}\big(\pi_\theta \,\|\, \pi_{\text{ref}}\big)}_{\text{7.5 KL}} \]

\(\beta\)（代码里的 kl_coeff）控制正则强度，默认为 0.02。

2.2 代码实现

kl_coeff = 0.0
if kl_coeff:
    ref_model = copy.deepcopy(model).to(device)   # 参考模型 = 训练开始时的模型
    ref_model.eval()
    for p in ref_model.parameters():
        p.requires_grad = False             # 不需要梯度
else:
    ref_model = None
# 采样阶段：顺便算参考模型的 logprob
if kl_coeff:
    with torch.no_grad():
        ref_logp = sequence_logprob(ref_model, token_ids, prompt_len)
else:
    ref_logp = None
# loss 阶段
pg_loss = -(advantages.detach() * logps).mean()
if kl_coeff:
    kl_loss = kl_coeff * torch.mean(logps - ref_logps)   # ⚠ 见第三节
else:
    kl_loss = torch.zeros_like(pg_loss)

2.3 两个技术细节

  1. copy.deepcopy 而不是 ref_model = model：必须是独立副本，否则引用同一个对象，参数会被一起更新，KL 恒为 0。
  2. ref_logps 也要 .detach()：参考模型已经 requires_grad=False，但显式 detach 更清晰（且 sequence_logprob 内部没有 no_grad）。

\(\pi_{\text{ref}}\) 的更新频率：训练开始时固定，或很少更新（DeepSeek-R1 是每 400 步）。这和 7.4 的裁剪比率不同——后者每轮都换参考。

三、方向问题：new - ref 不是 old - new

原文专门开了一小节讲这个（page 70 的 "KL direction versus rollout sampling"），因为这里有个真实的不一致。

你想度量的应该用的差
当前策略 vs 旧采样策略→old_logps - new_logps
当前策略 vs 固定参考策略→new_logps - ref_logps ✅ 本书用这个

但问题在于：rollout 是用 old_policy 采的，不是用 ref_policy 采的。而 KL 正则想约束的是「当前策略离固定参考有多远」。

原文的核心批评

「The subtlety is that the responses are generated by the old rollout policy, not by the current policy after the update. Therefore, mean(new_logps - ref_logps) is a simplified sampled surrogate rather than an exact KL estimate.」

一个严格的做法需要重要性采样修正（importance-sampling correction）——而 DAPO / DeepSeek-V3.2 的改进项 #9「Reweight the KL term with importance sampling」正是干这个的。

3.1 长度敏感性

因为代码用的是 mean（不是 sum），看起来做了长度归一化。但原文指出问题更深：

because the rollouts are sampled from the old policy, this simple sampled surrogate is not an exact KL estimate for the current policy unless we either sample from the current policy or apply an importance-sampling correction. As a result, the objective becomes length sensitive, which can bias training toward longer outputs in some cases, as suggested by the growing response length here, and can destabilize training.

也就是说：错误的估计方式引入了长度依赖，而这个长度依赖的符号是「偏向更长」，与 6.8 节序列 logprob 的「偏向更短」方向相反，两个效应互相打架。

四、失效模式：reward 崩塌后 KL 独大

这是本节最重要的实验观察。

4.1 现象

原文 7.5.2 的实验：训练跑到大约第 200 步，reward 全部塌到 0，最终 eval 准确率跌到 0.0%。

4.2 为什么会这样：梯度来源分析

关键在于训练后期各梯度项的贡献：

阶段rewardadvantagePG 梯度KL 梯度
step < 200> 0非零提供梯度辅助
step > 200= 0= 0无梯度独大

因为 \(\mathcal{L}_{\text{pg}} \propto A_i\)，所有 reward 都为 0 时 advantage 全为 0，PG 项完全不贡献梯度（这就是 6.7 节的零 advantage 情形）。KL 项成了唯一的梯度来源。

4.3 致命的一步：符号

现在看 KL 项在固定 token 上的梯度方向。损失是：

\[ \mathcal{L}_{\text{KL}} = \beta \cdot \frac{1}{T}\sum_{t} \Big[\log \pi_\theta(y_t) - \log \pi_{\text{ref}}(y_t)\Big] \]

要最小化它，就要压低\(\log \pi_\theta(y_t)\)——也就是降低模型给已经采样出来的那些 token 的概率。

这是反直觉的部分

你可能以为「拉回参考策略」会让分布回到原样。但这里有个致命区别：KL 项只作用在已经采样出来的那几个 token 上，而 ref_logps 在优化过程中是常数。

压低几个已采样 token 的概率，会让概率质量转移到没被采样的其他 token 上——下一 token 分布变得更平坦，熵上升，输出越来越随机。

原文的表述：

On those fixed sampled tokens, minimizing the loss mainly pushes down the current model's probability on the sampled actions, which can make the next-token distribution more spread out and raise entropy. The observed behavior is better understood as a failure mode of this sampled surrogate, which can lead to increasingly random outputs and the drop to 0.0% evaluation accuracy. If you want, you can plot the other evaluation metrics, such as policy_ratio, adv_avg, adv_std, and entropy_avg, and confirm that the entropy becomes very large.
验证方法

如果你的理解对了，那么 entropy_avg 曲线在训练后期应该剧烈上升。作者邀请读者自己去画图确认——这是一个可以直接做的自检实验，跑 7_5_plus_kl.py 然后画这四个指标。

4.4 对比：精确的 KL-to-reference 会怎样

原文明确对比了两种情况：

精确的 KL-to-reference本书的 sampled surrogate
优化对象整个 next-token 分布仅已采样的 token
reward 崩塌后把分布拉回参考（恢复能力）压低已采样 token，熵升（更糟）

关键差异：精确 KL 是把整个分布拉回去；sampled surrogate 只是「不涨」，反而可能更随机。在 reward 已经崩塌、PG 项失效的情况下，这个差异是致命的。

五、实践结论：数学任务上直接关掉

原文的最终判断，以及 6.10 里那句「我们故意省略了 KL 项」：

For math reasoning tasks, several recent systems report better stability and performance by omitting the KL term altogether.
