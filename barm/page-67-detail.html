7.4 裁剪策略比率：完整数学推导

6.9 的策略梯度损失假设「采样时的策略」就是「当前策略」。这个假设只在采完样立刻更新一次时成立。7.4 引入裁剪比率，就是为了让同一批数据被反复使用多次时训练不发散。

一、要解决什么问题

原始策略梯度（6.9）：

\[ \mathcal{L}_{\text{pg}} = -\frac{1}{N}\sum_{i=1}^{N} A_i \log \pi_\theta(y^{(i)} \mid x^{(i)}) \]

隐含假设：算 logprob 的 \(\pi_\theta\) 就是产生这些 rollout 的策略。问题在于真实训练要复用数据：

  1. 用 \(\pi_{\theta_{\text{old}}}\) 采样一批 rollout，算出 \(A_i\)
  2. 用同一批数据更新 \(\theta\)
  3. 如果还要再更新一次，此时的 \(\pi_\theta\) 已经变了，但 \(A_i\) 却是按旧策略的优劣算的

这叫 off-policy 问题。$A_i$ 属于旧策略，拿它来评价新策略的行为是错的。

二、策略比率 policy ratio

2.1 定义

用概率之比来衡量新旧策略的差异：

\[ \rho_i = \frac{\pi_\theta(y^{(i)} \mid x^{(i)})}{\pi_{\theta_{\text{old}}}(y^{(i)} \mid x^{(i)})} \]

比值的好处是与序列长度无关。如果要直接比概率，$T_i$ 不同的两条序列根本没法比；比值则自动约掉了长度效应。

2.2 从 logprob 算出来

因为 \(\log\) 和除法可以互换：

\[ \log \rho_i = \log \pi_\theta - \log \pi_{\theta_{\text{old}}} \quad\Longrightarrow\quad \rho_i = \exp\big(\log \pi_\theta - \log \pi_{\text{old}}\big) \]
预备知识：对数与指数的互逆

\(\log(a/b) = \log a - \log b\)（\(a,b>0\)），且 \(\exp(\log x) = x\)。于是 \(\rho_i = \pi_\theta/\pi_{\text{old}}\) 取对数得 \(\log\rho_i = \log\pi_\theta - \log\pi_{\text{old}}\)，再取指数即回到 \(\rho_i\) 本身——"取 log 做减法再 exp 回去"不改变值，只改变数值稳定性。

new_logps = logprobs                                       # 假想更新后的模型
old_logps = torch.tensor([-10.9243, -20.3546, -14.6130, -23.3677])

log_ratio = new_logps - old_logps
ratio     = torch.exp(log_ratio)
print("Ratio:", ratio)
# tensor([20.0855, 1.2214, 0.1353, 1.0000])

2.3 验算第一项

\[ \rho_1 = \exp(-7.9243 - (-10.9243)) = \exp(3.0) = 20.0855 \]

含义：更新后的模型给这条（正确的）回答的概率，是旧模型的 20 倍。

i回答正确?\(\log\pi_{\text{new}}\)\(\log\pi_{\text{old}}\)\(\log\rho\)\(\rho\)
1\boxed{83}✅−7.92−10.92+3.020.09
2The correct answer is \boxed{83}✅−20.15−20.35+0.21.22
3The final answer is 83❌−16.61−14.61−2.00.135
4We get \boxed{38}❌−23.37−23.370.01.00

四个数字的解读：

  • \(\rho = 1.0\)（第 4 行）表示「完全没变」，这是参照点。
  • \(\rho > 1\) 表示新策略更倾向于这条序列。
  • \(\rho < 1\) 表示新策略更不倾向于这条序列。
  • \(\rho\) 是指数，所以 \(\log\rho\) 差 3.0 就是 20 倍，差 2.0 就是 \(e^2 = 7.4\) 倍。logprob 的小变化会被放大成比率的大变化——这正是需要裁剪的原因。
为什么用 exp 而不直接比

因为序列概率小到 \(e^{-23}\) 这个量级，直接相除两个这么小的浮点数会损失精度。取 log 后做减法，再 exp 回去，数值稳定性好得多。

三、裁剪

3.1 公式

把比率限制在 \([1-\epsilon,\; 1+\epsilon]\) 区间内：

\[ \text{clip}(\rho_i,\, 1-\epsilon,\, 1+\epsilon) = \min\big(\max(\rho_i,\; 1-\epsilon),\; 1+\epsilon\big) \]
预备知识：\(\min(\max(\cdot))\) 就是"掐头去尾"

内层 \(\max(\rho_i, 1-\epsilon)\)：若 \(\rho_i\) 小于下界就抬到下界；外层 \(\min(\cdot, 1+\epsilon)\)：若超过上界就压到上界。合起来 \(\rho_i\) 被强制落进 \([1-\epsilon,\,1+\epsilon]\)，区间内的值原样不动。

clip_eps = 10.0   # DeepSeek-R1 用的值，非常宽松
clipped_ratio = torch.clamp(ratio, 1.0 - clip_eps, 1.0 + clip_eps)
print("Clipped ratio:", clipped_ratio)
# tensor([11.0000, 1.2214, 0.1353, 1.0000])

只有第 1 项被裁了：\(20.0855 \to 11.0000\)。其余三项的 \(\rho\) 都落在 clamp 区间 \([1-\epsilon,\,1+\epsilon]=[-9,\,11]\) 内（\(\rho\) 本身恒正，实际有效下界是 0；这个区间极宽，因为 \(\epsilon = 10\)）。

3.2 裁剪的完整目标函数

PPO / GRPO 的裁剪目标是两项取 min，这一点很容易被忽略：

\[ \mathcal{L}_{\text{clip}} = -\frac{1}{N}\sum_{i=1}^{N} \min\Big(\rho_i A_i,\;\; \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon)\, A_i\Big) \] 
adv = advantages.detach()
unclipped = ratio * adv
clipped   = clipped_ratio * adv
obj = torch.minimum(unclipped, clipped)
clipped_pg_loss = -torch.mean(obj)
为什么是 min 不是 max

因为外层有负号。RL 想最大化 \(\min(\rho_i A_i, \text{clip}(\cdot) A_i)\)，而 PyTorch 要最小化，所以取负。

「min」这个选择的巧妙之处：它只在让目标变好的那个方向上起作用——裁掉过于激进的改进，但保留过于保守的退步。这叫 pessimistic bound（悲观界）。

3.3 逐项看 min 在做什么

\(\rho A\)（unclipped）\(\rho_{\text{clip}} A\)min 取梯度的实际影响
\(A > 0,\ \rho = 20.09\)\(0.8659 \times 20.09 = 17.39\)\(0.8659 \times 11 = 9.53\)9.53✅ 正确但概率暴涨 → 限制继续推高
\(A > 0,\ \rho = 1.22\)\(1.06\)\(1.06\)1.06没被裁 → 正常推高
\(A < 0,\ \rho = 0.135\)\(-0.8659 \times 0.135 = -0.117\)−0.117−0.117没被裁（\(-9 \le 0.135\)）→ 正常压低
\(A < 0,\ \rho = 1.0\)\(-0.8659\)−0.8659−0.8659没被裁 → 正常压低
推导：\(\min\) 在 \(A>0\) 与 \(A<0\) 时各取哪一边

关键点：\(\min\) 里两项都含有因子 \(A\)，而 \(A\) 的符号会翻转不等式方向。记 \(c(\rho) = \mathrm{clip}(\rho, 1-\epsilon, 1+\epsilon)\)。

情形一：\(A > 0\)。此时 \(\min(\rho A, c(\rho)A) = A\cdot\min(\rho, c(\rho))\)。因为 \(c(\rho) \le 1+\epsilon\) 恒成立：

\[ \min(\rho A, c(\rho)A) = A\cdot\min(\rho,\,1+\epsilon) = \begin{cases}\rho A & \rho \le 1+\epsilon \\ (1+\epsilon)A & \rho > 1+\epsilon\end{cases} \]

即只在"变好太多"（\(\rho\) 冲破上界）时被按住；\(\rho\) 偏小（更新让好答案变差了）时不干预——对应上表第 2 行"没被裁"（第 3、4 行是 \(A<0\) 的情形，见下）。

情形二：\(A < 0\)。乘以负数翻转方向，\(\min(\rho A, c(\rho)A) = A\cdot\max(\rho, c(\rho))\)。因为 \(c(\rho) \ge 1-\epsilon\) 恒成立：

\[ \min(\rho A, c(\rho)A) = A\cdot\max(\rho,\,1-\epsilon) = \begin{cases}\rho A & \rho \ge 1-\epsilon \\ (1-\epsilon)A & \rho < 1-\epsilon\end{cases} \]

即只在"变坏太多"（\(\rho\) 跌破下界）时被托住；\(\rho\) 偏大（坏答案概率反而上升）时不干预。

合起来：\(\min\) 永远取"让目标函数更小的那一边"——裁掉过于激进的改进，保留过于保守的退步，这就是上文 warn 框里"悲观界（pessimistic bound）"的数学含义。

3.4 算一下完整 loss

\[ \mathcal{L}_{\text{clip}} = -\frac{1}{4}\left[9.53 + 1.06 - 0.117 - 0.8659\right] = -\frac{9.6071}{4} \approx -2.3998 \]

对上原文的 -2.3998。✓

注意：不要拿它去和 6.9 的 -2.5764 比——那是另一套公式 \(-\mathrm{mean}(A\cdot\log\pi)\)。这里正确的「未裁剪对照」是同一目标函数里去掉 clip 的版本：

\[ \mathcal{L}_{\text{unclipped}} = -\frac{1}{4}\big[17.392 + 1.058 - 0.117 - 0.866\big] = -\frac{17.467}{4} \approx \mathbf{-4.367} \]

两者之差全部来自第 1 项：\((17.392 - 9.525)/4 \approx \mathbf{1.967}\)。只有一项被裁，但这一项本身从 20 倍压到 11 倍，对 loss 的贡献仍然不小。

和原文数字的关系：原文同时打印了简化版 pg loss（\(-2.5764\)）和 clipped loss（\(-2.3998\)），并说差异小是因为 clip_eps=10 太宽松。那句话针对的是「本例只有一项触发了裁剪」；但若拿同一目标函数的 clipped / unclipped 对比，差异其实是 1.967，并不小——宽松的 \(\epsilon\) 只保证「很少触发」，一旦触发，单次裁掉的幅度仍然可以很大。

四、为什么需要裁剪

原文的解释：

If the new model suddenly assigns a much higher or much lower probability to a rollout than the old model, the raw ratio can become very large or very small. Without clipping, this would scale the advantage term substantially, which could lead to a very large gradient step that might destabilize training.
三重的放大效应

看第 1 行：\(\log\pi\) 变了 3.0，\(\rho\) 变成 20 倍，再乘上 \(A = 0.87\) 得到 17.4。logprob 空间里一个很小的移动，经过 exp 和乘 advantage 之后变成一个巨大的 loss 项——这个 loss 项会产生巨大的梯度，可能一步就把模型推到很远的地方。

后果：token 概率剧变 → reward 崩塌、熵坍缩，或者输出变得不稳定。原文列举了这三种症状。

4.1 policy_ratio 作为监控指标

policy_ratio = torch.mean(ratio)   # 5.6106
\[ \frac{20.0855 + 1.2214 + 0.1353 + 1.0000}{4} = 5.6106 \]

这个值在训练中被持续跟踪。远大于 1 说明更新步子迈得太大（模型大幅提高了对采样 token 的概率），是训练可能崩掉的早期信号。

4.2 clip_eps 的取值谱系

场景clip_eps效果
DeepSeek-R1（本书 Ch7）10极弱裁剪，几乎不限制
RLHF / PPO0.1激进裁剪，每步策略变化很小

原文的观察：with this very generous clip_eps value of 10.0, only the first value is clipped from 20.0855 down to 11.0000.

数学 R1 + 数学任务 ≈ 关掉裁剪

当 \(\epsilon = 10\) 时裁剪区间是 \([1-\epsilon,\,1+\epsilon]=[-9,\,11]\)。clamp 作用在 \(\rho\) 本身，所以要让它真的起作用需要 \(\rho > 11\)（或 \(\rho < -9\)，但 \(\rho>0\) 不会发生）——即 \(\log\rho\) 超过 \(\log 11 \approx 2.4\) 才会触发。advantage 通常在 \([-1, 1]\)（第 7 章实测 adv_std ≈ 0.9998），但那不改变触发条件；它只影响被裁之后对 loss 的贡献大小。

这是数学任务上一个有意义的 clip_eps 值，但在通用 RLHF 里就相当于几乎不裁剪。

五、DeepSeek-R1 的实际做法

7.4.2 描述了两种数据复用策略：

DeepSeek-R1（大 rollout 池）本书的简化版
rollout 池一次生成 8,192 条每轮生成 8 条
minibatch切成 16 个不用切，inner_epochs 控制
参考模型更新每 400 步每轮
 
# DeepSeek-R1 的流程
1. 复制当前模型作为参考策略
2. 用参考策略采样大批量 rollout
3. 切成 minibatch
4. 对每个 minibatch:
      a. 用参考模型算 old_logps
      b. 用当前模型算 new_logps    # 每个 minibatch 后模型都变了
      c. 更新当前模型
5. 更新参考模型

# 本书 7_4_plus_clip_ratio.py 的流程
1. 复制当前模型作为参考策略
2. 采样 8 条 rollout
3. a. old_logps  b. new_logps  c. 更新
4. 重复 2-3（默认再来一次），但用新 rollout
5. 更新参考模型
step 4 的差异是本质的

DeepSeek-R1 在 16 个 minibatch 上反复用同一批固定 rollout，所以 new_logps 每次都不一样，\(\rho\) 逐步偏离 1——裁剪机制真正被激活。

本书每轮重新采样，所以 new_logps 每次都是从新 rollout 算的，inner_epochs=2 才是让 new ≠ old 的机制。原文诚实地说明：Due to resource constraints, we cannot generate as many rollouts and minibatches as DeepSeek-R1 does, so we'll use a smaller approximation.

六、和其他改进的关系

裁剪解决「步子迈太大」，但长期漂移是另一个问题——需要 KL 项。

机制参照对象作用范围对应小节
clipped ratio\(\pi_{\theta_{\text{old}}}\)（每轮更新）单步更新幅度7.4
KL 项\(\pi_{\text{ref}}\)（训练初期固定）长期漂移7.5

原文特别强调这个对比：In the clipped policy ratio section, we replaced the reference model in each iteration. For the KL loss term, the reference model used to compute the reference logprobs is the original model at the beginning of training, and it is either kept fixed or replaced relatively rarely (in the case of DeepSeek-R1, every 400 steps).
