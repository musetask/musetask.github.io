8.6 交叉熵损失：完整数学推导

第 6 章 GRPO 用的是序列 logprob（sum，不归一化）；第 8 章蒸馏用的是交叉熵（mean，归一化）。同一个量，除以不同的东西，变成了两个完全不同的目标函数。 这一页讲清楚这个转换，以及它为什么直接决定了蒸馏的效果。

一、从序列 logprob 到交叉熵

1.1 负号

交叉熵就是负的平均对数概率：

\[ \mathcal{L}_{\text{CE}} = -\frac{1}{T}\sum_{t=1}^{T} \log P_\theta(y_t \mid y_{<t}, x) \]

负号的作用和 6.9 一样：PyTorch 只最小化，而「模型更确信」对应 logprob 更大（即 loss 更小）。所以要取负，让「loss 小」等价于「模型对正确答案更有信心」。

1.2 用原文的例子算一遍

原文沿用第 5 章的 "The capital of Germany is Berlin"：5 个目标 token（capital、of、Germany、is、Berlin），序列 logprob = −16.6250。

\[ \mathcal{L}_{\text{CE}} = -\frac{-16.6250}{5} = \frac{16.6250}{5} = 3.325 \]

原文的数字：If −16.6250 is the log probability, the negative log probability is 16.6250, and the negative average log probability (or cross-entropy) is 16.6250/5 = 3.325.

关键性质：越接近 0 越好

因为 logprob 总是 \(\le 0\)（概率不超过 1），所以 CE 总是 \(\ge 0\)。CE = 0 当且仅当模型给每个正确答案的概率都是 1（完美记忆）。CE 越小，模型越接近完美。

1.3 为什么必须除以 T

with torch.no_grad():
    seq_logprob = sequence_logprob(model, tok, prompt_len)

num_answer_tokens = tok.numel() - prompt_len
avg_logprob = -seq_logprob / num_answer_tokens
print(f"Average logprob: {avg_logprob:.2f}")  # 1.68

原文的解释：Summed log probabilities grow with sequence length, so they are not directly comparable across examples with shorter or longer answers.

这一点和 6.8 节的 mean vs sum 完全不同，值得并排看：

GRPO（Ch6）蒸馏（Ch8）
目标最大化 好回答 的联合概率最小化 参考答案 的负对数似然
聚合方式summean
长度效应保留（长回答梯度更大）消除（长回答不被额外惩罚）
本质策略梯度，需要似然的真实尺度监督学习，需要跨样本可比的损失值
为什么蒸馏必须用 mean

因为蒸馏数据里各条样本长度差异巨大（原文例子里最短 236 token，最长 2048，平均 1180）。用 sum 的话，长样本的 loss 天然大得多，梯度会被长样本主导，模型实际只学会了模仿长推理的写法。

用 mean 后每条样本权重相同，无论长短。

二、用 torch.nn.functional.cross_entropy

2.1 标准 API

torch.nn.functional.cross_entropy(logits, target)
# logits: [N, C]   C = 词表大小，未归一化
# target: [N]      每个位置的正确类别（这里是真实 token ID）

注意 PyTorch 的 cross_entropy 内部已经包含了 log_softmax，所以要传原始 logits，不能传概率或 logprob（传了就变成 log-log）。

数学定义（对单条样本、忽略 batch 维度）：

\[ \mathcal{L}_{\text{CE}} = \frac{1}{N_{\text{positions}}}\sum_{i=1}^{N_{\text{positions}}} \left(-\log \frac{\exp(\text{logits}[i, \text{target}[i]])}{\sum_{v} \exp(\text{logits}[i, v])}\right) \]

它等价于 -(target * log_softmax(logits)).sum(dim).mean()，用交叉熵融合算子实现可以省内存。

2.2 关键：只算答案部分

input_ids  = tok[:-1].unsqueeze(0)   # 去掉最后一个，作为输入
target_ids = tok[1:]                    # 整体右移一位，作为标签

logits = model(input_ids).squeeze(0)

first_answer_logit_idx = max(prompt_len - 1, 0)
answer_logits   = logits[first_answer_logit_idx:]
answer_targets  = target_ids[first_answer_logit_idx:]

with torch.no_grad():
    ce_mean_direct = torch.nn.functional.cross_entropy(answer_logits, answer_targets)

2.3 两个切片各自在做什么

切片数学意义
tok[:-1] 作输入，tok[1:] 作标签标准的 next-token 错位：位置 \(i\) 的预测对应位置 \(i+1\) 的 token。和你在 GPT-2 那本书里写过的一样
[prompt_len-1:]切掉 prompt 部分。原文：the prompt is the context provided as input and not something we want the model to be penalized for reproducing
为什么不惩罚 prompt

prompt 是我们强加的输入，不是模型该生成的东西。如果把 prompt 也算进 loss，模型会被训练成「无条件复现 prompt」，这会破坏推理能力。原文的措辞很明确：we discard the logits and targets that correspond only to the prompt portion.

这和 5.6 节 logprob scorer「排除 prompt」是同一个理由，但这里的 stakes 高得多——5.6 只是打分，8.6 是在改权重。

max(prompt_len - 1, 0) 的防御：如果 prompt_len 是 0 或 1，prompt_len - 1 会是负数，PyTorch 切片会从末尾开始取（拿到错误的数据）。这个 max 避免了这个坑。

2.4 验证两个实现一致

原文分别用两种方式算，结果应当相同：

方式代码
手写-seq_logprob / num_answer_tokens → 1.68
PyTorchF.cross_entropy(answer_logits, answer_targets) → 1.68
这一步的意义

它把第 6 章的 sequence_logprob（手写、只求和）和 PyTorch 的标准 API 连起来了。确认 cross_entropy 内部做的事就是「log_softmax + 负平均 + 只在选中 token 上」——以后你在任何 PyTorch 代码里看到 cross_entropy，都可以直接映射回这个公式。

三、硬蒸馏 vs 软蒸馏

第 8.1 节区分了两种蒸馏：

硬蒸馏 hard distillation软蒸馏 soft distillation
训练目标teacher 的文本 tokenteacher 的概率分布（KL 散度）
损失交叉熵\(D_{\text{KL}}(P_{\text{teacher}} \| P_{\text{student}})\)
需要什么只需 teacher 生成的文本需要 teacher 的 logits（全词表分布）
本质合成数据上的 SFT传统知识蒸馏
本书采用✅❌

硬蒸馏的实际优势（原文的措辞）：our only need access to the teacher's generated text, not its logits。这在实践中是决定性的——teacher 的 logits 是 151,936 维，存储成本极高；文本则可以存 JSON 反复使用。

原文还有一条经验结论：Hard distillation is usually more practical than soft distillation，且 DeepSeek-R1 论文报告小模型上硬蒸馏比纯 RL 训练效果更好。

4.1 验证损失下降但准确率不升

注意 Qwen3 teacher 那三行：验证损失从 0.4043 一路降到 0.3948（一直在降），但准确率 45.0% → 43.8% → 44.2%（在 45 附近震荡，不升）。

损失不是准确率

交叉熵衡量的是「模型对 teacher 输出的模仿保真度」，不是「解题正确率」。两者只是弱相关：一条推理路径可以被完美模仿而结论仍是错的。

这解释了为什么第 3 章的 verifier 评测不可省略——训练 loss 好看不代表任务做得对。原文始终用 MATH-500 准确率作为最终判据，而不是用 loss。

4.2 teacher 家族的影响

DeepSeek-R1 teacher（33.6%）明显不如 Qwen3 235B-A22B teacher（45.0%）。原文的解释：the teacher and student come from the same model family, which means that the tokenizer, prompting conventions, and overall response style are more closely aligned.

数学上这来自 tokenizer 差异：不同模型的 BPE 切分不同，同一段推理被切成不同数量的 token。跨家族蒸馏时，student 要同时学「模仿思路」和「适应切分习惯」，前者的能力被后者稀释了。

4.3 成本对比

原文给了很有说服力的一组数字：

训练耗时内存
蒸馏（Ch8）约 3 小时约 15 GB
GRPO 几轮（Ch6）约 12 小时约 70 GB

而且 teacher 数据可以提前离线生成（12,000 题，API 成本约 50 美元），训练时直接加载。RL 则必须在线采样。

括号内是有 </think> 标签的结果。原文的观察：

Interestingly, the Qwen3 model has a lower validation loss when </think> tokens are omitted, but this doesn't translate into better modeling performance. The omission of </think> makes the results slightly worse in almost all cases.
又一次「损失 ≠ 效果」

去掉 think 标签，验证损失更低（0.3130 vs 0.4043），但准确率略差（44.8% vs 45.0%）。

为什么？标签是冗余的、易预测的结构（格式固定，模型学起来不费劲），会拉低平均损失；但它们是推理过程的显式边界标记，对模型组织推理有帮助。把易学的部分算进损失会稀释信号。

这是交叉熵作为指标的一个内在局限：它按 token 平均，而不同 token 的「学习价值」差别很大。

六、两章目标函数的统一视角

把 Ch6 和 Ch8 放在一起，能看到一个清晰的谱系：

SFT / 蒸馏GRPORLHF
损失形式\(-\frac{1}{T}\sum_t \log\pi(y_t)\)\(-\frac{1}{N}\sum_i A_i \sum_t \log\pi(y_t)\)PPO + 人类偏好奖励
权重来源全部 1\(A_i\)（组内相对）人类排序
监督信号teacher 的 tokenverifier 的 0/1人
能否自动验证不需要验证✅ 可验证❌ 需要人
最关键的一行

GRPO 就是 SFT 加了一个权重 \(A_i\)。

如果所有 \(A_i = 1\)（即「这个回答很好」），GRPO 就退化成对自己采样出来的输出做 SFT——这叫 RFT / rejection sampling fine-tuning，只需要 verifier 判对错，不需要 advantage 归一化。

而 GRPO 之所以要减去组内均值（6.7 节），是为了处理「全对或全错」的情况——那时 \(A \equiv 0\)，梯度为零，什么都不学，这是有意的设计。
